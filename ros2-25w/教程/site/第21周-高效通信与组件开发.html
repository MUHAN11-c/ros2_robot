第21章 生命周期/进程内通信/组件/插件

第21章 高效通信与组件开发

本章覆盖 ROS2 的四个进阶特性：生命周期节点、进程内通信、组件（component）、插件（pluginlib），以及参数事件监听与话题工具。

本章对应代码：code/ws04_advanced/src/lifecycle_cpp、lifecycle_py、intra_process_cpp、demo_component、demo_param_events(_py)、demo_topic_tools、plugin_base、plugin_impl、plugin_loader。

21.1 生命周期节点

21.1.1 案例以及案例分析

需求：编写受状态机管控的节点，通过外部命令在 unconfigured → inactive → active → finalized 之间流转，回调中打印各阶段日志。适用于「先配置再启动」的健壮系统（如导航栈）。

21.1.2 C++ 实现要点

class MyNode: public rclcpp_lifecycle::LifecycleNode{
public:
    MyNode():rclcpp_lifecycle::LifecycleNode("my_lifecycle_node_cpp"){}
    CallbackReturn on_configure(const rclcpp_lifecycle::State &){
        RCLCPP_INFO(this->get_logger(),"节点配置......");
        return CallbackReturn::SUCCESS;
    }
    CallbackReturn on_activate(const rclcpp_lifecycle::State &){
        RCLCPP_INFO(this->get_logger(),"节点激活------------");
        return CallbackReturn::SUCCESS;
    }
    // on_deactivate / on_cleanup / on_shutdown 同理
};

21.1.3 运行效果（实测）

ros2 run lifecycle_cpp demo_lifecycle
ros2 lifecycle set /my_lifecycle_node_cpp configure
ros2 lifecycle set /my_lifecycle_node_cpp activate
ros2 lifecycle set /my_lifecycle_node_cpp deactivate
ros2 lifecycle set /my_lifecycle_node_cpp cleanup

节点端日志：

[INFO] [...]: 生命周期节点创建!
[INFO] [...]: 节点配置......
[INFO] [...]: 节点激活------------
[INFO] [...]: 节点待激活+++++++++++++++++++++
[INFO] [...]: 节点清空配置+++++++++++++++++++++

ros2 lifecycle set 每步返回 Transitioning successful。Python 版（lifecycle_py，节点名 my_lifecycle_node_py）行为一致。

21.2 进程内通信

21.2.1 案例以及案例分析

需求：同一进程内的发布方与订阅方通信，消息不经过 DDS 序列化/网络栈，降低延迟与 CPU 占用。

21.2.2 实现

关键点是通过 NodeOptions 为两个节点开启进程内通信，并放入同一个执行器：

// 4-1.节点设置：开启进程内通信；
rclcpp::NodeOptions options;
options.use_intra_process_comms(true);
// 4-2.单线程执行器 + 两个节点；
rclcpp::executors::SingleThreadedExecutor executor;
executor.add_node(std::make_shared<MinimalPublisher>(options));
executor.add_node(std::make_shared<MinimalSubscriber>(options));
executor.spin();

兼容提示：老式写法 rclcpp::SubscriptionOptions.use_intra_process_comm = IntraProcessSetting::Enable 在 Jazzy 下会导致 订阅注册异常（节点不上线、回调不触发）；请使用 NodeOptions::use_intra_process_comms(true)（官方示例写法）。

21.2.3 运行效果（实测）

[INFO] [...]: [main]: 节点已加入执行器，开始 spin
[INFO] [...]: [intra_pub_node_cpp]: 发布:hello intra process!
[INFO] [...]: [intra_sub_node_cpp]: 订阅的消息：'hello intra process!'

发布与订阅严格成对、每秒一次。

21.3 组件（Component）

21.3.1 案例以及案例分析

需求：把发布/订阅节点编译成动态库，运行时按需加载进同一个 component_container——多个节点同进程、共享执行器，省去进程间通信开销（这是导航栈的标准架构）。

21.3.2 实现要点

add_library(talker_component SHARED src/talker_component.cpp)
ament_target_dependencies(talker_component rclcpp rclcpp_component std_msgs)
rclcpp_components_register_nodes(talker_component "TalkerComponent")

节点类用 rclcpp_components::RegisterNodeMacro 注册，package.xml 导出 rclcpp_components。

21.3.3 运行效果（实测）

ros2 run rclcpp_components component_container
ros2 component load /ComponentManager demo_component my_component::TalkerComponent
ros2 component load /ComponentManager demo_component my_component::ListenerComponent
ros2 component list

组件源码位于 namespace my_component 中，注册名与加载命令使用完整限定名（与课程一致）；容器日志给出加载细节：

[INFO] [...]: [ComponentManager]: Found class: rclcpp_components::NodeFactoryTemplate<my_component::TalkerComponent>
[INFO] [...]: [talker_component_node_cpp]: talker组件被创建了
Loaded component 1 into '/ComponentManager' container node as '/talker_component_node_cpp'
/ComponentManager
  1  /talker_component_node_cpp
  2  /listener_component_node_cpp
[INFO] [...]: [talker_component_node_cpp]: 发布:hello component!
[INFO] [...]: [listener_component_node_cpp]: 订阅的消息：'hello component!'

两个组件运行在同一容器进程中，容器内话题 /topic 的发布/订阅闭环实时可见。

21.4 插件（pluginlib）

21.4.1 案例以及案例分析

需求：定义「正多边形」基类接口，以插件形式实现三角形/正方形，主程序运行时动态加载插件并计算面积——不重新编译主程序即可扩展形状。

21.4.2 实现要点

  • 基类包 plugin_base：纯虚基类 + 导出头文件；
  • 插件包 plugin_impl：PLUGINLIB_EXPORT_CLASS(polygon_plugins::Triangle, polygon_base::RegularPolygon) + pluginlib_export_plugin_description_file(plugin_base plugin_impl.xml)；
  • 加载方 plugin_loader：pluginlib::ClassLoader<polygon_base::RegularPolygon> loader("plugin_base","polygon_base::RegularPolygon")。

注意：ClassLoader 第一个参数是基类所在包名（插件通过 ament 索引注册到该包名下），写成插件包名会报 "Declared types are (empty)"。

21.4.3 运行效果（实测）

ros2 run plugin_loader demo_plugin_loader

三角形面积: 43.30
正方形面积: 100.00

（边长 10：三角形 10×10×sin60°/2≈43.30，正方形 100。）

21.6 本章小结

特性 一句话价值
生命周期 系统化管控节点「配置→激活→关闭」，故障可恢复
进程内通信 同进程零拷贝，延迟/负载显著下降
组件 运行时动态装载节点，共享进程与执行器
pluginlib 运行时扩展算法实现，主程序零改动
