14.2 知识点梳理

14.2.1 第1课 ROS2 简介与优势特点

  • 核心概念：ROS2（Robot Operating System 2，机器人操作系统 2）不是传统意义的操作系统，而是构建在操作系统（Linux）之上的机器人软件开发框架（开源元操作系统）：提供进程间通信机制、常用算法库、开发调试工具与社区生态，核心解决机器人系统中节点间通信与工具链问题。
  • ROS 诞生背景：2007 年前后，斯坦福 AI 实验室与 Willow Garage 面对"每个实验室都在重复造机器人软件轮子"的问题，提出用统一的通信中间件把感知、决策、控制模块解耦复用，STAIR 项目是起点，2009 年 ROS 正式发布。核心诉求是代码复用与模块解耦。
  • ROS 概念与作用：ROS 的三大作用——(1) 提供进程间通信（话题/服务/参数），让算法模块可以独立开发、独立部署；(2) 提供工具生态（rviz、rqt、rosbag、tf）；(3) 提供社区生态（navigation、moveit、PCL 相关包等开源算法）。它把机器人软件从"一个大程序"变成"一群协作的小程序"。
  • ROS2 发展历程：ROS1 基于 TCP/UDP 自研协议，存在单点 Master、无实时性、无安全机制、强依赖 Ubuntu 等问题；2014 年起 OSRF 启动 ROS2 项目（代号 ROS-TNG），核心是用 DDS（数据分发服务）作为通信底层，2017 年发布 Ardent，之后按年发布发行版（Foxy → Galactic → Humble → Iron → Jazzy …），Humble（2022，LTS 到 2027）是目前教学与工业主流。
  • ROS2 组成体系（自底向上四层）：
    1. DDS/RMW 层：通信真正落地的地方，RMW（ROS Middleware Interface）抽象接口下可插拔 Fast DDS、Cyclone DDS、Connext 等实现；
    2. rcl 核心层：与语言无关的 C 实现（rcl + rcutils + rmw），负责节点、话题、服务等核心逻辑；
    3. 客户端库层：rclcpp（C++）、rclpy（Python）、rcljava、rclrs 等，把 rcl 包装成各语言 API；
    4. 工具与生态层：ros2 CLI、launch、rqt、rviz2、rosbag2、tf2、navigation2、MoveIt2 等。
  • ROS2 优势（横向比较）——与其他机器人中间件/自研方案对比：
对比维度 ROS2 ROS1 自研 TCP/共享内存
通信底层 DDS，去中心化 自研 TCPROS/UDPROS + Master 自行实现
实时性 支持实时调度与零拷贝 无保证 取决于实现
安全机制 DDS-Security 加密鉴权 无 自行实现
跨平台 Linux/Windows/macOS/RTOS 基本限 Ubuntu 自行实现
多语言 C++/Python/Rust/Java… C++/Python 自定
产品质量 面向产品部署 面向研究原型 需长期维护
  • ROS2 优势（纵向比较）——相对 ROS1 的关键改进：去掉 Master（无单点故障，支持多机与动态发现）、DDS 带来 QoS（服务质量）策略、支持实时性与嵌入式、内建安全、支持生命周期节点（Lifecycle Node）、支持动作（Action）与参数服务原生化、多语言与跨平台、linter 与测试工具链完善。
  • 小结：ROS2 = DDS 通信底座 + 分层客户端库 + 工具链 + 生态，目标从"科研原型"升级为"可落地产品"。
  • 版本选择：课程基于 Humble（Ubuntu 22.04）；本教程实测环境为 Jazzy（Ubuntu 24.04），两者 API 基本一致，差异处均以「兼容提示」标注。

兼容提示：本教程全部代码已在 Jazzy 上实际编译运行通过。Humble → Jazzy 的主要差异（如动作目标响应回调签名、rosbag2 读取 API 返回值等）会在对应章节标注。

14.2.2 第2课 ROS2 安装与快速体验

  • 安装流程（五步，Ubuntu 22.04 + ROS2 Humble）：
    1. 设置编码：sudo locale-gen en_US en_US.UTF-8 && sudo update-locale LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8（避免构建时编码报错）；
    2. 启用 universe 存储库：sudo add-apt-repository universe；
    3. 设置软件源：添加 ROS2 GPG 密钥与 apt 源（国内可换清华/中科大镜像），sudo apt update；
    4. 安装：sudo apt install ros-humble-desktop（桌面完整版，含 rviz2/turtlesim/examples）；
    5. 配置环境：把 source /opt/ros/humble/setup.bash 写入 ~/.bashrc，source ~/.bashrc 立即生效。
  • 安装后验证：终端执行 source /opt/ros/<发行版>/setup.bash 后运行 ros2 --help 能看到版本与命令帮助即为安装成功（本教程 Jazzy 对应 source /opt/ros/jazzy/setup.bash）。
  • 卸载方式：sudo apt purge ros-humble-* && sudo apt autoremove；若只想换发行版，先删掉旧的 setup.bash 行再装新的。
  • 测试 ROS2：ros2 run demo_nodes_cpp talker 与 ros2 run demo_nodes_py listener，两个终端互发消息即为成功；也可运行官方小海龟示例验证图形环境（见 14.5.1）；ros2 doctor 可做环境体检。
  • 安装 colcon 构建工具：sudo apt install python3-colcon-common-extensions。colcon 是 ROS2 的官方构建工具（区别于 ROS1 的 catkin），支持同时构建 C++/Python 包。
  • 快速体验——案例简介：目标是写一对最小节点：Talker 发布字符串话题，Listener 订阅打印。分别用 C++（ament_cmake）和 Python（ament_python）两种构建类型实现，体会两者差异。
  • HelloWorld(C++) 基本流程：ros2 pkg create --build-type ament_cmake helloworld_cpp --dependencies rclcpp 创建包 → 在 src/ 写节点源文件 → CMakeLists.txt 里 add_executable + ament_target_dependencies + install(TARGETS ...) → 回到工作空间根目录 colcon build → source install/setup.bash → ros2 run <包名> <可执行文件名>。
  • HelloWorld(C++) 源码要点：节点 = 继承 rclcpp::Node 的类（或裸用 rclcpp::Node::make_shared）；发布用 create_publisher<std_msgs::msg::String>("topic", 10)；定时器 create_wall_timer 周期发布；入口 rclcpp::init → spin → shutdown。
  • HelloWorld(Python) 基本流程：ros2 pkg create --build-type ament_python helloworld_py --dependencies rclpy → 在包目录写节点 .py → setup.py 的 entry_points 注册可执行文件 → colcon build → ros2 run <包名> <可执行文件名>。
  • HelloWorld(Python) 源码要点：继承 rclpy.node.Node，create_publisher / create_subscription / create_timer，入口 rclpy.init → node → spin → destroy_node + shutdown。
  • ROS2 运行优化：colcon build --symlink-install（Python 改码免重编）、--packages-select <pkg>（只编指定包）、source ~/.bashrc 自动加载、把常用命令写别名、--cmake-args -DCMAKE_BUILD_TYPE=Release。

14.2.3 第3课 ROS2 环境搭建与体系框架详解

  • 文件系统——概览：一个工作空间（workspace）下 src/ 放功能包源码；colcon build 后生成 build/（编译中间产物）、install/（安装产物，含各包的 setup.bash）、log/（构建日志）。功能包（package）是 ROS2 的最小组织单元，含 package.xml（元信息与依赖）+ 构建文件（CMakeLists.txt 或 setup.py）+ 源码 + launch/ urdf/ config/ 等资源目录。
  • 文件系统——编码风格说明：C++ 遵循 Google C++ Style（课程风格），Python 遵循 PEP8；节点逻辑建议封装成类；命名小写下划线（包名、话题名），类名大驼峰，常量全大写；一个可执行文件对应一个"主节点"，公共接口放 include/<pkg>/ 或包内模块。
  • 文件系统——编码之初始化与资源释放：C++ 中 rclcpp::init(argc, argv) 开头、rclcpp::shutdown() 结尾，保证回调结束、上下文（Context）释放；Python 中 rclpy.init() / rclpy.shutdown()，并在 finally 里 destroy_node()。资源释放不到位会导致进程无法优雅退出、rosbag 写入不完整、DDS 实体泄漏。
  • 文件系统——配置文件：package.xml 声明 <depend>（构建+运行）、<build_depend>、<exec_depend>，C++ 包还要有 <export><build_type>ament_cmake</build_type></export>；CMakeLists.txt 用 find_package + ament_target_dependencies + install(DIRECTORY launch urdf config ...) 安装资源；Python 包 setup.py 里 data_files 要把 package.xml、launch/、resource/ 装进去，entry_points 注册 console_scripts。
  • 文件系统——常用命令：colcon build、colcon list、ros2 pkg list/create/executables/prefix、ros2 run、ros2 node/topic/service/param/interface、ros2 doctor。记住规律：ros2 <名词> <动词>，如 ros2 topic list。
  • 核心模块——通信相关：话题（Topic）、服务（Service）、动作（Action）、参数（Parameter）四种通信模型 + 接口定义（rosidl：.msg/.srv/.act）+ RMW/DDS 底层。这一块是第 15、16 周的主角。
  • 核心模块——工具相关：ros2 CLI、launch 系统、rqt 工具箱、rviz2 可视化、rosbag2 数据录制回放、tf2 坐标变换、urdf/xacro 建模。这一块是第 17、18 周的主角。
  • ROS2 体系框架——技术支持：通信由 OMG 标准 DDS 支撑（可选实现 Fast DDS / Cyclone DDS / RTI Connext）；构建由 colcon + ament 支撑；接口由 rosidl 代码生成；社区由 ROS Discourse、GitHub ros2 组织、ROS Index（docs.ros.org）支撑。
  • ROS2 体系框架——应用方向：移动机器人（差速/全向底盘 + 导航）、机械臂（MoveIt2）、自动驾驶（Autoware）、无人机（PX4 + ROS2 桥）、复合机器人与教育科研。后续课程的智能车（Mycar）就是"差速底盘 + 传感器 + 导航"的缩影。
  • 本周小结：先懂"ROS2 是四层体系"，再懂"代码按工作空间/功能包组织"，最后把环境与常用命令变成肌肉记忆，本周就算达标。

14.3 重点与难点

  1. 工作空间与功能包的层级关系：工作空间是"仓库"，功能包是"项目"，节点是"进程"。colcon build 必须在工作空间根目录执行，source install/setup.bash 后 ros2 run 才能找到可执行文件——这是新手最常见的"找不到包"根因。
  2. ament_cmake 与 ament_python 的差异：C++ 包靠 CMakeLists.txt 编译出可执行文件并 install(TARGETS)；Python 包靠 setup.py 的 entry_points 注册脚本。两者 package.xml 的 <build_type> 不同，混用必报错。
  3. 环境变量的加载顺序：/opt/ros/<distro>/setup.bash 是系统层，工作空间/install/setup.bash 是覆盖层；多个工作空间叠加时后 source 的覆盖先 source 的（详见第 16 章"工作空间覆盖"）。
  4. 初始化与资源释放的配对：init/shutdown、spin 的退出条件、Python 的 destroy_node，决定节点能否被 Ctrl+C 干净结束。
  5. 配置文件的"安装"概念：源码里的 launch/ urdf/ 不 install 就不会出现在 install/ 里，ros2 launch 就找不到——这是 launch 阶段高频 BUG。

实战 1：创建工作空间与功能包（场景：本章两个 Hello World 包；--dependencies 会同步写入 package.xml）

实战 2：Hello World（C++）——源文件与 CMakeLists.txt（文件 cpp00_hello_world/src/demo01_hello_world.cpp）

/*
    需求：ROS2 快速体验 —— HelloWorld(C++)。
    流程：
        1.包含头文件；
        2.初始化 ROS2 客户端；
        3.自定义节点类；
        4.调用spin函数，并传入节点对象指针；
        5.释放资源。
*/
// 1.包含头文件；
#include "rclcpp/rclcpp.hpp"

// 3.自定义节点类；
class HelloWorld: public rclcpp::Node{
public:
    HelloWorld():Node("hello_world_node_cpp"){
        RCLCPP_INFO(this->get_logger(),"Hello World!(C++)");
    }
};

int main(int argc, char ** argv)
{
    // 2.初始化 ROS2 客户端；
    rclcpp::init(argc,argv);
    // 4.调用spin函数，并传入节点对象指针；
    rclcpp::spin(std::make_shared<HelloWorld>());
    // 5.释放资源；
    rclcpp::shutdown();
    return 0;
}

CMakeLists.txt 关键内容（其余为 ament_cmake 模板默认内容）：

find_package(rclcpp REQUIRED)
add_executable(demo01_hello_world src/demo01_hello_world.cpp)
ament_target_dependencies(demo01_hello_world rclcpp)
install(TARGETS demo01_hello_world DESTINATION lib/${PROJECT_NAME})  # 装到 lib/<包名> 才能 ros2 run

实战 3：Hello World（Python）——源文件与 setup.py（文件 py00_hello_world/demo01_hello_world_py.py）

# -*- coding: utf-8 -*-
"""
    需求：ROS2 快速体验 —— HelloWorld(Python)。
"""
import rclpy
from rclpy.node import Node


class HelloWorld(Node):

    def __init__(self):
        super().__init__("hello_world_node_py")
        self.get_logger().info("Hello World!(python)")


def main():
    rclpy.init()
    rclpy.spin(HelloWorld())
    rclpy.shutdown()


if __name__ == '__main__':
    main()

setup.py 中注册入口（可执行文件名 = ros2 run 的第二个参数）：

entry_points={
    'console_scripts': [
        'demo01_hello_world_py = py00_hello_world.demo01_hello_world_py:main',
    ],
},

注意：ament_python 包需要 setup.cfg 指定脚本安装目录，否则 ros2 run 找不到可执行文件：

[develop]
script_dir=$base/lib/py00_hello_world
[install]
install_scripts=$base/lib/py00_hello_world

实战 4：编译、运行与优化（场景：日常开发循环）

cd ws01_plumbing
colcon build                                                # 编译全部功能包
colcon build --packages-select cpp00_hello_world            # 只编指定包
source install/setup.bash                                   # 每个新终端都要 source
ros2 run cpp00_hello_world demo01_hello_world               # 运行 C++ 版

常用构建选项：--symlink-install（Python 改码免重编）、--cmake-args -DCMAKE_BUILD_TYPE=Release（C++ 优化构建）。

实战 5：package.xml 依赖声明要点（场景：编译报"找不到 rclcpp"或运行报缺包）

<!-- package.xml 节选：依赖分构建期与运行期，写全才能被 colcon 排序构建 -->
<depend>rclcpp</depend>          <!-- 构建 + 运行都需要 -->
<exec_depend>ros2launch</exec_depend>   <!-- 仅运行期需要，如 launch -->
<export><build_type>ament_cmake</build_type></export>   <!-- Python 包写 ament_python -->

14.6 与 ROS2 / 机器人开发的关联

  1. 一切开发从建包开始：第 15 章开始的每个通信案例、第 18 章的 URDF 描述包、第 19 章起的 Mycar 全部遵循本章的包结构与构建流程，本章的"建包模板"可以直接复制使用。
  2. 文件系统规范决定可维护性：真实机器人项目往往是几十个包、上百个节点，launch/、config/、urdf/ 的规范放置让团队协作与 CI 构建成为可能。
  3. 环境变量与多工作空间：真机部署时机器人端与 PC 端常有不同工作空间叠加，理解 setup.bash 覆盖顺序能避免"改了代码不生效"的经典问题。
  4. C++/Python 双语言能力：工业界常用 C++ 写控制/驱动等性能敏感节点，用 Python 写上层调度与算法原型，本章 Hello World 就是两种模板的种子代码。

14.8 常见问题（FAQ）

  • Q：ros2 run 提示 "No executable found"？ A：九成是三件事之一——没 source install/setup.bash、可执行文件没 install 到 lib/<包名>（C++）或 entry_points 没注册（Python）、包名/可执行名拼写错误。依次用 ros2 pkg list、ros2 pkg executables <pkg> 验证。
  • Q：colcon build 报 Package 'xxx' not found in root 或依赖找不到？ A：确认在工作空间根目录执行、包目录在 src/ 下、package.xml 的 <depend> 写全；C++ 包还要在 CMakeLists.txt 里 find_package。
  • Q：装了多个 ROS2 发行版会冲突吗？ A：会。同一终端只应 source 一个发行版；echo $ROS_DISTRO 检查当前生效版本，~/.bashrc 中保留一行 source /opt/ros/<distro>/setup.bash。
  • Q：C++ 包改了源码为什么 ros2 run 还是旧行为？ A：C++ 需要重新 colcon build；Python 包若用了 --symlink-install，改完源码直接重启节点即可。另外确认运行的终端 source 的是同一个工作空间。

14.9 本章小结

  • ROS2 是构建在 DDS 之上的机器人软件框架，节点是基本执行单元；
  • 工作空间 = src + build + install + log，source install/setup.bash 后才能使用；
  • C++ 包（ament_cmake）与 Python 包（ament_python）的开发流程同为「创建功能包 → 编码 → 配置 → colcon build → ros2 run」；
  • Python 包不要遗漏 setup.cfg 的脚本安装目录配置。
