17.2 知识点梳理

17.2.1 第1课 launch 文件方式实现与 ROSbag2

A. launch 实现流程与 Python 实现

  • 应用场景、概念、作用与准备工作：launch（启动文件）用一个文件描述"启动哪些节点、怎么传参、以什么顺序/条件启动"，作用是一键复现系统、参数集中管理、支持条件与组合。准备：功能包里建 launch/ 目录，CMakeLists.txt 用 install(DIRECTORY launch DESTINATION share/${PROJECT_NAME})（Python 包在 setup.py 的 data_files 装入），再 ros2 launch <pkg> <文件> 运行。
  • launch 基本使用流程（C++ 实现）：ament_cmake 包加 launch 文件 → install → ros2 launch；若需要给 C++ 节点传参，在 launch 的 parameters 里写字典或 YAML 文件，节点 declare_parameter 接收。
  • launch 基本使用流程（Python 实现）：ament_python 包的 setup.py data_files 增加 ('share/' + package_name + ['launch/xxx.launch.py'])，否则 ros2 launch 找不到文件。
  • Python launch 简介：.launch.py 文件本质是 Python 模块，必须实现 generate_launch_description() -> LaunchDescription；核心实体——Node（节点）、ExecuteProcess（执行指令）、DeclareLaunchArgument + LaunchConfiguration（参数）、IncludeLaunchDescription（文件包含）、GroupAction + PushRosNamespace（分组）、RegisterEventHandler + OnProcessStart/OnProcessExit/OnStateChange（事件）。
  • Python launch——node（上下）：Node(package='pkg', executable='exe', name='节点名', namespace='ns', output='screen', emulate_tty=True, parameters=[...], remappings=[...], arguments=[...])。要点：package 是功能包名、executable 是可执行名（entry_points 名）、output='screen' 让日志进终端、emulate_tty 让日志带颜色、respawn=True 可崩溃重启。
  • Python launch——执行指令：ExecuteProcess(cmd=['ros2', 'run', 'turtlesim', 'turtlesim_node'], output='screen') 或 ExecuteProcess(cmd=['python3', 'script.py'])，用于启动非 ROS 程序、脚本、ros2 bag record 等任意 shell 命令。
  • Python launch——参数设置：三种来源——内联字典 parameters=[{'rate': 2.0}]、YAML 文件 parameters=[os.path.join(pkg_share, 'config', 'x.yaml')]、launch 参数 parameters=[{'name': LaunchConfiguration('name')}]（配合 DeclareLaunchArgument('name', default_value='x') 与命令行 ros2 launch pkg x.launch.py name:=y 覆盖）。
  • Python launch——文件包含：IncludeLaunchDescription(PythonLaunchDescriptionSource(path), launch_arguments={'arg': 'val'}.items())，可把子系统 launch 组合成大系统；路径用 get_package_share_directory('pkg') 获取。
  • Python launch——分组设置：GroupAction([PushRosNamespace('robot1'), DeclareLaunchArgument(...), Node(...)], condition=IfCondition(LaunchConfiguration('use_robot1')))，作用：批量加命名空间、批量生效参数、按条件整组启停。
  • Python launch——事件设置：RegisterEventHandler(OnProcessExit(target_action=node_a, on_exit=[LaunchDescription([...])]))——A 退出后启动 B（如"乌龟生成完再启动控制节点"）；OnProcessStart 启动时触发；OnStateChange 监听生命周期状态。补充：还可用 TimerAction(period=3.0, actions=[...]) 延时启动、EmitEvent(Shutdown()) 主动收尾。

B. launch 文件之 xml、yaml 实现

  • xml——node（上下）：<launch><node pkg="pkg" exec="exe" name="n" namespace="ns" output="screen"><param name="rate" value="2.0"/><remap from="/a" to="/b"/></node></launch>；<param from="config/x.yaml"/> 导入参数文件；<arg name="x" default="1"/> + $(var x) 引用。
  • xml——执行指令：<executable cmd="python3 script.py"/>；xml——参数设置：<param>/<param from>/<rosparam command="load">（视版本）；xml——分组设置：<group><push-namespace ns="robot1"/>...</group>（或 ns 属性）；xml——文件包含：<include file="$(find-pkg-share pkg)/launch/sub.launch.py"><arg name="a" value="1"/></include>。
  • yaml 写法：YAML launch 用声明式结构 launch: 下 node: {pkg, exec, name, param, remap}、include:、arg: 等，适合纯配置场景（不写逻辑）；三种格式能力等价，Python 表达力最强（可写循环/条件/计算），XML/YAML 更简洁。
  • launch 小结：选型建议——有逻辑（条件、循环、组合）用 Python；纯节点编排用 XML/YAML；参数一律外置到 config/*.yaml。

C. rosbag2 案例实现

  • rosbag2 场景、概念与作用：rosbag2 是 ROS2 的数据录制/回放工具，把话题消息按时间戳存进 SQLite3（默认）或 MCAP 文件。作用：离线复现 BUG、算法回归测试、训练数据采集、无机器人开发。与 ROS1 rosbag 的差异：存储插件化（sqlite3/mcap）、按 topic 可选存储插件与序列化格式。
  • rosbag2 命令工具 ros2bag：ros2 bag record -a（录全部）、ros2 bag record /topic1 /topic2 -o my_bag（指定话题，-o 指定目录）、ros2 bag info my_bag（看时长/消息数/类型）、ros2 bag play my_bag（回放，--loop 循环、-r 2.0 倍速、--topics 选择、--clock 发布仿真时间、-s 10 跳过前 10 秒）。
  • rosbag2 编码实现（C++）——案例源码分析：场景"程序内写 bag"（如记录控制器内部状态）。API 在 rosbag2_cpp（写：rosbag2_cpp::Writer；读：rosbag2_cpp::Reader）+ rosbag2_storage。
  • rosbag2 编码实现（C++）——框架搭建：CMakeLists.txt 依赖 rosbag2_cpp 与消息包；Writer 打开 rosbag2_storage::StorageOptions（uri + id）与 ConverterOptions（序列化格式 cdr）。
  • rosbag2 编码实现（C++）——录制数据：writer->create_topic(topic_metadata) 后循环 writer->write(message, topic_name, time)；时间戳用 node->now().nanoseconds()；注意所有消息走统一序列化（rclcpp 序列化器 rclcpp::Serialization<T>）。
  • rosbag2 编码实现（C++）——读取数据：reader->open(storage_options) → while (reader->has_next()) { auto [topic, data, t] = reader->read_next(); ... }，反序列化后还原消息；可用于离线批处理。
  • rosbag2 Python 实现说明：Humble 起提供 rosbag2_py（SequentialWriter/SequentialReader），API 与 C++ 对应；课程以 C++ 为主，Python 可照 rosbag2_py 示例改写。
  • launch 与 rosbag2 总结：常见组合——launch 里 ExecuteProcess(cmd=['ros2', 'bag', 'record', '-a']) 实现"启动即录制"；回放 bag + --clock + use_sim_time 实现时间对齐的离线调试。

17.2.2 第2课 C++、Python 实现坐标变换广播

A. 坐标变换基础

  • 场景：机器人上"雷达看到的障碍物"要转到"底盘坐标系"再转到"地图坐标系"才能用于导航；相机看到的目标要转到机械臂基座才能抓取。坐标变换（TF, Transform）就是维护这条坐标系树并随时查询。
  • 概念与作用：TF2 用树状坐标系结构（一棵树、无环）管理 frame 之间的平移+旋转（6 自由度），随时间变化的叫动态变换（如轮子转动），不变的叫静态变换（如雷达装在底盘上的位置）。作用：统一多传感器数据、支持任意两坐标系互查（lookupTransform）、配合 rviz2 显示。
  • 案例安装与运行：安装 ros-humble-tf2-tools、ros-humble-tf-transformations（或 tf_transformations）；ros2 run tf2_ros static_transform_publisher ... + ros2 run tf2_tools view_frames 生成坐标系树 PDF。
  • 相关消息：geometry_msgs/TransformStamped（带 header 的变换：header.frame_id 父系、child_frame_id 子系、transform.translation/rotation，四元数表示旋转）与 geometry_msgs/PointStamped（带时间戳的坐标点）。广播/监听通过 /tf_static（静态，latched）与 /tf（动态）话题传输 tf2_msgs/TFMessage。
  • 广播——引言与案例分析：广播（Broadcast）= 把"父系→子系"的变换发出去；监听（Lookup）= 查询任意两系间的变换。案例"雷达→底盘静态变换"：固定平移 (0.2, 0, 0.3)，广播一次即可。

B. 静态广播器

  • 命令实现（上下）：ros2 run tf2_ros static_transform_publisher --x 0.2 --y 0 --z 0.3 --roll 0 --pitch 0 --yaw 0 --frame-id base_link --child-frame-id laser；也可用 --x ... --q 传四元数；老式位置参数写法（x y z yaw pitch roll frame child）仍可用。静态变换发布到 /tf_static，QoS 为 transient_local（可靠 + 持久），后启动的监听也能收到。
  • C++ 实现：rclcpp::Node 内创建 std::make_shared<tf2_ros::StaticTransformBroadcaster>(node)，填 geometry_msgs::msg::TransformStamped（四元数用 tf2::Quaternion 填 roll/pitch/yaw 或 setRPY），sendTransform(ts) 发送一次。
  • C++ 补充：四元数不能直接赋 roll/pitch/yaw 字段，必须经 tf2::Quaternion q; q.setRPY(...); tf2::toMsg(q, ts.transform.rotation)；父子 frame 名不要带 / 开头（tf2 约定）。
  • Python 实现：from tf2_ros import StaticTransformBroadcaster；self.tf_broadcaster.sendTransform(t)；四元数用 tf_transformations.quaternion_from_euler(roll, pitch, yaw) 填 rotation.x/y/z/w。

C. 动态广播器

  • C++ 实现：tf2_ros::TransformBroadcaster（非 static），在定时器里随时间更新变换（如轮子角度、机器人位姿）并 sendTransform；必须持续发布（一般 10~100 Hz），监听端才能查到任意时刻的变换（tf2 内部有缓存，默认 10 秒）。
  • Python 实现：from tf2_ros import TransformBroadcaster，定时器回调里更新 TransformStamped 的时间戳（self.get_clock().now().to_msg()）后发送。要点：header.stamp 用当前时刻，写 0 或过期时间会导致监听端外推失败。

17.2.3 第3课 C++、Python 实现坐标变换监听

A. 坐标点发布

  • 案例以及分析：案例"雷达点坐标转到底盘"——发布 geometry_msgs/PointStamped（frame_id = laser），监听端把它转到 base_link 输出。先写点发布方作为数据源。
  • C++/Python 实现：定时器里 point.header.frame_id = "laser"; point.header.stamp = node->now(); 发布到 /point 话题；注意 stamp 与 TF 时间要对得上。
  • 坐标变换广播——小结：静态广播一次（/tf_static，transient_local），动态持续广播（/tf）；旋转用四元数；frame 命名全小写、无 /。

B. 坐标变换监听

  • 案例与案例分析：查询 base_link ← laser 的变换，把点/向量转过去。核心 API：tf2_ros::Buffer（变换缓存）+ tf2_ros::TransformListener（订阅 /tf、/tf_static 填充 Buffer）。
  • C++ 实现（上下）：auto buffer = std::make_shared<tf2_ros::Buffer>(node->get_clock()); auto listener = std::make_shared<tf2_ros::TransformListener>(*buffer); 然后 buffer->lookupTransform("base_link", "laser", tf2::TimePointZero)（取最新）或 lookupTransform(target, source, rclcpp::Time)（取指定时刻）；异常处理 tf2::TransformException（查不到时抛 ExtrapolationException/LookupException）。
  • Python 实现：self.tf_buffer = Buffer(); self.tf_listener = TransformListener(self.tf_buffer, self)；self.tf_buffer.lookup_transform('base_link', 'laser', Time())；do_transform_point(point, transform) 完成点变换。

C. 坐标点变换监听

  • 实现框架/框架搭建：把"订阅点话题 → 等对应 TF → 变换 → 发布"串起来；时间戳匹配是关键：点的 stamp 与 TF 缓存时间不对齐会抛外推异常。
  • 监听器创建：TransformListener 需与 Buffer 同生命周期；多线程下用 tf2_ros::CreateTimerROS 或专用回调组，避免查 TF 阻塞执行器。
  • 订阅坐标点：订阅 /point（PointStamped），回调中取 msg->header 的 frame 与 stamp 作为查询时刻。
  • 过滤器创建：用 tf2_ros::MessageFilter（消息过滤器）让"TF 没到齐的消息先排队，TF 到齐再回调"——绑定目标 frame；避免手动 sleep 等 TF。
  • 变换实现以及小结：tf2::doTransform(point_in, point_out, transform) 输出变换后坐标；小结：监听三件套 Buffer + Listener +（可选）MessageFilter；查询用 canTransform 先探再查更稳。
  • Python 实现：tf2_geometry_msgs.do_transform_point(point, transform)（Humble 中从 tf2_geometry_msgs 导入），或用 tf2_ros.MessageFilter 等价实现。

D. 坐标变换工具

  • ros2 run tf2_ros tf2_echo base_link laser（打印实时变换）、ros2 run tf2_tools view_frames（生成 frames.pdf 坐标树）、ros2 run tf2_ros static_transform_publisher --help；rviz2 的 TF 插件可图形化查看坐标系与随时间回放。

17.3 重点与难点

  1. launch 资源必须 install：launch/config/urdf 目录不写进 install(DIRECTORY ...) 或 setup.py 的 data_files，ros2 launch 就报"文件不存在"——本周第一大坑。
  2. launch 参数的三种来源与覆盖顺序：内联 < YAML 文件 < launch 参数（命令行 arg:=val）；LaunchConfiguration 只在 generate_launch_description 里解析，别在定义前引用。
  3. TF 的时间语义：动态变换必须持续广播且 header.stamp 为当前时间；查询指定时刻要保证 tf2 缓存覆盖该时刻（默认缓存 10 秒），否则 ExtrapolationException。
  4. 四元数 vs 欧拉角：TF 内部一律四元数；欧拉角只在人机接口出现。手写 rotation.x/y/z/w 必须归一化，setRPY/quaternion_from_euler 才安全。
  5. 消息过滤器解决"TF 还没到"：点的 stamp 比 TF 新时 lookupTransform 必失败；MessageFilter 把消息暂存到 TF 就绪再回调，是传感器融合的标配。

17.4.2 实战 2：Python launch 全要素（一键启动小乌龟系统 + 参数 + 事件）

# my_pkg/launch/turtle_system.launch.py
import os
from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch.actions import (DeclareLaunchArgument, ExecuteProcess,
                            GroupAction, IncludeLaunchDescription, RegisterEventHandler)
from launch.event_handlers import OnProcessExit
from launch.launch_description_sources import PythonLaunchDescriptionSource
from launch.conditions import IfCondition
from launch.substitutions import LaunchConfiguration
from launch_ros.actions import Node, PushRosNamespace


def generate_launch_description():
    pkg_share = get_package_share_directory('my_pkg')
    use_sim = LaunchConfiguration('use_sim')
    return LaunchDescription([
        DeclareLaunchArgument('use_sim', default_value='true'),
        Node(package='turtlesim', executable='turtlesim_node', name='sim',
             parameters=[os.path.join(pkg_share, 'config', 'sim.yaml'),
                         {'use_sim_time': use_sim}],   # YAML + 内联参数混用
             output='screen', emulate_tty=True),
        ExecuteProcess(cmd=['ros2', 'bag', 'record', '-a', '-o', 'run_bag'],
                       output='screen'),               # 启动即录 bag
        GroupAction([PushRosNamespace('robot1'),        # 分组 + 命名空间
                     Node(package='my_pkg', executable='follower', name='follower')],
                    condition=IfCondition(use_sim)),    # 条件整组启停
        RegisterEventHandler(OnProcessExit(             # 事件：sim 退出后回放 bag
            target_action=None, on_exit=[ExecuteProcess(cmd=['echo', 'sim exit'])])),
        IncludeLaunchDescription(                       # 文件包含：组合子系统
            PythonLaunchDescriptionSource(
                os.path.join(pkg_share, 'launch', 'sub.launch.py')),
            launch_arguments={'use_sim': use_sim}.items()),
    ])

C++ 编程实现（cpp02_rosbag2）。录制（src/demo01_writer.cpp）：

// 3-1.创建一个录制对象；
writer_ = std::make_unique<rosbag2_cpp::Writer>();
// 3-2.设置被录制的文件；
writer_->open("ros2bag/demo01_bag");
// 3-3.订阅话题并在回调中写入；
sub_ = this->create_subscription<geometry_msgs::msg::Twist>("/turtle1/cmd_vel",10,
    std::bind(&SimpleBagRecorder::sub_callback,this,_1));
// 3-4.写入文件(注意传入消息本体而非智能指针)；
writer_->write(*msg,"/turtle1/cmd_vel",this->now());

回放（demo02_reader.cpp）：

reader_ = std::make_unique<rosbag2_cpp::Reader>();
reader_->open("ros2bag/demo01_bag");
while (rclcpp::ok() && reader_->has_next()) {
    auto msg = reader_->read_next<geometry_msgs::msg::Twist>();
    RCLCPP_INFO(this->get_logger(),"读取消息:(%.2f,%.2f)",msg.linear.x,msg.angular.z);
    rclcpp::sleep_for(std::chrono::milliseconds(200));
}
reader_->close();

兼容提示：

  • Writer::write() 需传入消息本体（*msg）；传智能指针会因模板推导出 shared_ptr<Twist> 而链接失败。
  • Jazzy 中 Reader::read_next<T>() 按值返回消息（msg.linear.x）；Humble 返回 shared_ptr（msg->linear.x）。
  • 同名 bag 目录已存在时 open() 会抛异常，重跑前先删除 ros2bag/demo01_bag。

17.4.5 实战 5：静态变换广播（C++ 主力 + Python 对照）

// static_tf/src/static_broadcaster.cpp
#include "geometry_msgs/msg/transform_stamped.hpp"
#include "rclcpp/rclcpp.hpp"
#include "tf2/LinearMath/Quaternion.h"
#include "tf2_ros/static_transform_broadcaster.h"

class StaticTF : public rclcpp::Node {
public:
  StaticTF() : Node("static_tf") {
    tf_broadcaster_ = std::make_shared<tf2_ros::StaticTransformBroadcaster>(this);
    geometry_msgs::msg::TransformStamped t;
    t.header.stamp = now();                    // 静态变换用当前时刻即可
    t.header.frame_id = "base_link";           // 父系
    t.child_frame_id = "laser";                // 子系
    t.transform.translation.x = 0.2;           // 雷达在底盘前 0.2m、高 0.3m
    t.transform.translation.z = 0.3;
    tf2::Quaternion q; q.setRPY(0, 0, 0);      // 欧拉角转四元数（勿手写 x/y/z/w）
    t.transform.rotation = tf2::toMsg(q);
    tf_broadcaster_->sendTransform(t);         // 只发一次：/tf_static (transient_local)
  }
private:
  std::shared_ptr<tf2_ros::StaticTransformBroadcaster> tf_broadcaster_;
};

# Python 对照（动态广播版：定时器里持续发布）
from geometry_msgs.msg import TransformStamped
from tf2_ros import TransformBroadcaster
from tf_transformations import quaternion_from_euler

class DynamicTF(Node):
    def __init__(self):
        super().__init__('dynamic_tf')
        self.br = TransformBroadcaster(self)
        self.timer = self.create_timer(0.1, self.on_timer)   # 10 Hz

    def on_timer(self):
        t = TransformStamped()
        t.header.stamp = self.get_clock().now().to_msg()     # 必须是当前时刻
        t.header.frame_id = 'odom'
        t.child_frame_id = 'base_link'
        q = quaternion_from_euler(0, 0, self.theta)          # yaw
        t.transform.rotation.x, t.transform.rotation.y = q[0], q[1]
        t.transform.rotation.z, t.transform.rotation.w = q[2], q[3]
        self.br.sendTransform(t)

17.4.6 实战 6：变换监听 + 消息过滤器（Python）

# tf_listener/tf_listener/point_tf.py
from geometry_msgs.msg import PointStamped
from rclpy.node import Node
from tf2_ros import Buffer, TransformListener, MessageFilter
from tf2_geometry_msgs import do_transform_point

class PointTF(Node):
    def __init__(self):
        super().__init__('point_tf')
        self.buf = Buffer()
        self.listener = TransformListener(self.buf, self)
        self.pub = self.create_publisher(PointStamped, 'point_in_base', 10)
        self.sub = self.create_subscription(PointStamped, 'point', self.raw_cb, 10)
        # 消息过滤器：目标 frame 的 TF 就绪后才回调 on_point
        self.filter = MessageFilter(self.sub, self.buf, 'base_link', 10, self)
        self.filter.register_callback(self.on_point)

    def on_point(self, msg: PointStamped):
        tf = self.buf.lookup_transform('base_link', msg.header.frame_id, msg.header.stamp)
        self.pub.publish(do_transform_point(msg, tf))

17.6 与 ROS2 / 机器人开发的关联

  1. launch 是多节点系统唯一入口：导航（Nav2）、建图（slam_toolbox）、MoveIt2 全靠 launch 组合；掌握 Python launch 的条件/分组/事件才能做复杂系统编排。
  2. rosbag2 是算法开发的"数据资产"：视觉/激光算法离线迭代全靠录制数据；--clock + use_sim_time 让回放与在线行为一致；MCAP 格式正成为行业数据标准（本章实测 bag 即 mcap 存储）。
  3. TF2 是机器人学的通用语言：雷达/相机/IMU/机械臂各 link 的空间关系都在 TF 树上；导航定位（map→odom→base_link）是 TF 树的直接应用。
  4. 为第19-20章 Mycar 做准备：智能车的 bringup、传感器 TF、数据录制都直取本周内容；本阶段打好基础，实战周只需关注业务逻辑。

17.7 自测与练习

  1. 概念题：静态变换与动态变换的区别（话题、QoS、发布频率、时间语义）各是什么？为什么静态变换用 /tf_static + transient_local？
  2. 动手任务：写一个 Python launch，同时启动 turtlesim_node 与两个自定义节点（一个发布 /cmd_vel、一个打印位姿），并用 ros2 bag record /turtle1/cmd_vel 录制。验收标准：一条 ros2 launch 命令全部起来；ros2 bag info 能看到录制的话题。
  3. 动手任务：静态广播 odom -> base_link（yaw=0）与 base_link -> laser（x=0.2, z=0.3），再用监听节点把 laser 系下的点 (1, 0, 0) 转到 odom 系打印。验收标准：结果约为 (1.2, 0, 0.3)；tf2_echo 与 view_frames 验证树结构。

参考答案要点：1) 静态：/tf_static、transient_local（后订阅者也能收到）、发布一次、无时间外推问题；动态：/tf、持续发布（10~100 Hz）、header.stamp 必须当前、查询指定时刻受 10s 缓存限制。2) launch 中 Node(package='turtlesim', executable='turtlesim_node') + 两个自定义 Node + ExecuteProcess(cmd=['ros2','bag','record',...])；记得 install launch 目录。3) 变换合成：laser→base 平移 (0.2,0,0.3)，base→odom 无旋转，故点 (1,0,0) → (1.2,0,0.3)；用 lookup_transform('odom','laser', Time()) 直接查两级合成。

17.8 常见问题（FAQ）

  • Q：ros2 launch 报找不到 launch 文件？ A：launch 目录没 install：C++ 包加 install(DIRECTORY launch DESTINATION share/${PROJECT_NAME})；Python 包在 setup.py 的 data_files 加 ('share/' + package_name, ['launch/xxx.launch.py'])，然后重新 colcon build 并 source。
  • Q：lookupTransform 抛 ExtrapolationException？ A：查询时刻超出 tf2 缓存（默认 10s）或动态变换断流；确认广播端持续发布且 header.stamp 正确；查"最新变换"用 TimePointZero/Time() 而不是 now()。
  • Q：ros2 bag play 后订阅端没数据？ A：默认按录制时间戳发布，订阅端若 use_sim_time 没开、或 QoS 不匹配（bag 默认 reliable，订阅 best_effort 也可能不兼容）；用 ros2 topic echo 与 ros2 bag info 对照话题名与类型。
  • Q：TF 树连不上（view_frames 断成几棵）？ A：父子 frame 名拼写/前缀不一致（robot1/base_link 与 base_link 是不同 frame）；检查是否有环、是否有节点同时广播同一 child；rviz2 的 TF 插件可逐帧定位。
  • Q：launch 里参数传了但节点没收到？ A：节点必须 declare_parameter；YAML 的顶层 key 要与节点名/命名空间匹配（/**: 或 节点名:）；LaunchConfiguration 的值是字符串，数值参数建议在节点侧转换或用 ParameterValue(..., value_type=float)。

17.9 本章小结

  • launch 三种格式（Python/XML/YAML）能力等价，推荐 Python（可编程、可传参），参数/包含/分组/事件是四大核心要素，launch 目录必须 install；
  • rosbag2 底层存储为 mcap（实测 demo01_bag_0.mcap），命令行 ros2 bag record/play/info 覆盖大多数场景，--clock 配合 use_sim_time 实现时间对齐的离线调试；
  • 编程接口 rosbag2_cpp::Writer/Reader 与命令行行为一致，注意 write(*msg) 解引用与不同发行版 read_next 返回值差异；
  • TF2 广播分静态（StaticTransformBroadcaster，一次发送）与动态（TransformBroadcaster，持续发送），监听用 Buffer + Listener + lookupTransform，"TF 未到齐"用 MessageFilter 排队；
  • 乌龟跟随/护航（第18章）与 URDF/rviz2（第18章）是本章工具的综合应用与验收。
