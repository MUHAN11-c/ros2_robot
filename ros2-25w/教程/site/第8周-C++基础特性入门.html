第8章 C++ 基础特性入门（命名空间/引用/封装）

8.2 知识点梳理

8.2.1 第1课：C++ 语言概述与基础概念

  • 核心概念：C++ 是在 C 基础上面向对象（OOP）扩展而来的静态类型编译型语言，兼容 C 的同时增加了类、模板、异常、命名空间、STL 等设施。编译模型仍是「预处理 → 编译 → 链接」。
  • C++ 概述与第一个程序：最小可运行程序由头文件、main 函数和输出流组成。C++ 用 <iostream> 的 std::cout 取代 printf，用 std::cin 取代 scanf，类型安全（不会出现 printf("%d", x) 格式串写错的隐患）。
// hello.cpp —— C++17 第一个程序
#include <iostream>

int main() {
    std::cout << "Hello, ROS2 C++!" << std::endl;
    return 0;
}

g++ -std=c++17 -Wall -o hello hello.cpp && ./hello
# -std=c++17 指定语言标准；-Wall 打开常用警告
  • 快捷生成 main 函数：IDE/编辑器中可用代码片段一键生成主函数（VS Code 输入 main + Tab；Vim + snippets 插件同理）。重点不是快捷键本身，而是统一工程模板：固定包含顺序、固定 int main(int argc, char** argv) 签名——后面写 ROS2 节点时 main 必须带命令行参数。
  • 双冒号全局作用域（::）：:: 是作用域解析运算符（scope resolution）。前面什么都不写表示全局作用域，用于当局部变量/成员与全局名字冲突时强制取全局版本。
#include <iostream>
int value = 42;              // 全局变量

int main() {
    int value = 7;           // 局部变量遮蔽（shadow）全局变量
    std::cout << "local  = " << value << "\n";      // 7
    std::cout << "global = " << ::value << "\n";    // 42，:: 强制走全局
}
  • 命名空间解决命名冲突（namespace）：大型工程中不同库可能都有 init()、Timer，命名空间把名字划入独立作用域，从根上消除冲突。访问方式：空间名::成员。
namespace lidar { void init() { /* ... */ } }
namespace camera { void init() { /* ... */ } }

int main() {
    lidar::init();
    camera::init();
}
  • 命名空间的特性：
    • 命名空间只能写在全局作用域，内部还可以嵌套命名空间（C++17 可写 namespace a::b { }）。
    • 同名命名空间可以分散在多个文件/多次声明，编译器会把它们合并（这正是 ROS2 头文件的组织方式：rclcpp 命名空间散布在成百上千个头文件里）。
    • 支持匿名命名空间（namespace { ... }），其中的名字仅本翻译单元可见，等价于 static，用于隐藏实现细节。
    • 支持别名：namespace rt = robot_tools::sensors::detail;。
  • using 声明与编译指令：using 名字; 是「把一个名字引入当前作用域」（粒度细、可控）；using namespace 空间名; 是「把整个空间的名字全部倒进来」（方便但易冲突）。头文件中绝对不要写 using namespace，否则会污染所有包含该头文件的翻译单元。
namespace robot { constexpr double PI = 3.1415926; int id = 1; }

using robot::PI;          // using 声明：只引入 PI
// using namespace robot; // using 编译指令：整个空间可见，慎用

注意： ROS2 代码里 using namespace std; 是常见反模式。rclcpp 自身大量使用 std:: 前缀，一旦你全局 using，rclcpp::Timer、std::chrono 等与自定义名字冲突时编译错误会非常难懂。

8.2.2 第2课：C++ 相较于 C 语言的优势特性解析

编译期检查的全面增强

  • 核心概念：C++ 在编译期检查上全面强于 C，同时提供 const、引用等零开销抽象。这些增强不是语法糖，而是后续类、模板、泛型算法的地基。
  • 全局变量检测增强：C 语言中重复声明同名全局变量可能蒙混过关；C++ 会报「重定义」错误。C++ 要求全局变量声明与定义严格区分（extern int x; 只是声明）。
  • 函数检测增强：C 不检查实参类型与个数，也不要求声明返回值；C++ 严格检查参数类型、个数、返回值，且调用未声明函数直接报错。
  • 类型转换检测增强：C 允许 void* 与任意指针隐式互转、malloc 返回值直接赋给具体指针；C++ 必须显式转换（static_cast 等），void* → 具体指针也需强转。这把大量「运行期崩溃」提前到「编译期报错」。
  • 结构体增强：C 的 struct 只能放数据；C++ 的 struct 可以有成员函数、构造函数、访问权限（public/private），本质是默认 public 的 class。ROS2 生成的消息类型 std_msgs::msg::Header 等就是带成员函数的结构体/类。
  • bool 类型增强：C++ 有真正的 bool（true/false 是关键字），bool 变量非 0 值赋值都会被归一化为 1，可与整数互相转换但更安全。
  • 三元表达式增强：C 的 a ? b : c 只能得到值；C++ 中若 b、c 是同类型左值，结果是左值（可被赋值），常用于链式条件赋值。

const 增强与内存分配

  • C++ 中 const 修饰的是编译期常量，可以直接作数组长度（C 中不行）；
  • const 全局变量是内部链接（各编译单元私有，不像 C 那样默认外部链接），头文件里定义 const 常量不会重定义；
  • 但对 const 变量取地址、或用 extern 修饰时，编译器会为其分配内存——此时它是「只读变量」而非纯常量；
  • 用 const/constexpr 代替 #define：有类型检查、有作用域、可调试。
constexpr int kMaxJoints = 6;         // 编译期常量，可作数组长度
double offsets[kMaxJoints] = {0};

const int kBufSize = 256;             // const 常量：有类型、有作用域
const int* p = &kBufSize;             // 取地址后，编译器为其分配内存

引用体系：别名、传参与常量引用

  • 引用（reference）基本语法：类型& 别名 = 原名; 引用是变量的别名，必须初始化、不能改指向、不能为空。
  • 引用的细节与底层原理：
    • 引用必须初始化，且初始化后不能再改为引用其他变量（区别于指针）；
    • 底层实现是指针常量 T* const，由编译器完成解引用，所以「引用即别名」是语言层面的语义保证；
    • 可以对引用再取引用（本质还是同一变量）；
    • 数组不能直接整体引用，需要用指针或 std::array/std::vector。
  • 引用实现参数传递：按引用传参（void f(T& x)）避免拷贝大对象，且可被调用方修改实参；只读场景用 const T&。这是 C++ 代码里最常见的函数签名，也是 ROS2 回调常用 const std_msgs::msg::X::SharedPtr msg 的理论背景。
  • 指针引用（T*&）：引用可以作为指针的别名，常用于「函数内改变外部指针指向」的场景（如工厂函数返回对象指针、链表头插）。
  • 常量引用（const T&）：可绑定字面量/临时量并延长其生命周期；用作只读参数既避免拷贝又防止误改。
void scale(double k, const std::vector<double>& in, std::vector<double>& out);
// in 只读、out 可写、k 传值：意图一目了然

注意： 不要返回局部变量的引用（悬垂引用）；函数需要返回新对象时返回值（编译器有 RVO 优化，不亏），需要返回成员时可返回引用。

8.2.3 第3课：内联函数与类和对象

  • 核心概念：宏函数没有类型检查、易因优先级出错、无法调试；内联函数（inline）以「建议编译器展开」的方式替代宏，保留类型安全与调试能力。
  • 宏函数缺陷与内联函数：#define MAX(a,b) ((a)>(b)?(a):(b)) 会多次求值且无类型检查；改写为 inline 函数即可避免。现代 C++ 中简单小函数直接在类内定义，编译器通常自动内联，inline 更多用于头文件中定义函数避免重定义（如 STL 风格）。
  • 函数默认值：参数可从右向左给默认值；声明与定义只能一处给默认值（一般放头文件声明处）。rclcpp 接口常靠默认值减少样板代码。
  • 占位参数（unnamed parameter）：函数声明中只写类型不写名字 void f(int, int b)，用于占位兼容接口或预留扩展点。
  • 函数重载（overload）：同一作用域内函数名相同、参数列表不同（类型/个数/顺序）即可重载；仅返回类型不同不算重载。编译器按「重载决议」选最佳匹配。
  • 函数重载细节：注意隐式转换带来的二义性（如 f(int) 与 f(double) 调 f(1.5f) 可能二义）、默认参数与重载的组合坑。重载是 std::cout << 与 ROS2 参数模板接口的实现基础。
  • extern "C"：C++ 支持函数重载靠名字修饰（name mangling）；用 extern "C" 包裹声明可让函数按 C 规则链接，便于调用 C 库（如驱动 SDK、C 语言编写的传感器接口）。
extern "C" {
    int lidar_open(const char* dev);   // 按 C 符号链接，无名字修饰
}
  • 封装与访问权限：封装 = 数据 + 操作数据的函数绑在一起，并用访问权限控制接口。public（对外接口）/ protected（子类可见）/ private（仅类内可见），class 默认 private，struct 默认 public。
  • 尽量设置成员为私有：成员一律 private，通过 getter/setter 暴露受控接口——可在 setter 中做合法性校验、加锁、发通知，日后改内部实现不破坏使用者。rclcpp 的参数接口 declare_parameter/get_parameter 就是这种设计。
  • 立方体案例：设计 Point3D 与 Cube 两个类——成员私有、getter/setter 校验尺寸为正、提供求面积/体积、判断两个立方体是否相等、判断点是否在立方体内（分别用成员函数与全局函数 + 友元两种方式）。这是「类设计 + 封装 + 接口划分」的入门级综合练习。

8.3 重点与难点

  1. 引用 vs 指针：引用是必须初始化、不可改指向的别名，底层是常量指针；优先用引用表达「必填的可写/只读出参」，需要「可能为空 / 需要改指向」才用指针。
  2. const 的三重身份：编译期常量、内部链接、只读变量（取地址后有内存）。constexpr 与 const 的区别（前者要求编译期可求值）是面试常考点。
  3. 命名空间卫生：头文件中禁止 using namespace；实现文件中局部 using 声明优先于编译指令。
  4. 封装的度：成员一律私有不是教条，而是给「变化」留缓冲层——这与 ROS2 节点把 publisher/subscription 收进类成员、只暴露 spin 接口是同一思想。
  5. 重载决议与二义性：默认参数、隐式转换、const 修饰的重载（f(T&) vs f(const T&)）共同决定匹配结果，出错信息很长，要学会从「候选函数列表」里定位原因。

// ref_demo.cpp
#include <iostream>
#include <vector>

void add_bias(const std::vector<double>& in,   // 只读：不拷贝、不修改
              std::vector<double>& out,        // 可写出参
              double*& cursor) {               // 指针引用：可改变外部指针
    out.clear();
    for (double v : in) out.push_back(v + 0.1);
    cursor = out.data();            // 影响调用方的指针
}

int main() {
    std::vector<double> src{1.0, 2.0, 3.0}, dst;
    double* p = nullptr;
    add_bias(src, dst, p);
    std::cout << dst.size() << " " << (p == dst.data()) << "\n";   // 3 1
}

// inline_overload.cpp
#include <iostream>
#include <string>

template <typename T>
inline T clamp(T v, T lo, T hi) { return v < lo ? lo : (v > hi ? hi : v); }

void log(int v)    { std::cout << "[int] " << v << "\n"; }
void log(double v) { std::cout << "[dbl] " << v << "\n"; }
void log(const std::string& s) { std::cout << "[str] " << s << "\n"; }

int main() {
    std::cout << clamp(5, 0, 3) << "\n";       // 3
    log(1); log(1.5); log(std::string("ok"));  // 重载决议按实参类型
}

场景 5：封装与访问权限（立方体案例，对应第3课）

// cube.cpp
#include <iostream>
#include <stdexcept>

class Point3D {
public:
    Point3D(double x = 0, double y = 0, double z = 0) : x_(x), y_(y), z_(z) {}
    double x() const { return x_; }
    double y() const { return y_; }
    double z() const { return z_; }
private:
    double x_, y_, z_;                 // 成员私有，只暴露只读接口
};

class Cube {
public:
    Cube(double l, double w, double h) : l_(l), w_(w), h_(h) {
        if (l <= 0 || w <= 0 || h <= 0) throw std::invalid_argument("size must be > 0");
    }
    double volume() const { return l_ * w_ * h_; }
    bool contains(const Point3D& p) const {
        return p.x() >= 0 && p.x() <= l_ && p.y() >= 0 && p.y() <= w_ && p.z() >= 0 && p.z() <= h_;
    }
    bool same_size(const Cube& other) const {
        return l_ == other.l_ && w_ == other.w_ && h_ == other.h_;
    }
private:
    double l_, w_, h_;
};

int main() {
    Cube box(2, 3, 4);
    std::cout << box.volume() << " " << box.contains({1, 1, 1}) << "\n";   // 24 1
    std::cout << box.same_size(Cube(2, 3, 4)) << "\n";                     // 1
}

g++ -std=c++17 -Wall -o cube cube.cpp && ./cube

端到端实战（实测）：Rectangle 类

需求：实现 Rectangle（成员私有、构造校验为正、area()/perimeter()），并实现判断两矩形能否拼成正方形的全局函数——封装 + 构造校验异常 + 全局协作函数的综合案例（与课程立方体案例同型）：

// rect.cpp
class Rectangle {
public:
    Rectangle(double w, double h) : w_(w), h_(h) {
        if (w <= 0 || h <= 0) throw std::invalid_argument("尺寸必须为正");
    }
    double area() const { return w_ * h_; }
    double perimeter() const { return 2 * (w_ + h_); }
    double width() const { return w_; }
    double height() const { return h_; }
private:
    double w_, h_;
};

bool can_form_square(const Rectangle& a, const Rectangle& b) {
    return std::fabs(a.width() - b.height()) < 1e-9 &&
           std::fabs(a.height() - b.width()) < 1e-9;   // 旋转后可拼成正方形
}

视频对照：课程 立方体案例 的全局函数 com_cube(Cube &c1, Cube &c2)（引用参数 + getter 比较）与 c1.set_l(10) 系列调用已逐字复现：体积=1000 相等=1，见《端到端核对报告》基础篇表。

实测（g++ -std=c++17 -Wall）：

r1 面积=12 周长=14
可组正方形=1
caught: 尺寸必须为正

要点解析：

  • 非法尺寸在对象创建阶段即被构造函数抛出的 std::invalid_argument 拦截（fail fast，坏数据进不了系统）；
  • 全局函数 can_form_square 只通过公有 getter 读长宽，不触碰私有成员——封装与全局协作函数并存；
  • 浮点等值比较用 std::fabs(...) < 1e-9 容差判断，避免浮点「看似相等实则不等」的陷阱。

8.6 与 ROS2 / 机器人开发的关联

  1. 命名空间即库边界：rclcpp、sensor_msgs::msg、nav_msgs::msg 全靠命名空间避免冲突；写自己的功能包（如 my_robot::planner）也应从第一天起建命名空间。
  2. 引用与 const 引用 = 回调函数标准签名：void topic_cb(const std_msgs::msg::String::SharedPtr msg) 用智能指针 + const 语义表达「只读消息」，避免每条消息拷贝，直接决定实时性。
  3. 封装 = 节点类设计：把 publisher/subscription/timer 收进类私有成员，对外只留 spin() 或几个业务方法，是 rclcpp 官方示例的统一写法。
  4. extern "C" 打通硬件 SDK：机器人相机、雷达、运动控制卡的 SDK 多为 C 接口，需要在 C++ 项目中用 extern "C" 包裹头文件。
  5. 内联与 constexpr 提升实时性能：控制循环中的小工具函数（限幅、角度归一化）用 constexpr/inline 写在头文件，零开销且可编译期计算。

8.8 常见问题（FAQ）

  • Q：struct 和 class 到底怎么选？ A：语义上只有默认访问权限的差别。习惯上「纯数据聚合、无不变式」用 struct（如消息类型、点云点），「有不变式、需封装」用 class。
  • Q：inline 函数必须写 inline 才会被展开吗？ A：不是。类内定义的函数默认隐式 inline；编译器是否真展开取决于优化等级。inline 现在更重要的作用是允许函数在多个翻译单元定义而不报链接错误。
  • Q：const 变量到底分配不分配内存？ A：能被编译器折叠为常量的就不分配；一旦取地址或 extern 声明就会分配，此时它退化为「只读变量」。
  • Q：引用能为空吗？能改指向吗？ A：都不能。需要「可能为空」或「需要改指向」的语义时用指针（或 std::optional/智能指针）。
  • Q：为什么 ROS2 回调参数多是智能指针而不是引用？ A：消息由中间件持有，生命周期跨回调，用 SharedPtr 共享所有权最安全；const ... SharedPtr 表达只读意图。

8.9 本章小结

  • 命名空间即库边界（rclcpp、sensor_msgs::msg）——自己的功能包从第一天起建命名空间；
  • 引用与 const T& 是回调函数标准签名的理论基础；
  • 封装 = 节点类设计：publisher/subscription 收进私有成员、只暴露必要接口；
  • extern "C" 打通 C 语言编写的传感器 SDK；
  • 用 const/constexpr 代替 #define：有类型、有作用域、可调试；
  • 内联与函数重载是 std::cout << 与 ROS2 模板参数接口的实现基础。
