10.2 知识点梳理

10.2.1 第1课：继承机制深度解析与应用实践

  • 核心概念：继承（Inheritance）让派生类（derived class）复用基类（base class）的成员并扩展新能力，表达 is-a 关系。ROS2 中 rclcpp::Node 是基类，你的节点类继承它就自动获得 create_publisher 等接口。
  • 继承基础语法：class Dog : public Animal { ... };。三种继承方式 public/protected/private 决定基类成员在派生类中的访问级别：public 继承保持原有级别，protected 继承把 public 降级为 protected，private 继承把所有成员降级为 private（is-a 变 has-a-like）。
  • 派生类访问权限：private 成员在派生类不可直接访问（需通过基类的 public/protected 接口）；protected 成员对派生类可见、对外不可见。设计原则：基类对外 public、对子类 protected、内部实现 private。
  • 继承的对象模型：派生类对象内存 = 基类子对象 + 新增成员（可看成「大对象里嵌小对象」）。这决定了指针/引用的向上转换安全性。
  • 继承中的构造和析构：派生类构造前基类构造先执行（按继承声明顺序），析构相反。派生类构造函数可通过初始化列表调用指定基类构造函数。
  • 用初始化列表调用父类构造：Derived(...) : Base(...), member_(...)。基类无默认构造时必须显式调用，否则编译错误。
  • 继承中同名成员处理：派生类成员遮蔽（shadow）基类同名成员；用 Base::name 显式访问被遮蔽者。同名成员函数也会遮蔽（除非用 using Base::f; 或 Base::f()）。
  • 继承中同名的静态成员处理：静态成员属于类，派生类通过 派生类::成员 或 基类::成员 访问同一份；遮蔽规则同普通成员，可用 Base:: 解决。
  • 多继承：class C : public A, public B。注意成员名冲突需限定（A::x vs B::x），且易产生菱形继承问题，工程中慎用（优先组合）。
  • 菱形继承与虚继承：两个中间类继承同一基类，最底层类重复持有基类成员 → 二义性。用虚继承（class B : virtual public A）让共同基类只保留一份。代价：对象布局复杂、构造责任上移、性能略降。Qt 等框架用虚继承管理 QObject 树。

10.2.2 第2课：虚函数与抽象类原理及使用

  • 核心概念：多态（Polymorphism）= 同一接口、不同实现。静态联编（编译期绑定）效率高，动态联编（运行期绑定，通过虚函数表 vtable）灵活。
  • 静态联编和动态联编：普通函数调用、重载决议是静态联编；通过基类指针/引用调用虚函数时按对象实际类型分派（动态联编），前提是函数声明 virtual 且签名一致。
  • 计算器案例：用抽象类 Operation + 派生 Add/Sub/Mul，在客户端用 Operation* op = new Add; 执行 op->calculate(a,b)——新增乘除只需加类，不改客户端（开闭原则）。
  • 纯虚函数和抽象类：virtual void f() = 0; 为纯虚函数；含纯虚函数的类是抽象类，不能实例化，只能作接口。派生类必须实现全部纯虚函数才能实例化。
  • 虚析构和纯虚析构：基类析构必须 virtual，否则 delete Base* 只调基类析构导致资源泄漏。纯虚析构 virtual ~Base() = 0; 需类外给出定义（Base::~Base() {}），用于强制抽象。
  • 向上、向下类型转换：向上（派生→基类指针/引用）安全隐式；向下（基类→派生）需 dynamic_cast 做运行期检查（基类必须有虚函数），失败返回 nullptr/抛 bad_cast。
  • 重载、重定义、重写：重载（同一作用域，参数不同）、重定义（派生类同名遮蔽基类，无 virtual）、重写（override，派生类实现基类虚函数、签名完全一致）。C++11 建议加 override 关键字让编译器检查。
class Device {
public:
    virtual void start() = 0;                // 纯虚 → 抽象接口
    virtual ~Device() = default;             // 虚析构，防止 delete 基类指针泄漏
};

class Lidar : public Device {
public:
    void start() override { /* ... */ }      // override 强制检查签名
};

注意： 只有通过指针或引用调用虚函数才有多态；按值传参对象会被「切片（slicing）」成基类对象，动态类型信息丢失。

10.2.3 第3课：函数模板特性详解与实战运用

  • 核心概念：模板（Template）= 泛型编程的工具，把类型参数化。函数模板让「同一逻辑」适用于所有支持相应运算的类型。
  • 自动推导与显式指定：T max_of(T a, T b) 由编译器按实参推导 T；类型不一致时可显式 max_of<int>(1, 2.5) 或提供默认模板参数。
  • 模板练习：实现 swap_t、print_arr、sort_desc 等通用函数，体会「一次编写、到处实例化」。
  • 模板函数与普通函数的区别：模板是编译期按需生成的蓝图；普通函数是已编译实体。模板调用可能产生多份代码（代码膨胀），但换来类型通用。
  • 调用规则：优先普通函数（精确匹配）；模板只在普通函数不匹配或显式指定时使用；可重载模板、可特化。
  • 模板实现机制：编译器做两次检查——语法检查 + 实例化检查（不使用不实例化，所以未调用的模板里写错类型可能不报错）。
  • 模板的局限性：模板不知道某类型支持哪些运算（如 a + b 对自定义类型可能无定义），解决办法是「实例化时报错 + 提供特化」。
  • 具体化（特化）提供特殊模板：template<> T max_of(Person a, Person b) { ... } 为特定类型定制实现。优先级：非模板 > 显式特化 > 普通模板。
  • 类模板基本语法：template <typename T> class Box { T data_; }; 使用 Box<int> b; 或 C++17 推导 Box b(42);（CTAD）。
  • 类模板成员函数的调用时机：成员函数在调用时才实例化，未调用的成员不参与类型检查（懒实例化）。
  • 类模板做函数参数：函数可声明 void f(Box<int>&)（具体化）、template<typename T> void f(Box<T>&)（泛型），或用基类指针/接口解耦。
  • 类模板和继承：基类是模板时，派生类必须指定具体类型 class D : public Base<int>，或把派生类也声明为模板 template<typename T> class D : public Base<T>。
  • 类模板的成员函数在类外实现：需要 template<typename T> void Box<T>::show() { ... } 完整前缀。
  • 分文件编写：模板不能只在 .cpp 定义（链接期看不到实例化）。惯例：声明 + 实现都放 .h/.hpp，或 .cpp 中显式实例化 template class Box<int>;。
  • 友元和类模板：类模板的友元需 template<typename> friend class X; 或全局友元函数，语法繁琐，慎用。

10.2.4 第4课：类型转换、异常处理及输入输出操作

  • 核心概念：C++ 强制使用显式转换（static_cast/dynamic_cast/const_cast/reinterpret_cast）替代 C 风格强转，转换意图写在代码里；异常提供错误传播机制；I/O 流统一了终端与文件操作。
  • 静态转换（static_cast）：编译期转换，用于有明确关系的类型（数值互转、void* ↔ 具体指针、上行转换）。不做运行期检查，性能零开销。
  • 动态转换（dynamic_cast）：运行期安全转换（下行/交叉转换），依赖 RTTI 与虚函数；失败返回 nullptr（指针）或抛 std::bad_cast（引用）。
  • const_cast：去掉或添加 const，用于调用遗留 C 接口；若对象本身是 const 却去掉 const 并修改，属未定义行为。
  • reinterpret_cast（重新解释转换）：按位重新解释（指针↔整数、不同类型指针互转），危险，仅在驱动/序列化等底层场景使用。
  • 异常基本语法：throw 表达式; → 沿调用栈找 try/catch；catch (类型& e) 按类型匹配，可用 catch (...) 兜底。异常对象按值抛出、按引用捕获。
  • 异常的传递：沿调用链向上传播，若无人捕获则调用 std::terminate 终止程序。ROS2 回调中必须自己捕获，否则整个 executor 崩溃。
  • 自己抛出异常：throw std::invalid_argument("...")；抛出后栈解旋（stack unwinding）自动析构已构造对象。
  • 栈解旋：抛出异常时，从 try 到 throw 之间的栈上对象全部析构（RAII 保证资源释放），这是 unique_ptr、std::lock_guard 安全的底层机制。
  • 异常变量的生命周期：按值抛出会复制异常对象；按引用捕获 catch (const std::exception& e) 避免切片与二次拷贝；捕获 e 的引用在 catch 块内有效。
  • 异常的多态：基类 std::exception 的 what() 是虚函数，可用一个 catch (const std::exception&) 捕获所有标准异常并打印具体信息。
  • 系统标准异常：std::exception、std::runtime_error、std::logic_error、std::out_of_range、std::bad_alloc 等；what() 返回错误描述。
  • 自己写的异常类：继承 std::runtime_error，添加错误码/上下文信息，便于分层捕获。
  • 标准输入（cin 系列 7 小节）：operator>> 格式化提取、getline 读整行（含空格）、cin.ignore/cin.get/cin.clear/cin.fail 处理缓冲区残留与错误状态、std::ws 跳过空白；输入案例演示「循环读取直到 EOF/非法输入」。
  • 字符输出与格式化输出：put/printf 风格 std::cout.put('A')、std::setw/std::setfill/std::setprecision/std::fixed（<iomanip>）控制宽度、填充、精度；std::boolalpha 让 bool 打印 true/false。
  • 文件写入与读取：std::ofstream 写、std::ifstream 读，is_open() 判断，<</getline 读写，std::fstream 读写混合；文本模式与二进制模式（std::ios::binary）区别。

10.3 重点与难点

  1. 虚函数表与动态联编：有虚函数的类首部有 vptr 指向 vtable；按值传参的切片问题会让多态失效——用指针/引用。
  2. 纯虚函数与接口设计：抽象类定契约、派生类给实现，是 ROS2 插件（pluginlib）、导航控制器接口的通用范式。
  3. 虚析构必要性：基类析构非 virtual + delete Base* = 泄漏；写基类第一行就该写 virtual ~Base() = default;。
  4. 模板的分文件陷阱：模板实现在 .cpp 会链接失败；模板头文件需含实现（.hpp 或 #include "xx.tpp"）。
  5. 异常安全：异常抛出时栈解旋保证 RAII 对象析构；不要在析构函数中抛异常（会导致 terminate）；ROS2 实时回调里更常用错误码/std::optional 而非异常。

场景 1：继承、构造顺序、同名成员（对应第1课）

// inherit.cpp
#include <iostream>
#include <string>

class Base {
public:
    explicit Base(std::string id) : id_(std::move(id)) { std::cout << "Base ctor\n"; }
    virtual ~Base() { std::cout << "Base dtor\n"; }
    void show() const { std::cout << "Base::show " << id_ << "\n"; }
protected:
    std::string id_;
};

class Derived : public Base {
public:
    Derived(std::string id, int extra) : Base(std::move(id)), extra_(extra) {
        std::cout << "Derived ctor\n";
    }
    ~Derived() override { std::cout << "Derived dtor\n"; }
    void show() const { std::cout << "Derived::show " << id_ << " " << extra_ << "\n"; }  // 重定义
    void callBase() const { Base::show(); }                    // 显式调用基类版本
private:
    int extra_;
};

int main() {
    Derived d("robot1", 7);
    d.show();
    d.callBase();
    Base* p = &d;          // 向上转换（安全）
    p->show();             // 静态联编：调 Base::show（无 virtual 时）
}

g++ -std=c++17 -Wall -o inherit inherit.cpp && ./inherit

场景 2：虚函数多态 + 抽象类 + 虚析构（对应第2课）

// poly.cpp
#include <iostream>
#include <memory>
#include <vector>

class Controller {                       // 抽象类：接口契约
public:
    virtual double compute(double err) = 0;      // 纯虚函数
    virtual ~Controller() = default;             // 虚析构
};

class Pid : public Controller {
public:
    Pid(double kp, double ki, double kd) : kp_(kp), ki_(ki), kd_(kd) {}
    double compute(double err) override {
        integral_ += err;
        double out = kp_ * err + ki_ * integral_ + kd_ * (err - prev_);
        prev_ = err;
        return out;
    }
private:
    double kp_, ki_, kd_, integral_ = 0, prev_ = 0;
};

class BangBang : public Controller {
public:
    double compute(double err) override { return err > 0 ? 1.0 : -1.0; }
};

int main() {
    std::vector<std::unique_ptr<Controller>> ctrls;   // 多态容器
    ctrls.push_back(std::make_unique<Pid>(1.0, 0.1, 0.05));
    ctrls.push_back(std::make_unique<BangBang>());
    for (const auto& c : ctrls) std::cout << c->compute(0.5) << "\n";   // 动态联编
}

g++ -std=c++17 -Wall -o poly poly.cpp && ./poly

场景 3：函数模板、特化与类模板（对应第3课）

// template_demo.cpp
#include <iostream>
#include <string>
#include <vector>

template <typename T>
T max_of(T a, T b) { return a > b ? a : b; }

template <>                                    // 显式特化：针对 const char*
const char* max_of(const char* a, const char* b) {
    return std::string(a) > std::string(b) ? a : b;
}

template <typename T>
class RingBuffer {                             // 类模板
public:
    explicit RingBuffer(std::size_t cap) : cap_(cap) {}
    void push(const T& v) {
        if (buf_.size() == cap_) buf_.erase(buf_.begin());
        buf_.push_back(v);
    }
    std::size_t size() const { return buf_.size(); }
private:
    std::size_t cap_;
    std::vector<T> buf_;
};

int main() {
    std::cout << max_of(3, 5) << " " << max_of(2.5, 1.5) << "\n";
    std::cout << max_of("apple", "banana") << "\n";     // 使用特化
    RingBuffer<int> rb(3);
    for (int i = 1; i <= 4; ++i) rb.push(i);
    std::cout << rb.size() << "\n";                     // 3
}

g++ -std=c++17 -Wall -o template_demo template_demo.cpp && ./template_demo

场景 4：类型转换 + 异常处理（对应第4课）

// cast_throw.cpp
#include <iostream>
#include <memory>
#include <stdexcept>
#include <string>

struct Shape { virtual ~Shape() = default; };
struct Circle : Shape { double r = 1.0; };
struct Square : Shape { double a = 2.0; };

double parse_positive(const std::string& s) {
    double v = std::stod(s);
    if (v <= 0) throw std::invalid_argument("must be positive: " + s);
    return v;
}

int main() {
    try {
        Shape* p = new Circle;
        if (auto* c = dynamic_cast<Circle*>(p))            // 向下转换：运行期检查
            std::cout << "circle r=" << c->r << "\n";
        std::cout << parse_positive("3.14") << "\n";
        std::cout << parse_positive("-1") << "\n";          // 抛出异常
    } catch (const std::invalid_argument& e) {
        std::cerr << "[caught] " << e.what() << "\n";       // 按引用捕获，避免切片
    } catch (const std::exception& e) {
        std::cerr << "[std] " << e.what() << "\n";
    } catch (...) {
        std::cerr << "[unknown]\n";
    }
}

端到端实战（实测）：多态传感器容器 + dynamic_cast

抽象类定契约、多态容器管理异构设备、向下转换识别具体类型——ROS2 传感器插件架构的浓缩版：

// sensor.cpp
class Sensor {                                   // 抽象类
public:
    virtual void read() const = 0;
    virtual ~Sensor() = default;                 // 虚析构
};
class Lidar : public Sensor {
public:
    void read() const override { std::cout << "[lidar] ranges=360\n"; }
};
class Camera : public Sensor {
public:
    explicit Camera(int w) : width_(w) {}
    void read() const override { std::cout << "[camera] width=" << width_ << "\n"; }
    int width() const { return width_; }         // 私有成员经公有接口暴露
private:
    int width_;
};

std::vector<std::unique_ptr<Sensor>> sensors;    // 多态容器
sensors.push_back(std::make_unique<Lidar>());
sensors.push_back(std::make_unique<Camera>(640));
for (const auto& s : sensors) s->read();         // 动态联编
for (const auto& s : sensors)
    if (auto* cam = dynamic_cast<const Camera*>(s.get()))
        std::cout << "found camera width=" << cam->width() << "\n";

实测（g++ -std=c++17 -Wall）：

[lidar] ranges=360
[camera] width=640
found camera width=640

编写时恰好踩到本章知识点：在类外直接访问私有成员 cam->width_ 被编译器拦截——改为经公有接口 width() 暴露。封装不是教条，是编译器帮你挡 bug。

要点解析：

  • Sensor 声明纯虚 read() 即成抽象类，Lidar/Camera 各自 override 实现——新增第三种传感器（如 IMU）只加派生类，主循环零改动（开闭原则）；
  • dynamic_cast<const Camera*> 运行期识别具体类型，失败得 nullptr，基类含虚析构才保证 RTTI 可用；
  • unique_ptr 管理多态对象生命周期，容器销毁时经虚析构逐个正确释放。

10.6 与 ROS2 / 机器人开发的关联

  1. 继承是 ROS2 节点架构：class MyNode : public rclcpp::Node、LifecycleNode、导航插件（nav2_core::Controller）都是「抽象基类 + 派生实现」；override 关键字从今天开始养成习惯。
  2. 多态管理异构设备：相机/雷达/IMU 统一 Sensor 抽象接口，节点内用 std::vector<std::unique_ptr<Sensor>> 轮询采集，新增设备不改主流程。
  3. 模板与 rclcpp API：create_subscription<T>(...)、rclcpp::Subscription<MsgT> 是类模板；理解实例化机制才看得懂编译错误。
  4. 类型转换与消息指针：dynamic_cast 用于把 rclcpp::Node* 转回具体节点类；std::static_pointer_cast 用于消息智能指针转换。
  5. 异常与回调安全：ROS2 回调中未捕获异常会终止 executor；日志记录用 try/catch 包住解析/文件/网络调用，兜底 std::exception。
  6. 文件 I/O 与配置：参数文件、轨迹 CSV、标定 YAML 的读写都用 fstream/<iomanip>；为后面 nav2 参数调试打底。

10.7 自测与练习（含参考答案要点）

  1. 概念题：静态联编与动态联编的区别是什么？什么条件下才会触发动态联编？
  2. 概念题：为什么基类析构函数必须是 virtual？纯虚析构和普通虚析构有何不同？
  3. 动手任务：设计 Sensor 抽象基类 + Lidar/Camera 两个派生类，用 std::vector<std::unique_ptr<Sensor>> 统一调用 read() 并打印各自数据。验收：新增第三种传感器不修改主循环代码。
  4. 动手任务：写模板函数 template<typename T> double sum(const std::vector<T>& v)，并为 std::vector<std::string> 提供特化（返回总字符数）。验收：显式特化优先于通用模板生效。

参考答案要点：题 1——静态联编在编译期绑定（普通函数/重载），动态联编在运行期按对象实际类型分派，条件是「通过指针/引用调用 + 函数声明 virtual + 签名一致」。题 2——否则 delete Base* 只调基类析构，派生类资源泄漏；纯虚析构 virtual ~B() = 0; 强制抽象但必须类外定义。题 3——容器持有 unique_ptr<Sensor>，read() 声明纯虚，派生类 override。题 4——通用模板用 T 累加，特化版本遍历 size()。

10.8 常见问题（FAQ）

  • Q：override 关键字有什么用？ A：强制编译器检查是否真的重写了基类虚函数，签名不一致时报错，防止「以为重写其实重定义」的 bug。
  • Q：dynamic_cast 什么时候返回 nullptr？ A：基类指针指向的对象实际类型不包含目标类型时（下行转换失败）；要求基类至少有一个虚函数（保证 RTTI）。
  • Q：模板为什么不能分文件写？ A：模板实例化发生在使用处，编译 .cpp 时编译器看不到模板实现，链接期找不到符号。惯例是实现放头文件。
  • Q：什么时候用异常，什么时候用返回码？ A：异常适合「罕见、不可局部处理」的错误（配置解析、文件缺失）；实时控制回路里更适合错误码/std::optional，避免栈解旋开销。
  • Q：catch 应该捕获值还是引用？ A：捕获引用（const std::exception&），避免对象切片和多余拷贝。

10.9 本章小结

  • 「抽象基类 + 派生实现」是 rclcpp 节点、LifecycleNode、nav2 插件的通用范式；
  • 多态容器 std::vector<std::unique_ptr<Sensor>> 让新增设备不改主流程（开闭原则）；
  • create_subscription<T> 是类模板——理解实例化机制才看得懂模板编译错误；
  • 实时控制回路里更常用错误码/std::optional，异常留给「罕见且不可局部处理」的错误；
  • 基类析构必写 virtual，派生类重写必标 override；
  • 模板实现放头文件（.hpp），分文件是模板最常见的新手陷阱。
