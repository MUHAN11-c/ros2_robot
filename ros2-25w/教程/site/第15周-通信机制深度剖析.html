第15章 通信机制深度剖析

第15章 通信机制深度剖析

通信机制是 ROS2 的核心。本章依次完成话题、服务、动作、参数四种通信机制的案例实现（含自定义接口消息），每种机制都按「案例分析 → 接口消息 → C++ 实现 → Python 实现 → 运行效果」展开。

本章对应代码：code/ws01_plumbing/src/base_interfaces_demo、cpp01_topic、py01_topic、cpp02_service、py02_service、cpp03_action、py03_action、cpp04_param、py04_param。

15.1 话题通信

15.1.1 案例以及案例分析

需求：发布方以 1Hz 发布文本消息，订阅方接收并打印（原生消息 std_msgs/String）；随后改用自定义消息 Student（姓名/年龄/身高）重复该案例。

流程：

  1. 编写发布方；
  2. 编写订阅方；
  3. 编辑配置文件；
  4. 编译；
  5. 执行（先启动发布方，再启动订阅方）。

15.1.2 C++ 实现（原生消息）

发布方核心代码（cpp01_topic/src/demo01_talker_str.cpp）：

// 3.自定义节点类；
class Talker: public rclcpp::Node{
public:
    Talker():Node("talker_node_cpp"){
        RCLCPP_INFO(this->get_logger(),"发布节点创建!");
        // 3-1.创建发布方；
        publisher_ = this->create_publisher<std_msgs::msg::String>("chatter",10);
        // 3-2.创建定时器，周期性发布；
        timer_ = this->create_wall_timer(1s,std::bind(&Talker::on_timer,this));
    }
private:
    void on_timer(){
        auto msg = std_msgs::msg::String();
        msg.data = "hello world!" + std::to_string(count_++);
        RCLCPP_INFO(this->get_logger(),"发布方发布的消息:%s",msg.data.c_str());
        publisher_->publish(msg);
    }
    rclcpp::Publisher<std_msgs::msg::String>::SharedPtr publisher_;
    rclcpp::TimerBase::SharedPtr timer_;
    int32_t count_ = 0;
};

订阅方（demo02_listener_str.cpp）在回调中打印：

void topic_callback(const std_msgs::msg::String::SharedPtr msg){
    RCLCPP_INFO(this->get_logger(),"订阅的消息：'%s'",msg->data.c_str());
}

15.2 服务通信

15.2.1 案例以及案例分析

需求：客户端提交两个整型数据，服务端求和后响应。接口 srv/AddInts.srv：

int32 num1
int32 num2
---
int32 sum

15.2.2 C++ 实现

服务端（cpp02_service/src/demo01_server.cpp）：

using AddInts = base_interfaces_demo::srv::AddInts;
using namespace std::placeholders;

class AddIntsServer: public rclcpp::Node{
public:
    AddIntsServer():Node("add_ints_server_node_cpp"){
        RCLCPP_INFO(this->get_logger(),"服务端节点创建!");
        // 3-1.创建服务端；
        server_ = this->create_service<AddInts>("add_ints",std::bind(&AddIntsServer::add,this,_1,_2));
    }
private:
    // 3-2.编写回调函数处理请求并产生响应；
    void add(const AddInts::Request::SharedPtr req, const AddInts::Response::SharedPtr res){
        res->sum = req->num1 + req->num2;
        RCLCPP_INFO(this->get_logger(),"%d + %d = %d",req->num1, req->num2, res->sum);
    }
    rclcpp::Service<AddInts>::SharedPtr server_;
};

客户端（demo02_client.cpp）通过命令行参数提交数据，spin_until_future_complete 等待响应。

15.2.3 运行效果（实测）

客户端程序（提交 3 和 5）：

[INFO] [...]: 发送请求: num1=3, num2=5
[INFO] [...]: 收到响应: sum=8

15.3 动作通信

15.3.1 案例以及案例分析

需求：客户端提交一个整型数 n，服务端连续反馈求和进度（百分比），最终响应 1~n 的累加和。接口 action/Progress.action：

int64 num
---
int64 sum
---
float64 progress

15.3.2 C++ 实现要点

服务端（cpp03_action/src/demo01_action_server.cpp）：

  • 目标处理：num >= 1 才接受（ACCEPT_AND_EXECUTE），否则拒绝；
  • 执行体在子线程中运行（std::thread{...}.detach()），以 Rate(1Hz) 连续反馈 progress；
  • 客户端（demo02_action_client.cpp）注册目标响应/连续反馈/最终响应三个回调。

兼容提示：Jazzy 起客户端「目标响应回调」直接接收 GoalHandle::SharedPtr；Humble 中为 std::shared_future<GoalHandle::SharedPtr>（需 .get()）。

15.3.3 运行效果（实测）

    progress: 0.1

    progress: 0.2

Feedback:
    progress: 0.3

Result:

15.4 参数服务

15.4.1 案例以及案例分析

需求：参数服务端节点实现参数的增、删、改、查；客户端节点远程读写服务端参数。演示参数 car_name=tiger、width=1.55、wheels=5。

15.4.2 C++ 实现要点

服务端（cpp04_param/src/demo01_param_server.cpp）：

ParamServer():Node("param_server_node_cpp",rclcpp::NodeOptions().allow_undeclared_parameters(true)){
    // 增 → 查 → 改 → 查 → 删 → 查
}

兼容提示：Jazzy 中 declare_parameter 声明的是静态类型参数，无法被 undeclare_parameter 删除（Humble 中同理），会抛出 cannot undeclare a statically typed parameter。需要删除的参数应以 set_parameter 创建（动态类型），并配合 allow_undeclared_parameters(true)；查询已删除参数时使用 get_parameter(name, param) 布尔重载判断。

客户端（demo02_param_client.cpp）通过 rcl_interfaces::srv::GetParameters/SetParameters 远程访问 /param_server_node_cpp 的参数服务。

15.4.3 运行效果（实测）

服务端（增 → 查 → 改 → 查 → 删 → 查）：
