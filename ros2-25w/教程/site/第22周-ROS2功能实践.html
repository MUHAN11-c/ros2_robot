第22章 里程计与虚拟传感器实践

第22章 里程计与虚拟传感器实践

进入应用实训篇。本章实现里程计→轨迹（Path）转换，以及激光雷达/点云两个虚拟传感器数据源，为 SLAM 与导航提供数据基础。

本章对应代码：code/ws05_sensor/src/demo/cpp00_odom、py00_odom、cpp01_laser_sim、py01_laser_sim、cpp02_pointcloud_sim、py02_pointcloud_sim。

22.1 里程计与轨迹发布

22.1.1 案例以及案例分析

需求：订阅 /odom（nav_msgs/Odometry），把每个时刻的位姿追加进 /path（nav_msgs/Path）——这是 rviz2 中查看小车行驶轨迹的标准做法。

22.1.2 C++ 实现要点

void odom_callback(const nav_msgs::msg::Odometry::SharedPtr odom){
    // Path 中元素为 PoseStamped，需附带坐标系与时间戳；
    geometry_msgs::msg::PoseStamped ps;
    ps.header.frame_id = "odom";
    ps.header.stamp = odom->header.stamp;
    ps.pose = odom->pose.pose;
    path_.poses.push_back(ps);
    path_.header.stamp = this->now();
    path_pub_->publish(path_);
}

22.1.3 运行效果（实测）

无实车时以虚拟里程计驱动：

ros2 topic pub --rate 10 /odom nav_msgs/msg/Odometry "{header: {frame_id: odom}, ...}"
ros2 run cpp00_odom odom2path
ros2 topic echo /path --once

header:
  frame_id: odom
poses:
- header:
    stamp:
      sec: 0
  pose:
    position:
      x: 1.0
      y: 2.0

Python 版 odom2path_py 效果一致。

22.2 虚拟激光雷达

22.2.1 案例以及案例分析

需求：不依赖真实雷达，按 LaserScan 消息规范合成一圈 360°、±π 扫描数据（含一个 2m 处障碍物扇区），发布到 /scan——常用于 SLAM 算法的离线调试。

22.2.2 运行效果（实测）

ros2 run cpp01_laser_sim laser_sim
ros2 topic echo /scan --once --no-arr

header:
  frame_id: laser
angle_min: -3.1415927410125732
angle_max: 3.1415927410125732
# ranges 共 360 个采样点，其中障碍物方位角约 0.05 rad 处读数≈2.0m

22.3 虚拟点云

22.3.1 案例以及案例分析

需求：合成 16 线点云并发布 /point_cloud（sensor_msgs/PointCloud2）。C++ 使用 PointCloud2Modifier 填充，Python 使用 point_cloud2.create_cloud_xyz32。

22.3.2 运行效果（实测）

ros2 topic echo /point_cloud --once --no-arr

header:
  frame_id: base_link
height: 1
width: 240
fields:
- name: x
- name: y
- name: z

22.4 本章小结

  • 里程计位姿 → Path 的关键是为每个 PoseStamped 填 frame_id 与 stamp；
  • 虚拟传感器数据源让我们在无硬件条件下完成 SLAM/导航算法调试；
  • C++ 的 PointCloud2Modifier 与 Python 的 point_cloud2 工具是构造点云的两个标准姿势。
