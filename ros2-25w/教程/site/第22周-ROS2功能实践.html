22.3 第2课 底盘使用与里程计案例

22.3.1 里程计接口消息（视频：里程计接口消息）

ros2 interface show nav_msgs/msg/Odometry 逐字段：

字段 含义
header.stamp / header.frame_id 时间戳 / 位姿所在坐标系（通常 odom）
child_frame_id 位姿描述的对象（通常 base_link）
pose.pose.position / orientation 位置（m）与姿态四元数
twist.twist.linear / angular 机体坐标系下的线速度与角速度
pose.covariance / twist.covariance 6×6 协方差，融合（EKF）时的权重依据

注意：header.frame_id 是「位姿所在系」（odom），child_frame_id 是「被描述对象」（base_link）。填反会导致 tf 树断链或反向，rviz2 中机器人「倒着走」。

22.3.2 路径相关消息接口（视频：路径相关消息接口）

  • nav_msgs/Path = header + geometry_msgs/PoseStamped[] poses；
  • PoseStamped = header（stamp + frame_id）+ pose（position + orientation）；
  • 整条轨迹的坐标系由 Path.header.frame_id 统一声明，rviz2 的 Path 显示插件按它做 tf 变换。

22.3.3 案例分析（视频：里程计案例以及案例分析）

需求：订阅 /odom，把历史位姿串成轨迹（Path）并发布到 /path，rviz2 中可视化机器人行驶轨迹。

分析：轨迹点不能每个回调都加——按「当前点与轨迹末点距离超过 0.5m 才追加」稀疏化；每个轨迹点是 PoseStamped（带 frame_id 与 stamp）。

22.3.4 C++ 实现八讲（视频 01~08，代码为仓库实测源文件 cpp00_odom/src/odom2path.cpp）

① 框架搭建（01）——订阅 /odom、发布 /path、path_.header.frame_id = "odom"：

#include "rclcpp/rclcpp.hpp"
#include "nav_msgs/msg/odometry.hpp"
#include "nav_msgs/msg/path.hpp"
#include "cmath"

using std::placeholders::_1;

class Odom2Path: public rclcpp::Node{
public:
    Odom2Path():Node("odom2path_node_cpp"){
        RCLCPP_INFO(this->get_logger(),"odom2path 节点创建!");
        // 3-1.订阅里程计消息；
        odom_sub_ = this->create_subscription<nav_msgs::msg::Odometry>("odom",10,
            std::bind(&Odom2Path::odom_callback,this,_1));
        // 3-2.发布轨迹消息；

        // 初始化 path 的坐标系；

② 获取当前点与轨迹末点的距离（02，帧 out/stills/w22_dist_260s_crop.png）：

    void odom_callback(const nav_msgs::msg::Odometry::SharedPtr odom){
        // 1.获取当前坐标点与轨迹中最后一个坐标点的距离数据；
        double x = odom->pose.pose.position.x;
        double y = odom->pose.pose.position.y;
        double last_x = path_.poses.back().pose.position.x;
        double last_y = path_.poses.back().pose.position.y;
        double distance = std::sqrt(std::pow(x - last_x, 2) + std::pow(y - last_y, 2));

③ 距离大于 0.5m 才追加进轨迹（03，帧 out/stills/w22_add_240s_crop.png）：

        // 2.距离大于 0.5 米，才将当前坐标点添加进轨迹（首点直接入轨迹）；
        if (path_.poses.empty() || distance > 0.5) {
            geometry_msgs::msg::PoseStamped ps;
            ps.header.frame_id = "odom";
            ps.header.stamp = odom->header.stamp;
            ps.pose = odom->pose.pose;
            path_.poses.push_back(ps);
            // 3.发布轨迹消息；
            path_.header.stamp = this->now();
            path_pub_->publish(path_);
        }
    }

④ 轨迹发布以及测试（04）：stage 仿真 + rviz2，Fixed Frame=odom、添加 Path 显示（Topic=/path、Style=Lines），绿色轨迹随运动累积。

⑤ BUG 描述以及修复（05，帧 out/stills/w22_bug_220s.png）：BUG 在于轨迹为空时直接取 poses.back() 越界（以及首点永远不入轨迹）——修复为 path_.poses.empty() || distance > 0.5 的判断（仓库代码即修复后版本）。

⑥ rviz2 修改 Path 样式（06）：Path 显示项可调 Style（Lines/Billboards/Boxes）、Color、Line Width/Billboard Size——轨迹密集时用 Billboards 更醒目。

⑦ 移植到实体机器人（07，帧 out/stills/w22_port_170s.png）：把包拷入机器人工作空间 → 确认底盘驱动发布的 /odom 话题名与 frame 一致（Arduino/STM32 底盘驱动均发布标准 /odom）→ colcon build → 机器人上运行节点，PC 端 rviz2（同 DOMAIN_ID）即可看到真实轨迹。

⑧ 小结（08）：消息接口 → 距离过滤 → 轨迹组织 → 可视化 → 移植，是「接口驱动开发」的标准流程。

22.3.5 Python 实现（视频：Python_01/02，仓库 py00_odom/odom2path_py.py）

import math
import rclpy
from geometry_msgs.msg import PoseStamped
from nav_msgs.msg import Odometry, Path
from rclpy.node import Node

class Odom2PathPy(Node):
    def __init__(self):
        super().__init__("odom2path_node_py")
        self.sub = self.create_subscription(Odometry, "odom", self.odom_callback, 10)
        self.pub = self.create_publisher(Path, "path", 10)
        self.path = Path()
        self.path.header.frame_id = "odom"

    def odom_callback(self, odom):
        x = odom.pose.pose.position.x
        y = odom.pose.pose.position.y
        if self.path.poses:
            last_x = self.path.poses[-1].pose.position.x
            last_y = self.path.poses[-1].pose.position.y
            distance = math.sqrt((x - last_x) ** 2 + (y - last_y) ** 2)
        else:
            distance = float("inf")           # 首点直接入轨迹
        if distance > 0.5:
            ps = PoseStamped()
            ps.header.frame_id = "odom"
            ps.header.stamp = odom.header.stamp
            ps.pose = odom.pose.pose
            self.path.poses.append(ps)
            self.path.header.stamp = self.get_clock().now().to_msg()
            self.pub.publish(self.path)

Python 版差异点：poses[-1] 取末点；空轨迹用 float("inf") 让首点必然入轨——与 C++ 的 empty() || 判断等价。

22.4 第3课 激光雷达详解与仿真案例

22.4.1 激光雷达概念与作用（视频：01 概念与作用，411s）

激光雷达（LiDAR，Light Detection and Ranging）通过测量激光束的往返时间/相位得到距离，输出一圈（2D）或多圈（3D）测距点，是 SLAM 与导航最主要的环境感知传感器（帧 out/stills/w22_lidar1_150s.png：测距原理示意）。

22.4.2 特点与分类（视频：02 特点与分类，515s，帧 out/stills/w22_lidar1_320s.png）

  • 按线数：单线（2D 扫描，如 RPLIDAR/思岚）与多线（16/32/64 线，如 Velodyne、禾赛、速腾）；
  • 按测距原理：TOF（飞行时间）与三角测距；
  • 关键指标：测距范围、精度、采样频率（Hz）、角分辨率、点频；
  • 特点：测距精度高、不受光照影响（主动发光）、可夜间工作；成本较高、雨雾尘衰减、玻璃/镜面难测。

22.4.3 单线雷达基本使用与 laserscan 插件（视频：基本使用/插件使用）

  • 真机端：安装驱动（如 rplidar_ros）后发布 /scan；
  • 仿真端：在 URDF/Gazebo 中用 laserscan（ray / gpu_ray）插件生成 sensor_msgs/LaserScan，配置采样数、角范围、噪声等参数——Gazebo 侧参数与消息字段一一对应（见下）。

22.4.4 LaserScan 消息接口（视频：接口上/下，帧 out/stills/w22_scanif_650s.png）

ros2 interface show sensor_msgs/msg/LaserScan 逐字段：

字段 类型 含义
header std_msgs/Header stamp + frame_id（雷达坐标系，如 laser）
angle_min / angle_max float32 扫描起始/终止角（rad），单线雷达通常 ±π
angle_increment float32 相邻测距点角间隔（rad），如 1° = π/180
time_increment float32 相邻两点的时间间隔（s）
scan_time float32 整圈扫描耗时（s），1/scan_time 即帧率
range_min / range_max float32 有效测距范围（m），区间外的读数无效
ranges[] float32[] 第 i 点距离 = angle_min + i*angle_increment 方向的测距值
intensities[] float32[] 反射强度（可选），仿真常置 0 或固定值

注意：ranges[i] 出现 inf（超出量程）或 nan（无效回波）是常态，处理前必须判 std::isfinite(r) 且 range_min <= r <= range_max，否则 SLAM 与避障都会被脏数据带偏。角度语义遵循右手系（x 前、y 左、z 上），角度搞反避障方向就反。

22.4.5 单线仿真案例（视频：分析 + C++×3 + Python，仓库 cpp01_laser_sim/src/laser_sim.cpp 全文）

案例分析：不依赖真实雷达，按 LaserScan 语义合成一圈 ±π、1° 间隔的扫描（正前方 2m 处模拟一个障碍物），发布到 /scan。

C++ 框架 + 基本参数（01）：

class LaserSim: public rclcpp::Node{
public:
    LaserSim():Node("laser_sim_node_cpp"){
        RCLCPP_INFO(this->get_logger(),"单线激光雷达仿真节点创建!");
        // 3-1.组织扫描基本参数；
        scan_.header.frame_id = "laser";
        scan_.angle_min = -M_PI;
        scan_.angle_max = M_PI;
        scan_.angle_increment = M_PI / 180.0; // 1度一个点；
        scan_.time_increment = 0.0;
        scan_.scan_time = 0.1;                // 10Hz
        scan_.range_min = 0.15;
        scan_.range_max = 12.0;
        timer_ = this->create_wall_timer(100ms,std::bind(&LaserSim::on_timer,this));
        pub_ = this->create_publisher<sensor_msgs::msg::LaserScan>("scan",10);
    }

核心逻辑（02）——按角度语义填充 ranges：

    void on_timer(){
        size_t count = (scan_.angle_max - scan_.angle_min) / scan_.angle_increment;
        scan_.ranges.assign(count,INFINITY);        // 默认无回波
        scan_.intensities.assign(count,0.0);
        // 模拟正前方 2m 处的障碍物(角度 0 附近)；
        double distance = 2.0 + 0.2 * std::sin(this->now().seconds());
        for (size_t i = 0; i < count; ++i) {
            double angle = scan_.angle_min + i * scan_.angle_increment;
            if (std::abs(angle) < 0.05) {           // 前方 ±0.05rad 扇区有障碍
                scan_.ranges[i] = distance;
                scan_.intensities[i] = 100.0;
            }
        }
        scan_.header.stamp = this->now();
        pub_->publish(scan_);
    }

结果优化（03）：ranges 全量预分配避免每帧重建；intensities 填充；header.stamp 每帧更新；障碍距离加正弦扰动模拟「活」的场景。Python 版（py01_laser_sim/laser_sim_py.py）逻辑一致，用 [float('inf')]*count 初始化、math.sin 扰动。

22.4.7 PointCloud2 点云接口（视频：点云接口，1230s，帧 out/stills/w22_pcif_700s.png）

sensor_msgs/PointCloud2 用「二进制大数组 + 字段描述」表达 N 个点，逐字段：

字段 类型 含义
header Header stamp + frame_id（如 laser）
height uint32 有序点云的行数（线数）；无序点云为 1
width uint32 每行点数；无序点云即总点数
fields[] PointField[] 字段描述：name（x/y/z/intensity/ring）、offset、datatype（FLOAT32=7 等）、count
is_bigendian bool 字节序
point_step uint32 单点字节数（xyz 三 float = 12；加 intensity = 16）
row_step uint32 单行字节数 = width × point_step
data[] uint8[] 原始字节流，长度 = row_step × height
is_dense bool true 表示无无效点（无 nan/inf）

没有 points[i].x 这样的现成访问器：C++ 用 PointCloud2Iterator（下一节），Python 用 point_cloud2.read_points 或 create_cloud_xyz32。

22.4.8 多线仿真案例 C++ 五讲（视频 01~05，仓库 cpp02_pointcloud_sim/src/pointcloud_sim.cpp 全文）

① 框架搭建（01）：定时器 10Hz + /point_cloud 发布方（同单线版骨架）。

② 组织点云基本参数（02）：

sensor_msgs::msg::PointCloud2 cloud;
cloud.header.frame_id = "laser";
cloud.height = 1;                                // 无序点云
sensor_msgs::PointCloud2Modifier modifier(cloud);
modifier.setPointCloud2FieldsByString(1,"xyz");  // x/y/z 三个 float32 字段
const size_t count = 360;
modifier.resize(count);                          // 分配 360 点空间（同时设 width）

PointCloud2Modifier 会自动填好 fields/point_step/row_step——手工拼需要自己算 offset（x@0、y@4、z@8）与步长。

③ 遍历扫描点（03）——三个迭代器同步前进：

sensor_msgs::PointCloud2Iterator<float> iter_x(cloud,"x");
sensor_msgs::PointCloud2Iterator<float> iter_y(cloud,"y");
sensor_msgs::PointCloud2Iterator<float> iter_z(cloud,"z");

④ 设置扫描点参数（04）——按水平角把一圈点布在半径 R 的圆上：

double radius = 2.0 + 0.2 * std::sin(this->now().seconds());
for (size_t i = 0; i < count; ++i, ++iter_x, ++iter_y, ++iter_z) {
    double theta = i * M_PI / 180.0;
    *iter_x = static_cast<float>(radius * std::cos(theta));
    *iter_y = static_cast<float>(radius * std::sin(theta));
    *iter_z = 0.0f;
}
cloud.header.stamp = this->now();
pub_->publish(cloud);

扩展成「真 16 线」只需：height=16，外层加垂直角 pitch = (ring - 7.5) * 垂直角分辨率，*iter_z = r * sin(pitch)、水平半径乘 cos(pitch)——与真实多线雷达的点云组织方式一致。

⑤ 优化以及小结（05）：预分配 + 迭代器直写零拷贝；stamp 每帧更新；is_dense 按是否含无效点设置。

22.5 重点与难点

  1. Odometry 的坐标系约定：header.frame_id=odom（位姿所在系），child_frame_id=base_link（被描述对象）。填反 tf 树断链。
  2. 轨迹稀疏化：每个回调都塞点几分钟就上万点、拖垮 rviz2——0.5m 距离阈值 + 首点直接入轨是课程的标准答案（22.3.4②③）。
  3. LaserScan 角度语义：ranges[i] 方向 = angle_min + i*angle_increment，右手系；inf/nan 过滤是第一课。
  4. PointCloud2 内存布局：「裸字节数组 + 元信息」，C++ 用 PointCloud2Modifier + PointCloud2Iterator，Python 用 create_cloud_xyz32。
  5. 仿真 → 实机迁移：话题名（/scan vs /rslidar_points）、QoS（传感器数据建议 SensorDataQoS）、frame_id 与 URDF 链杆一致，三类最常见移植故障。

22.8 与 ROS2 / 机器人开发的关联

  1. sensor_msgs 消息族的地基：本章的 LaserScan、PointCloud2 与第23 章的 Image、Imu、NavSatFix 同属 sensor_msgs，字段设计哲学一致（header + 数据体 + 元信息）。吃透一个，其余接口阅读成本减半。
  2. tf2 坐标树的第一块拼图：里程计案例产出的 odom → base_link 动态变换，加上激光雷达的 base_link → laser_link 静态变换，就是 SLAM（map → odom）与导航所需完整 tf 链路的下半段。
  3. nav2 的输入契约：Nav2 的 controller_server 依赖 /odom（或 EKF 融合后的 /odometry/filtered）做速度反馈，costmap 依赖 /scan 或 /points 做障碍层。消息组织不规范，Nav2 直接报「transform timeout」或代价地图全黑。
  4. 仿真 → 实机迁移范式：本章案例「先仿真跑通、再移植实体」的流程，会在第24 章（Ignition Gazebo）与第25 章（导航）反复复用。

22.9 自测与练习

  1. 概念题：nav_msgs/Odometry 的 header.frame_id 与 child_frame_id 分别应该填什么？如果两者都填 base_link，tf2 会有什么表现？
  2. 概念题：LaserScan 中第 i 个测距值的方向角如何计算？ranges[i] = inf 与 nan 分别代表什么？
  3. 动手任务：把本章轨迹节点的阈值从 0.5m 改为 0.2m，在仿真中走同一路线，对比两条 /path 的点数与平滑度；再用 rviz2 的 Measure 工具估算轨迹总长，验证「阈值越小轨迹越贴近真实路径、点数越多」。
  4. 动手任务：写一个节点订阅 /scan，实时发布「前方 30° 扇区内的最小距离」（std_msgs/Float32），在 rviz2 中验证：靠近障碍物时数值单调减小。

参考答案要点：1. header.frame_id 填 odom（位姿所在系），child_frame_id 填 base_link（被描述对象）；都填 base_link 会让 tf 树中 odom→base_link 缺失，rviz2 报 "No transform from [base_link] to [odom]"。2. 方向角 = angle_min + i * angle_increment；inf=超出量程无回波，nan=无效测量。3. 阈值 0.2m 点数约为 0.5m 的 2.5 倍，总长更接近真值（正偏差更小）。4. 对 |angle| <= 15° 且 isfinite(r) 的点取 min；务必过滤 inf/nan。

22.10 常见问题（FAQ）

  • Q：ros2 node list 在 PC 上看不到机器人节点？ A：按顺序排查：① 两端 ROS_DOMAIN_ID 是否一致；② 是否同一局域网/有无 AP 隔离；③ 防火墙是否放行 DDS 端口（7400 起的 UDP 段）；④ 多网卡机器可设 ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET 或配置 FastDDS 单播。
  • Q：rviz2 中 Path 什么都不显示？ A：先查 ros2 topic echo /path --once 是否有数据；再查 rviz2 的 Fixed Frame 是否与 Path.header.frame_id（如 odom）在同一 tf 树；最后查 Path 显示项的 Topic 是否填对。
  • Q：轨迹节点启动即崩溃/首个点不显示？ A：空轨迹时取 poses.back() 越界——课程 BUG 修复（22.3.4⑤）正是此问题，用 poses.empty() || distance > 0.5 判断解决。
  • Q：ranges 里全是 inf？ A：说明该方向无回波（超出量程或吸光），属正常现象；若全部为 inf，查雷达供电、驱动话题名是否匹配、仿真插件的 range_max 是否配置过小。
  • Q：仿真里正常的 /scan 换到实机角度全反？ A：多为雷达安装方向与 URDF 中 laser_link 的 rpy 定义不一致；用 ros2 run tf2_ros tf2_echo base_link laser_link 核对静态变换，必要时在 URDF 中调整安装角。

22.11 本章小结

  • 机器人 = 机械/控制/感知/能源四系统；SSH + 同 DOMAIN_ID 是远程开发的最小闭环；
  • 里程计→轨迹的关键：PoseStamped 带 frame_id 与 stamp、0.5m 距离阈值稀疏化、首点直接入轨（课程 BUG 修复点）；
  • LaserScan 按 angle_min + i*angle_increment 的角度语义合成 ±π 360 线扫描；PointCloud2 用「宽高 + 字段 + 步长 + 字节流」组织，C++ 三件套 Modifier/Iterator 是标准姿势；
  • 虚拟传感器数据源让我们在无硬件条件下完成 SLAM/导航算法调试，接收端落回 NumPy/OpenCV 加工工具箱。
