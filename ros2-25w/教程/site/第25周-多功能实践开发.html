25.2 知识点梳理

25.2.1 地图服务（第1课上半，12 讲）

  • 核心概念：地图服务（Map Service）负责地图的保存、加载与提供；SLAM 建出的 /map 是内存中的 OccupancyGrid，只有落盘成 pgm+yaml 才是可复用的导航资产。

  • 要点 1 · 地图保存节点：nav2_map_server 的 map_saver_cli 把 /map 话题上的 nav_msgs/OccupancyGrid 保存为磁盘文件：

    ros2 run nav2_map_server map_saver_cli -f ~/maps/office --ros-args -p save_map_timeout:=2000
# 产出 office.pgm（图像）+ office.yaml（元数据）

  • 要点 2 · 地图保存基本流程：等 SLAM 稳定（回环闭合、无未探索黑洞）→ 触发保存 → 校验文件完整（pgm 与 yaml 同目录同名、分辨率合理）。保存过早会把「未知区」永久固化进地图。

  • 要点 3 · ROS2 中的地图接口：

    | 消息/服务 | 作用 | |---|---| | nav_msgs/OccupancyGrid | 占据栅格地图：header + MapMetaData info + int8[] data | | nav_msgs/MapMetaData | resolution（m/格）、width/height（格数）、origin（地图原点位姿） | | data[i] | 取值 0（空闲 free）/ 100（占据 occupied）/ -1（未知 unknown） | | nav2_msgs/srv/SaveMap | 保存地图服务（带参数覆盖） | | nav2_msgs/srv/LoadMap | 按文件名加载地图服务 |

  • 要点 4 · 地图存储格式（两讲展开）：*.pgm 是 8 位灰度图（白=空闲、黑=占据、灰=未知）；*.yaml 记录 image、mode: trinary、resolution、origin: [x, y, yaw]、negate、occupied_thresh（默认 0.65）、free_thresh（默认 0.25）。yaml 的 origin 是「地图图像左下角」在 map 坐标系的位姿，挪动它会整体平移地图。本章仓库的 demo_nav2/maps/demo_map.yaml 就是标准样例（见 25.4.3）。

  • 要点 5 · 地图读取节点：map_server（包 nav2_map_server）configure 时按 yaml_filename 读盘，向 /map 以 transient_local QoS 发布 OccupancyGrid，供 AMCL 与全局代价地图消费。
  • 要点 6 · 读取方式 1（终端读取）：ros2 run nav2_map_server map_server --ros-args -p yaml_filename:=...（或 launch 传 map:=），再 ros2 topic echo /map --once --field info 查看分辨率/宽高/原点。
  • 要点 7 · 读取方式 2（程序读取，三讲递进）：① 基本实现——订阅 /map 解析 OccupancyGrid（注意 transient_local QoS）；② 优化——只处理一帧、异常兜底、日志规范化；③ 补充——改用 LoadMap 服务按需加载、统计空闲/占据比例等业务逻辑。示例代码见 25.4.3。
  • 要点 8 · 小结：地图文件是导航系统的持久化资产，应纳入版本管理；pgm/yaml 成对出现，改名要同步改 yaml 的 image 字段。

25.2.2 定位 AMCL（第1课下半，9 讲）

  • 要点 1 · 概述：AMCL（Adaptive Monte Carlo Localization，自适应蒙特卡洛定位）用粒子滤波维护机器人位姿的概率分布：观测模型匹配激光与地图、运动模型采样自里程计，粒子数自适应（KLD 采样）。节点 amcl（包 nav2_amcl）订阅 /scan、/map、/tf（里程计），发布 map → odom 变换、/amcl_pose（PoseWithCovarianceStamped）与 particle_cloud。
  • 要点 2 · 定位节点使用六步（视频 3-8 讲）：① 框架搭建（自建 bringup 包放 launch/yaml）→ ② 加载地图（map_server + map:=...yaml）→ ③ 核心实现（amcl 参数 + 雷达/里程计接线）→ ④ 运行（rviz2 中观察粒子云收敛）→ ⑤ 手动初始化（rviz2 的「2D Pose Estimate」发布 /initialpose，粒子云骤然收缩到真值附近）→ ⑥ 优化（粒子数、update_min_d/update_min_a、激光模型 likelihood_field 参数）。
  • 要点 3 · BUG 与修复（对应「多车定位 03」同类坑）：常见三类——/scan 的 frame_id 与 tf 树不一致（改雷达 frame 或 scan_topic）；map → odom 没人发布（amcl 未 activate）；两套定位同时发布同一变换（互相打架，见编队节）。

  • 要点 4 · 关键参数：

    | 参数 | 含义 | 调参直觉 | |---|---|---| | alpha1..alpha5 | 运动模型噪声 | 里程计越差调越大 | | max_particles / min_particles | 粒子数上下限 | 大地图/多歧义环境增大 | | update_min_d / update_min_a | 位移/转角更新阈值 | 调小提高定位频率、费 CPU | | max_beams | 每帧激光采样光束数 | 越大越稳越慢（本章 demo 取 60） | | laser_model_type | likelihood_field / beam | 默认 likelihood_field，快且稳 | | set_initial_pose + initial_pose | 参数方式给初值 | 仿真固定起点时可免手动初始化 | | recovery_alpha_slow/fast | 全局重定位（绑架恢复） | 机器人被搬动后自动收敛 |

25.2.3 导航服务器（第2课上半，22 讲）

  • 核心概念：导航服务器（Navigation Servers）指 Nav2 中各职责单一的生命周期节点；本课以「逐服务器实操」把第24 章的架构图落地。本章 demo_nav2/launch/bringup_launch.py 实际拉起 6 个服务器 + 1 个生命周期管理器 + rviz2（见 25.4.1）。

  • 服务器 1 · map_server（地图服务）：configure 时读 yaml/pgm → 向 /map 发布 OccupancyGrid（transient_local）。参数要点：yaml_filename（launch 可用 map:= 覆盖）、topic_name、frame_id。失效表现：后续节点等不到地图、全局代价地图空白。

  • 服务器 2 · amcl（定位）：见 25.2.2。本章参数段要点：base_frame_id: base_footprint、global_frame_id: map、scan_topic: scan、set_initial_pose: true + initial_pose 全零、max_beams: 60、粒子 500~2000。

  • 服务器 3 · planner_server（路径规划，3 讲）：插件化全局规划器（NavfnPlanner、SmacPlanner2D、ThetaStar），执行 ComputePathToPose 动作，输入全局代价地图，输出 /plan。本章用 nav2_navfn_planner/NavfnPlanner：use_astar: false（Dijkstra）、tolerance: 0.5、allow_unknown: true、expected_planner_frequency: 1.0。第 3 讲 rviz2 集成：全局代价地图 + /plan 显示 + 「Nav2 Goal」触发整条链；验收标准是路径绕开膨胀层、走廊中走中线。

  • 服务器 4 · controller_server（运动控制器，2 讲）：执行 FollowPath 动作，按 controller_frequency 周期输出 /cmd_vel。本章用 dwb_core::DWBLocalPlanner：min_vel_x: 0.0、max_vel_x: 0.5、min/max_vel_theta: ±1.0、xy_goal_tolerance: 0.15、yaw_goal_tolerance: 0.25，goal_checker 用 SimpleGoalChecker（容差同上）。备选插件：MPPIController、RegulatedPurePursuit。

  • 服务器 5 · behavior_server（恢复服务器，2 讲）：提供 Spin（原地旋转 1.57 rad 清局部盲区）、BackUp（倒车 0.30 m 脱困，速度 0.05 m/s）、Wait（等 5 s）、ClearCostmap（清全局/局部代价地图），由行为树在规划/跟踪失败时调用，cycle_frequency: 10.0。这是机器人「卡住自救」的机制。

  • 服务器 6 · bt_navigator（行为树导航器，2 讲）：按 XML 行为树编排整个导航流程，对外提供 NavigateToPose 动作。节点分四类：Control（PipelineSequence/ReactiveFallback/RoundRobin/RecoveryNode）、Condition（GoalUpdated）、Action（ComputePathToPose、FollowPath、Spin、BackUp、Wait、ClearEntireCostmap）、Decorator（RateController）。参数要点：global_frame: map、robot_base_frame: base_footprint、bt_loop_duration: 10、default_server_timeout: 20、default_bt_xml_filename: navigate_w_replanning.xml。逐节点解析见 25.4.2。

  • 服务器 7 · waypoint_follower（路点跟踪，2 讲）：执行 FollowWaypoints 动作，按序访问多个目标点，可配置路点任务插件（如每个路点拍照）。本章 demo_formation/data/waypoints.csv（id,x,y 三列）就是路点表的雏形，头车可按 CSV 逐点导航。

  • 平滑双件套（4 讲）：smoother_server（SimpleSmoother）优化全局路径曲率，减少急转；velocity_smoother（nav2_velocity_smoother）限制加速度/加加速度（jerk），把控制器输出的「跳变速度」变成底盘可执行的平滑速度——实机上不加它，电机与轮胎都会「受苦」。本章参数文件未包含这两项，属扩展项（课程视频单独演示）。

  • 自主探索 SLAM（2 讲）：把 Nav2 与 SLAM 组合（配合探索插件/explore_lite 类方案），机器人自主前往地图边界「未知区域」完成建图闭环；本质是「SLAM 建图 + 导航到 frontier（前沿）」循环。验收：全程无人工干预、最终地图覆盖率满足设定阈值。

  • 生命周期管理器（1 讲）：lifecycle_manager（nav2_lifecycle_manager）按 node_names 顺序把所有服务器 configure → activate，任何一个失败都会导致导航「起不来」；autostart: true 表示 launch 后自动激活。调试手段：ros2 lifecycle list /planner_server、ros2 lifecycle get /planner_server。参数文件的键必须与节点名精确匹配（本章实测踩坑，见 25.5.1）。

25.2.4 多车编队（第2课下半，20 讲）

  • 要点 1 · 简介与案例分析（2 讲）：编队 = 多车保持期望相对位姿（头车 leader + 从车 follower）；相对位姿用坐标变换表达。案例拆解：头车按全局目标导航，从车以「头车位姿 ∘ 编队偏移」为目标实时跟随。
  • 要点 2 · 仿真环境准备（1 讲）：stage_ros2 双车 world——本章 demo_formation/worlds/formation.world：10m×10m 四面围墙（±5 m，厚 0.2 m），每车差速驱动（drive "diff"，0.35 m 车身）+ 360° 雷达（range 0.15~12.0 m、samples 360），robot1（蓝，pose [0 1 0 0]）为领航、robot2（红，pose [0 -1 0 0]）为跟随，odom_err 注入里程计误差。
  • 要点 3 · 多车定位五步（5 讲）：① 实现思路——每车独立 AMCL，map → robotN/odom 各自隔离；② launch 文件编写——按车命名空间批量起节点；③ BUG 以及修复——两车 tf 不隔离时 odom → base_link 互相覆盖，rviz2 表现为「两车互相抽搐」，解法是 frame_prefix（robot1/odom）或独立 tf；④ 多车定位——两车同时收敛、互不干扰；⑤ 小结。
  • 要点 4 · 多车导航七步（7 讲）：① 框架搭建——复制单车 bringup 为双车；② launch 文件修改——namespace/frame_prefix 参数化；③ 配置文件修改——两套 nav 参数（话题、frame 全部带前缀）；④ 头车导航实现——头车就是普通单车 Nav2，发 NavigateToPose 即可；⑤ 从车配置文件——注意 robot_base_frame、costmap frame 与 tf 前缀一致；⑥ 从车导航实现——从车目标点 = 头车当前位姿经队形偏移变换后的点（或直接跟踪静态 tf 给出的队形位）；⑦ 小结。

25.3 重点与难点

  1. 地图坐标系的 origin 语义：yaml 的 origin: [x, y, yaw] 是「地图图像左下角」在 map 坐标系的位姿。改分辨率或 origin 而不重新配准，AMCL 粒子会整体偏移。
  2. AMCL 的收敛与绑架：初始位姿靠 /initialpose 或 set_initial_pose；机器人被搬动（绑架问题）后靠 recovery_alpha_* 重定位。粒子云长期发散 = 里程计噪声参数与实际不符或地图与环境不一致。
  3. Nav2 生命周期与参数匹配：所有服务器是 lifecycle node，configure（加载参数/插件）→ activate（开始工作）。报「node not active」先查 lifecycle_manager 日志与参数文件里的插件名拼写；参数 yaml 的顶层键必须等于节点名，多套一层嵌套会变成「找命名空间下的同名节点」，参数注入失败直接抛 ParameterUninitializedException（本章实测复现，见 25.5.1）。
  4. 行为树调试：导航失败时先看 bt_navigator 日志中的行为树 tick 路径，确认是规划失败、跟踪失败还是恢复行为循环；view_frames + ros2 topic echo /plan 是两大取证工具。
  5. 多车 tf 隔离：两车不加 frame_prefix 时，两个 odom → base_link 冲突，rviz2 中表现「两车互相抽搐」。每车独立 tf 树或统一带前缀，二选一并保持全局一致。
  6. 编队控制律的边界：follower.py 的「间距误差 + 朝向头车」是跟驰式控制，稳态会正对头车；严格的几何编队（保持方位角）需要把目标点改为「头车位姿 ∘ 固定偏移」再求误差。静态 tf 表达队形偏移适合匀速平缓运动，高速/变队形需动态队形控制。
  7. 语音链路实时性与安全：ASR 延迟（网络/推理）决定交互体验；指令解析用关键词匹配 + 未识别只播报不动作，避免误触发（「停」误识别为「听」）造成安全问题；SDK 凭据只能走环境变量/密钥服务，绝不写进源码。

逐节点语义：

节点 类型 作用
RecoveryNode(6) Control 主循环：失败先执行第二分支（恢复），再重试第一分支，最多 6 次
PipelineSequence Control 顺序 tick 且每轮从头重估——「边走边重规划」的来源
RateController hz=1.0 Decorator 把全局规划限频到 1 Hz，避免每 tick 都算路径
RecoveryNode(1) ComputePathToPose Control 规划失败 1 次就触发第二分支
ComputePathToPose Action 调 planner_server，{goal}/{path} 是黑板变量，planner_id 对应参数里的 GridBased 实例
ClearEntireCostmap Action 清全局/局部代价地图（服务名固定）
FollowPath Action 调 controller_server 跟踪路径，controller_id 对应 FollowPath 实例
ReactiveFallback Control 恢复分支入口：每 tick 先查 GoalUpdated，新目标来了立即放弃恢复去导航
GoalUpdated Condition 黑板 goal 是否被刷新
RoundRobin Control 轮流执行子节点：第一次失败转 Spin，再失败 Wait，再 BackUp，循环
Spin 1.57 Action 原地转 90° 清扫局部盲区
Wait 5 Action 原地等 5 s（等动态障碍离开）
BackUp 0.30/0.05 Action 以 0.05 m/s 倒 0.30 m 脱困

import rclpy
from rclpy.node import Node
from nav_msgs.msg import OccupancyGrid


class MapReader(Node):
    def __init__(self):
        super().__init__('map_reader')
        self.create_subscription(OccupancyGrid, '/map', self.on_map, 1)  # 地图是 transient_local

    def on_map(self, msg: OccupancyGrid):
        total = msg.info.width * msg.info.height
        free = sum(1 for v in msg.data if v == 0)
        occ = sum(1 for v in msg.data if v == 100)
        self.get_logger().info(
            f'{msg.info.width}x{msg.info.height} res={msg.info.resolution} '
            f'free={free/total:.1%} occ={occ/total:.1%} origin=({msg.info.origin.position.x}, '
            f'{msg.info.origin.position.y})')
        self.destroy_subscription(self.subscriptions[0])   # 只看一次


def main():
    rclpy.init()
    rclpy.spin(MapReader())
    rclpy.shutdown()

注意： /map 用 transient_local（latched）QoS 发布，普通订阅者若用默认 QoS 可能收不到地图；rclpy 中把 QoS durability 设为 ReliabilityPolicy.RELIABLE + DurabilityPolicy.TRANSIENT_LOCAL。

25.4.4 NavigateToPose 动作客户端（发导航目标）

# 通过 NavigateToPose 动作让 Nav2 导航到目标点（文件 send_goal.py）
import rclpy
from rclpy.node import Node
from rclpy.action import ActionClient
from geometry_msgs.msg import PoseStamped
from nav2_msgs.action import NavigateToPose


class NavGoal(Node):
    def __init__(self):
        super().__init__('nav_goal')
        self.client = ActionClient(self, NavigateToPose, 'navigate_to_pose')

    def send(self, x, y, yaw_w=1.0):
        self.client.wait_for_server()
        goal = NavigateToPose.Goal()
        goal.pose = PoseStamped()
        goal.pose.header.frame_id = 'map'
        goal.pose.header.stamp = self.get_clock().now().to_msg()
        goal.pose.pose.position.x = x
        goal.pose.pose.position.y = y
        goal.pose.pose.orientation.w = yaw_w
        return self.client.send_goal_async(goal)


def main():
    rclpy.init()
    node = NavGoal()
    node.send(3.0, 1.5)
    rclpy.spin(node)
    rclpy.shutdown()

三个易错点：goal 的 frame_id 必须是 map；时间戳用当前时间（不要用 0，tf 外插会拒绝）；发目标前确认 navigate_to_pose 动作已在 ros2 action list 中（bt_navigator 已 activate）。

        self.declare_parameter("leader_frame", "robot1")
        self.declare_parameter("follower_frame", "robot2")
        self.declare_parameter("formation_offset", 2.0)
        self.leader_frame = self.get_parameter("leader_frame").value
        self.follower_frame = self.get_parameter("follower_frame").value
        self.offset = self.get_parameter("formation_offset").value
        # 2.tf 缓存与监听器；
        self.buffer = tf2_ros.Buffer()
        self.listener = tf2_ros.TransformListener(self.buffer, self)
        # 3.跟随车速度发布方(命名空间下)；
        self.pub = self.create_publisher(Twist, "/robot2/cmd_vel", 10)
        # 4.定时器；
        self.create_timer(0.2, self.on_timer)

    def on_timer(self):
        try:
            ts = self.buffer.lookup_transform(
                self.follower_frame, self.leader_frame, rclpy.time.Time())
            dx = ts.transform.translation.x
            dy = ts.transform.translation.y
            dist = math.sqrt(dx * dx + dy * dy)
            twist = Twist()
            # 与领航车的实际间距 = dist；期望间距 = offset；
            err = dist - self.offset
            if abs(err) > 0.2:
                twist.linear.x = 0.5 * max(min(err, 1.0), -1.0)
                twist.angular.z = 1.0 * math.atan2(dy, dx)
            self.pub.publish(twist)
        except (tf2_ros.LookupException, tf2_ros.ConnectivityException,
                tf2_ros.ExtrapolationException) as e:
            self.get_logger().info("异常提示:%s" % str(e), throttle_duration_sec=2.0)


def main():
    rclpy.init()
    rclpy.spin(Follower())
    rclpy.shutdown()


if __name__ == '__main__':
    main()

控制律逐行讲解：lookup_transform(follower, leader, Time()) 取「头车在跟随车坐标系中的位姿」，Time() 表示用最新可用变换；dist 为两车间距，err = dist - 2.0 是间距误差；abs(err) > 0.2 是 0.2 m 死区（带内不发速度，防抖振）；linear.x = 0.5 * clamp(err, ±1.0) 是比例控制 + 限幅（0.5 是增益，±1.0 限速）；angular.z = atan2(dy, dx) 让车头指向头车。tf 三类异常（尚未有变换/树不通/时间外插）都做节流日志而不是崩溃。参数化设计使同一节点可用于任意 leader/follower 组合。setup.py 入口名 formation_follower。

demo_voice/voice_controller.py 全文（指令映射节点）：

# -*- coding: utf-8 -*-
"""
    需求：智能语音 —— 语音识别(ASR)与 ROS2 集成骨架。
    说明：课程使用讯飞语音 SDK(需要 APPID/AK/SK 密钥，务必通过环境变量注入，
          不要写入源码)；本节点封装"文本指令 → ROS2 控制指令"链路：
          1. ASR 结果以 std_msgs/String 发布到 voice_cmd_text 话题；
          2. 控制指令映射: "前进/后退/左转/右转/停止" → cmd_vel。
"""
import os

import rclpy
from geometry_msgs.msg import Twist
from rclpy.node import Node
from std_msgs.msg import String


class VoiceController(Node):

    # 语音指令 → 速度指令映射；
    COMMANDS = {
        "前进": (0.3, 0.0),
        "后退": (-0.3, 0.0),
        "左转": (0.0, 1.0),
        "右转": (0.0, -1.0),
        "停止": (0.0, 0.0),
    }

    def __init__(self):
        super().__init__("voice_controller_node_py")
        self.get_logger().info("语音控制节点创建!")
        # 讯飞 SDK 密钥只从环境变量读取；
        self.iflytek_appid = os.environ.get("IFLYTEK_APPID", "")
        if not self.iflytek_appid:
            self.get_logger().warn("未设置 IFLYTEK_APPID 环境变量，仅支持文本指令模拟")
        # 控制指令发布方；
        self.pub = self.create_publisher(Twist, "cmd_vel", 10)
        # 指令订阅方(由 ASR 节点/键盘模拟节点发布 String 文本)；
        self.sub = self.create_subscription(String, "voice_cmd_text", self.on_text, 10)

    def on_text(self, msg):
        self.asr_callback(msg.data)

    def asr_callback(self, text):
        """由语音识别结果驱动的控制回调。"""
        self.get_logger().info("收到语音指令:%s" % text)
        twist = Twist()
        for key, (lx, az) in self.COMMANDS.items():
            if key in text:
                twist.linear.x = lx
                twist.angular.z = az
                self.pub.publish(twist)
                self.get_logger().info("执行: linear=%.2f angular=%.2f" % (lx, az))
                return
        self.get_logger().info("未知指令，已忽略")


def main():
    rclpy.init()
    rclpy.spin(VoiceController())
    rclpy.shutdown()


if __name__ == '__main__':
    main()

COMMANDS 表逐条（格式：(linear.x, angular.z)）：前进 (0.3, 0) 线速 0.3 m/s；后退 (-0.3, 0)；左转 (0, 1.0) 逆时针角速 1 rad/s；右转 (0, -1.0)；停止 (0, 0) 全零急停。匹配策略是「关键词子串命中即执行、命中即返回」——ASR 整句（如「请前进」）也能命中；未命中任何关键词只记日志不动作（安全默认）。asr_callback 与 on_text 分离，便于把订阅回调替换成 SDK 内部回调直驱。入口名 voice_controller。

demo_voice/voice_input.py（键盘模拟 ASR，联调用）：

class VoiceInput(Node):

    def __init__(self):
        super().__init__("voice_input_node_py")
        self.get_logger().info("语音指令输入(模拟)创建! 输入: 前进/后退/左转/右转/停止 + 回车")
        self.pub = self.create_publisher(String, "voice_cmd_text", 10)

    def spin_input(self):
        while rclpy.ok():
            try:
                text = input()
            except EOFError:
                break
            msg = String()
            msg.data = text.strip()
            self.pub.publish(msg)


def main():
    rclpy.init()
    node = VoiceInput()
    import threading
    thread = threading.Thread(target=node.spin_input, daemon=True)
    thread.start()
    rclpy.spin(node)
    rclpy.shutdown()

关键点：input() 是阻塞调用，必须放进 daemon 线程，否则会卡死 executor——这正是「SDK 阻塞回调不得进主线程」的最小演示；正式使用时把本节点替换为讯飞 SDK 识别结果发布方即可，voice_controller 不用改一行。

25.6 与 ROS2 / 机器人开发的关联

  1. nav2 全栈收口：本章把第24 章架构图中的每个服务器都实操了一遍——生命周期管理、行为树调度、planner/controller/behavior/waypoint/smoother 协同，就是工业级导航产品的标准骨架。
  2. tf2 坐标树的最终形态：map →(AMCL) odom →(EKF/轮式里程计) base_link →(URDF) 各传感器，多车场景再叠加 frame_prefix。这张树是所有机器人项目的「排障第一图」；编队 follower 本质上就是一个纯 tf 消费者。
  3. 地图与定位的持久化接口：OccupancyGrid、SaveMap/LoadMap、/initialpose 是导航产品的数据契约；换算法（AMCL ↔ 定位版 SLAM ↔ 视觉定位）只要保住这套接口就能替换。
  4. 多机器人系统的 ROS2 模式：命名空间 + tf 前缀 + 参数分套 + 多机 DDS 发现，这套模式可直接迁移到仓储多车、机群巡检等真实项目。
  5. 语音/上层交互的节点化封装：任何第三方 SDK（语音、视觉大模型、云平台）都可以按「订阅输入话题 → 处理 → 发布输出话题/动作」封装成节点，与 Nav2 的 NavigateToPose 动作组合即成完整产品交互链；阻塞式 SDK 调用放独立线程是通用守则。
  6. 仿真 → 实机迁移收尾清单：地图分辨率与真实环境一致、AMCL 运动噪声按实测里程计调、速度平滑参数按底盘动力学调、语音指令加安全限速——这四项决定实机表现。

  1. 概念题：OccupancyGrid.data 中 -1、0、100 分别代表什么？地图 yaml 的 origin 改了会发生什么？
  2. 概念题：行为树 XML 中 RateController hz="1.0"、RoundRobin、GoalUpdated 各自的作用是什么？去掉 RateController 会发生什么？
  3. 动手任务：完成「建图 → 保存 → AMCL 定位 → 导航到目标点」全流程：第24 章的仿真环境中建图保存为 office，重启后加载地图用 AMCL 定位，发 NavigateToPose 目标点（3.0, 1.5）。验收标准：粒子云收敛后导航成功率 ≥ 8/10，view_frames 中 map → odom 由 amcl 发布。
  4. 动手任务：修复 25.5.1 的 lifecycle_manager 崩溃：把 nav2_params.yaml 的键嵌套改为节点名直挂，重新构建后验证 ros2 lifecycle get /map_server 输出 active，且 ros2 action list 出现 navigate_to_pose。
  5. 动手任务：双车编队：两车在同一地图中，通过静态坐标变换令 robot2 跟随 robot1 右后方 1 m 位置。验收标准：robot1 移动时 robot2 稳定保持相对位姿（误差 < 0.3 m），两车 tf 树互不冲突。
  6. 动手任务：语音控制闭环：用录音/文本模拟 ASR 输出「前进」「停止」，机器人 /cmd_vel 响应正确，并由 TTS 播报「已执行」。扩展：给 COMMANDS 表新增「加速」并把「前进」改为长按语义（持续指令超时自动置零）。

参考答案要点：1. -1 未知、0 空闲、100 占据；origin 是地图图像左下角在 map 系的位姿，改动会导致地图整体平移/旋转，AMCL 定位随之整体偏移。2. RateController 把子节点限频到 1 Hz（全局规划每秒至多一次）；RoundRobin 让 Spin/Wait/BackUp 轮流上阵；GoalUpdated 在恢复过程中发现新目标立即返回去导航。去掉 RateController 则每个 tick 都调 planner_server，CPU 占用飙升且路径频繁重算。3. 定位发散优先查 /initialpose 是否给准、里程计与 AMCL 噪声参数是否匹配、激光 frame_id 是否正确。4. 参数 yaml 顶层键=节点名是硬规则；用 /** 通配虽省事但会波及所有节点，推荐显式节点名。5. 编队的关键是 tf 前缀隔离与从车跟踪目标点由「头车位姿 ∘ 队形偏移」实时计算；静态偏移适合匀速平缓运动，高速时需动态队形控制。6. 指令解析用精确关键词匹配 + 未识别指令只播报不动作，避免误触发；持续指令加看门狗定时器，超时发零速。

25.8 常见问题（FAQ）

  • Q：map_saver_cli 保存的图全是灰色/空白？ A：/map 尚无数据或 QoS 不匹配；先 ros2 topic echo /map --once 确认有地图，给订阅端配 TRANSIENT_LOCAL durability，或增大 save_map_timeout。
  • Q：AMCL 粒子云收敛但导航仍失败？ A：定位正常 ≠ 导航可用。依次查：全局 costmap 是否加载静态层（static_layer）、目标点是否落在膨胀区/未知区、controller_server 是否 activate、/cmd_vel 是否被其他节点（如 teleop）抢占。
  • Q：lifecycle_manager 一启动就 ParameterUninitializedException: node_names？ A：参数文件顶层键与节点名不匹配（常见是多层嵌套或拼错节点名）。核对 launch 里 name:= 与 yaml 顶层键一字不差；用 ros2 param list /lifecycle_manager_navigation 验证参数已注入。
  • Q：NavigateToPose 发了没反应？ A：ros2 action list 确认 navigate_to_pose 存在、bt_navigator 已 activate、goal 的 frame_id 是 map 且时间戳有效（用当前时间，不要用 0）。
  • Q：两车在 rviz2 中「抽搐/瞬移」？ A：tf 冲突。给每车配置 frame_prefix（如 robot1/）或在独立机器上分别运行再通过 relay 合并；检查是否有两个节点发布同一变换。
  • Q：编队 launch 直接报 package 'stage_ros2' not found？ A：环境未装 stage_ros2。安装它，或改用 Ignition/Gz 仿真（第24 章 demo_ign_sim + bridge）提供双车 tf；formation_follower 节点本身不依赖 stage。
  • Q：语音识别节点跑起来卡顿？ A：SDK 录音/网络回调阻塞了 executor 线程。把 SDK 放独立线程 + 线程安全队列，或用 MultiThreadedExecutor + callback_group；文本发布频率与指令解析解耦（参考 voice_input.py 的 daemon 线程写法）。
  • Q：讯飞 SDK 示例能跑，接进 ROS2 后报鉴权失败？ A：多数是 APPID 与 SDK 包不配套（SDK 按 APPID 下载绑定），或把密钥写进源码后被改动。坚持 IFLYTEK_APPID 等凭据走环境变量/密钥服务，与 voice_controller.py 的做法保持一致。

25.9 本章小结与课程回顾

  • 地图服务：pgm+yaml 是导航的持久化资产；map_saver_cli 保存、map_server 加载、程序端注意 transient_local QoS 与 origin 语义。
  • AMCL：粒子滤波定位，六步落地（框架→地图→接线→运行→手动初始化→优化）；初值给准、噪声匹配、tf 正确是收敛三要素。
  • Nav2 = 定位 + 规划 + 控制 + 行为树的生命周期化组合：参数集中于一个 yaml（顶层键必须等于节点名），行为树 XML 决定「失败怎么办」的策略；恢复服务器是自助兜底。
  • 编队的本质是「以队友为参考系的速度控制」：多车隔离靠命名空间 + tf 前缀；队形偏移用静态坐标变换表达，跟随控制是「间距误差 P 控制 + 朝向头车」。
  • 语音控制 = ASR 文本 → 指令映射 → Twist：SDK 能力（听写/在线合成/评测/语法识别）封装成节点；凭据只能走环境变量/密钥服务，未识别指令只播报不动作。
