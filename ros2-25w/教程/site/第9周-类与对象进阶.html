9.2 知识点梳理

9.2.1 第1课：构造函数解析与初始化实现

  • 核心概念：构造函数（constructor）在对象创建时自动执行，负责「初始化 + 资源申请」；析构函数（destructor，~类名()）在对象销毁时自动执行，负责「资源释放」。二者构成 RAII（资源获取即初始化）思想的基础。
  • 构造函数和析构函数：构造函数可重载、无返回值、名字与类名相同；析构函数不可重载、无参数。对象在栈上离开作用域、delete 堆对象、或容器销毁元素时自动调用析构。
  • 构造函数分类：默认构造（无参）、有参构造、拷贝构造（T(const T&)）、移动构造（C++11，T(T&&)）。编译器在未手写时会生成默认版本。
  • 构造函数调用方式：括号法 Person p(10);、显示法 Person p = Person(10);、隐式转换法 Person p = 10;（单参构造会被隐式调用，通常用 explicit 禁止）。不要用 Person p();——那是声明了一个返回 Person 的函数（最著名的「最烦解析」问题）。
  • 构造函数调用细节与规则：若用户定义了任何构造函数，编译器不再生成默认构造；拷贝构造在值传递传参、值返回对象、用已有对象初始化新对象时被调用（传参会调拷贝构造，这正是性能热点，故参数常用 const T&）。
  • 浅拷贝的问题与深拷贝：编译器默认拷贝构造是逐成员复制（浅拷贝），对象持有 new 出来的指针时，两个对象指向同一块内存 → 析构时 double free。必须手写拷贝构造/拷贝赋值，为指针成员重新分配并复制内容（深拷贝，三/五法则）。C++11 起优先用 std::unique_ptr/std::vector 让编译器生成的拷贝控制正确。
  • 初始化列表：Class() : a_(1), b_(2) {} 比在构造体内赋值更高效（少一次默认构造+赋值），且必须用于引用成员、const 成员、无默认构造的成员。初始化顺序按成员声明顺序，不是列表书写顺序。
  • 类对象作为类成员（组合）：成员对象先于外层对象构造（按声明顺序），析构相反（先析构外层再析构成员）。rclcpp 节点类内含 publisher/subscription 成员正是这种组合关系。
  • explicit 关键字：禁止构造函数参与隐式转换，避免 Widget w = 42; 这类意外转换。单参构造几乎都应该 explicit。
  • new 和 delete：new 分配并调用构造，delete 调析构并释放；数组用 new[]/delete[] 必须配对。细节坑：delete 空指针安全、重复 delete 崩溃、new 抛 std::bad_alloc、对应 malloc/free 不可混用。现代 C++ 优先智能指针与容器。
class Joint {
public:
    explicit Joint(double rad = 0.0) : rad_(rad) {}
    Joint(const Joint& other) : rad_(other.rad_) {}        // 拷贝构造
    ~Joint() = default;
private:
    double rad_;
};
Joint j1(0.5);
Joint j2 = j1;        // 调用拷贝构造

注意： 手写了析构函数，通常就要考虑手写/删除拷贝构造与拷贝赋值（三/五法则）。持有裸 new 资源又依赖默认拷贝 = 定时炸弹；用 std::unique_ptr 后让编译器替你做正确的事。

9.2.2 第2课：静态成员解析与指针应用

  • 核心概念：静态成员（static member）属于类本身而非某个对象，所有对象共享一份；this 指针指向调用成员函数的当前对象。
  • 静态成员变量：类内声明 static int count_;，类外（或 C++17 inline static）定义初始化；不占对象内存，通过 类名::成员 访问。常用于计数器、全局配置缓存。
  • 静态成员函数：无 this，只能访问静态成员；可用类名直接调用。常作工厂函数/单例入口（如 Node::make_shared、Instance()）。
  • const 静态成员属性：static const int / static constexpr 可在类内初始化（编译期常量）；非 const 静态成员必须类外定义。
  • 单例模式（Singleton）：保证一个类只有一个实例并提供全局访问点。C++11 起局部静态变量线程安全，实现最简：
class RobotConfig {
public:
    static RobotConfig& instance() {
        static RobotConfig inst;     // C++11 起线程安全的静态局部变量
        return inst;
    }
    RobotConfig(const RobotConfig&) = delete;             // 禁止拷贝
    RobotConfig& operator=(const RobotConfig&) = delete;  // 禁止赋值
    double max_speed = 1.5;
private:
    RobotConfig() = default;
};
  • 经典面试题：为什么单例要删掉拷贝构造/赋值？（否则能复制出第二个实例）；单例与全局变量的坏味道（隐藏依赖、难测试），ROS2 更推荐把配置放进节点参数而非全局单例。
  • 对象模型基础：对象内存只含成员变量（不含成员函数，函数在代码区共享）；空类对象占 1 字节（保证地址唯一）。C++ 类布局是理解多态/虚表的前提。
  • this 指针的使用：this 是隐式传给非静态成员函数的指针，可用于区分同名形参与成员、返回对象自身引用（链式编程）、传 this 给需要对象指针的接口。
  • 链式编程：成员函数返回 *this 的引用（T& setA(){...; return *this;}），可连续调用 obj.setX(1).setY(2).setZ(3)。rclcpp 里 rclcpp::NodeOptions().arguments(...).context(...) 就是链式风格。
  • 空指针访问成员函数的问题：T* p = nullptr; p->show(); 若 show 不访问成员变量可能不崩（this == nullptr），一旦访问成员即段错误。防御写法：成员函数开头 if (this == nullptr) return; 或保证对象一定存在。
  • 常函数与常对象：常函数 void show() const; 承诺不修改成员（this 为 const T*）；常对象只能调用常函数、只能访问 const 成员。这是「只读接口」的类型级保证——ROS2 中 const 成员函数是接口设计标配。
  • mutable：mutable 成员在常函数中仍可修改（常用于缓存、互斥锁）。
  • 友元（friend）：让全局函数或另一个类访问本类私有成员。全局函数做友元、类做友元（单向、不可传递、不可继承）。友元破坏封装，应克制使用——只用于「确实需要双向协作」的场景（如运算符重载中 operator<<）。

9.2.3 第3课：运算重载符讲解

  • 核心概念：运算符重载 = 给自定义类型定义运算符行为，本质是调用 operator运算符 函数。规则：不能改变优先级/结合性/操作数个数、不能发明新运算符，部分运算符（::、.、.* 等）不能重载。
  • 加号重载：成员函数版 T operator+(const T& other) const; 或全局函数版 T operator+(const T& a, const T& b);。可实现「对象+对象」「对象+内置类型」的对称重载（全局版更对称）。
  • 运算符重载可实现函数重载：同一 operator+ 可按参数类型提供多个版本。
  • 重载细节：成员版左侧必须是本类对象；全局版需要友元或公有接口；注意返回值是否应为引用（避免悬垂）。
  • 左移运算符重载（<<）：让自定义类型可被 std::cout 输出。必须用全局函数（左操作数是 ostream&），签名 std::ostream& operator<<(std::ostream& os, const T& obj);，内部逐字段输出并返回 os 以支持链式。RCLCPP_INFO 风格日志、消息打印都依赖此模式。
  • 自增运算符重载：前置 T& operator++()（返回引用、先加后用）与后置 T operator++(int)（返回加前副本、带 int 占位区分）。
  • 智能指针初步：operator-> 与 operator* 重载让智能指针（unique_ptr/shared_ptr）像原生指针一样使用；自定义资源句柄类常重载它们实现代理语义。
  • 赋值运算符重载（operator=）：默认浅拷贝；持有资源的类必须实现「自赋值检查 + 释放旧资源 + 深拷贝 + 返回 *this」。这是三/五法则的核心。C++11 起还应考虑移动赋值 operator=(T&&)。
  • 重载关系运算符：operator==/!=/< 等，让对象可比较、可放入 std::set/std::map（容器要求严格弱序）。C++20 可用 operator<=> 一次生成全部比较。
  • 函数调用运算符重载（仿函数）：operator() 让对象像函数一样调用，可携带状态，是 lambda 的底层形态、STL 算法谓词的基础。
  • 重载总结：单目运算符常用成员版、双目对称运算符用全局版、流运算符只能全局版、赋值类必须成员版；返回引用还是值决定能否链式。

9.3 重点与难点

  1. 深浅拷贝与三/五法则：析构、拷贝构造、拷贝赋值（C++11 加移动构造、移动赋值）要么都写要么都禁（= delete），这是 C++ 内存安全的第一原则。
  2. 初始化列表：引用/const/无默认构造成员必须用；执行顺序按成员声明顺序，别依赖书写顺序。
  3. this 与 const 正确性：const 成员函数 + const T& 参数 + 常对象构成「只读接口」体系，编译器帮你挡 bug。
  4. 单例的度：单例解决「唯一实例」但也制造全局状态，机器人代码里优先用依赖注入（传引用/传指针）而不是全局单例。
  5. 运算符重载的取舍：让类型像内置类型一样自然，但滥用（把 + 重载成拼接日志）会毁掉可读性；重载 == 时必须同时考虑 !=（C++20 前）。

// ctor.cpp
#include <iostream>
#include <string>

class Robot {
public:
    explicit Robot(std::string name) : name_(std::move(name)) {
        std::cout << "ctor " << name_ << "\n";
    }
    Robot(const Robot& o) : name_(o.name_) { std::cout << "copy ctor " << name_ << "\n"; }
    ~Robot() { std::cout << "dtor " << name_ << "\n"; }
private:
    std::string name_;
};

void byValue(Robot r) { (void)r; }   // 值传参 → 调用拷贝构造

int main() {
    Robot a("r1");       // 括号法
    Robot b = Robot("r2");   // 显式法
    Robot c = a;         // 拷贝构造
    byValue(a);          // 传参拷贝
}

g++ -std=c++17 -Wall -o ctor ctor.cpp && ./ctor

场景 2：深拷贝解决 double free（对应第1课）

// deep_copy.cpp
#include <cstring>
#include <iostream>

class Buffer {
public:
    explicit Buffer(const char* s) : size_(std::strlen(s) + 1), data_(new char[size_]) {
        std::memcpy(data_, s, size_);
    }
    Buffer(const Buffer& o) : size_(o.size_), data_(new char[size_]) {  // 深拷贝
        std::memcpy(data_, o.data_, size_);
    }
    Buffer& operator=(const Buffer& o) {                                // 深拷贝赋值
        if (this == &o) return *this;          // 自赋值检查
        delete[] data_;
        size_ = o.size_;
        data_ = new char[size_];
        std::memcpy(data_, o.data_, size_);
        return *this;
    }
    ~Buffer() { delete[] data_; }
    const char* c_str() const { return data_; }
private:
    std::size_t size_;
    char* data_;
};

int main() {
    Buffer a("lidar"), b = a, c("camera");
    c = a;
    std::cout << a.c_str() << " " << b.c_str() << " " << c.c_str() << "\n";
}

g++ -std=c++17 -Wall -fsanitize=address -o deep_copy deep_copy.cpp && ./deep_copy
# -fsanitize=address 让内存错误当场暴露

场景 3：静态成员 + 单例 + 链式 this（对应第2课）

// singleton_chain.cpp
#include <iostream>

class JointTarget {
public:
    static int live_count;                       // 静态成员：所有对象共享
    JointTarget() { ++live_count; }
    ~JointTarget() { --live_count; }
    JointTarget& set_rad(double v) { rad_ = v; return *this; }   // 返回 *this → 链式
    JointTarget& set_name(const char* n) { name_ = n; return *this; }
    void show() const {                          // 常函数：不改成员
        std::cout << name_ << " = " << rad_ << "\n";
    }
private:
    double rad_ = 0.0;
    const char* name_ = "joint";
};

int JointTarget::live_count = 0;                 // 类外定义

int main() {
    JointTarget j;
    j.set_rad(1.2).set_name("shoulder").show();  // 链式编程
    std::cout << JointTarget::live_count << "\n";
}

g++ -std=c++17 -Wall -o singleton_chain singleton_chain.cpp && ./singleton_chain

场景 4：友元 + 流运算符 + 仿函数（对应第2、3课）

// overload.cpp
#include <iostream>

class Vec2 {
public:
    Vec2(double x = 0, double y = 0) : x_(x), y_(y) {}
    Vec2 operator+(const Vec2& o) const { return Vec2(x_ + o.x_, y_ + o.y_); }
    bool operator==(const Vec2& o) const { return x_ == o.x_ && y_ == o.y_; }
    double operator()(double scale) const { return scale * (x_ * x_ + y_ * y_); }  // 仿函数
    friend std::ostream& operator<<(std::ostream& os, const Vec2& v);   // 友元：访问私有
private:
    double x_, y_;
};

std::ostream& operator<<(std::ostream& os, const Vec2& v) {
    return os << "(" << v.x_ << ", " << v.y_ << ")";      // 返回 os 支持 << 链式
}

int main() {
    Vec2 a(1, 2), b(3, 4);
    std::cout << a + b << " equal=" << (a == b) << "\n";  // (4, 6) equal=0
    std::cout << a(2.0) << "\n";                          // 仿函数：10
}

g++ -std=c++17 -Wall -o overload overload.cpp && ./overload

场景 5：智能指针与 operator-> / operator*（对应第3课）

// smart_ptr.cpp
#include <iostream>
#include <memory>

struct Sensor {
    void read() const { std::cout << "sensor read\n"; }
};

int main() {
    auto sp = std::make_shared<Sensor>();   // 引用计数智能指针

    std::unique_ptr<Sensor> up(new Sensor); // 独占所有权，禁止拷贝

    // std::unique_ptr<Sensor> up2 = up;    // 编译错误：unique_ptr 不可拷贝
}

端到端实战（实测）：深拷贝 + 单例 + 链式

需求：实现深拷贝的 Buffer 类（杜绝 double free）与 Vec2 类（operator+、operator<<、仿函数 operator()），体会三/五法则与运算符重载。

三大主题合一：深拷贝 Buffer（三法则）、单例 Logger（禁拷贝 + 地址唯一）、ConfigBuilder 链式接口（返回 *this）。

// logger.cpp（节选）
class Buffer {                        // 深拷贝
public:
    explicit Buffer(const char* s) : size_(std::strlen(s) + 1), data_(new char[size_]) {
        std::memcpy(data_, s, size_);
    }
    Buffer(const Buffer& o) : size_(o.size_), data_(new char[size_]) {
        std::memcpy(data_, o.data_, size_);
    }
    Buffer& operator=(const Buffer& o) { /* 自赋值检查+深拷贝 */ ... }
    ~Buffer() { delete[] data_; }
};

class Logger {                        // 单例
public:
    static Logger& instance() { static Logger inst; return inst; }
    Logger(const Logger&) = delete;
    Logger& operator=(const Logger&) = delete;
    void log(const std::string& msg) { std::cout << "[log] " << msg << "\n"; }
private:
    Logger() = default;
};

class ConfigBuilder {                 // 链式
public:
    ConfigBuilder& set_speed(double v) { speed_ = v; return *this; }
    ConfigBuilder& set_mode(const std::string& m) { mode_ = m; return *this; }
};

实测（g++ -std=c++17 -Wall）：

lidar lidar lidar
单例同地址=1
[log] 系统启动
mode=nav speed=2

三份深拷贝互不影响、两处取到的单例地址相同、链式配置生效。

要点解析：

  • Buffer 手写拷贝构造 + 深拷贝赋值（自赋值检查 → 释放旧资源 → 重新分配复制），三份对象各自持有独立内存，-fsanitize=address 下无 double free；
  • Logger::instance() 用 C++11 线程安全的静态局部变量，构造函数私有 + = delete 拷贝/赋值，保证全局唯一；
  • ConfigBuilder 每个设置函数返回 *this 引用，set_mode("nav").set_speed(2) 一行完成配置——与 rclcpp::NodeOptions 同款风格。

9.6 与 ROS2 / 机器人开发的关联

  1. rclcpp 节点即类：class MyNode : public rclcpp::Node 在构造函数里创建 publisher/subscription/timer，析构时自动释放——全部是本周「构造/析构 + 组合」的知识。
  2. 消息缓存里的深浅拷贝：传感器回调若把消息裸指针存进队列，回调结束对象析构即悬垂；正确做法是存 SharedPtr 或按值深拷贝，这正是深拷贝问题的真实版本。
  3. 单例与全局状态：ROS2 参数、TF 缓存、设备句柄若做成全局单例会难以测试；推荐把它们作为节点类成员注入。
  4. << 重载与日志：RCLCPP_INFO_STREAM(node->get_logger(), "pose: " << x) 能拼接自定义类型，前提是你重载了 operator<<。
  5. 仿函数与回调：operator() 对象、std::bind、lambda 都可作为订阅回调；理解仿函数才能理解 rclcpp::AnySubscriptionCallback 的分发机制。
  6. 链式接口：rclcpp::NodeOptions().arguments(...).use_intra_process_comms(true) 的链式风格源自 return *this 模式。

9.7 自测与练习（含参考答案要点）

  1. 概念题：什么情况下必须用初始化列表？成员初始化顺序由什么决定？
  2. 概念题：解释浅拷贝 double free 的完整过程（两对象、一个指针成员、两次析构）。
  3. 动手任务：实现 class LidarFrame：持有 std::vector<float> 点云缓冲，支持拷贝/移动（或显式 = delete 并用 std::unique_ptr），提供 operator<< 打印点数与首尾点。验收：-fsanitize=address 下无内存错误。
  4. 动手任务：实现单例 Logger：禁止拷贝赋值、提供 log(const std::string&)，并在两个独立函数中取到同一实例（地址相同）。

参考答案要点：题 1——引用成员、const 成员、无默认构造的类成员必须用初始化列表；顺序按成员声明顺序。题 2——浅拷贝让两对象共享指针 → 第一个析构 delete 内存 → 第二个析构对已释放内存再次 delete（double free/UB）。题 3——移动构造 Buffer(Buffer&&) noexcept 转移指针并置空源对象；打印用全局 operator<<。题 4——static Logger& instance() + = delete 拷贝/赋值；&instance() 在两处取值相同。

9.8 常见问题（FAQ）

  • Q：构造函数里 throw 会怎样？ A：对象尚未构造完成，已构造的成员会被析构、内存回收；不会泄漏，但调用方需捕获。
  • Q：为什么析构函数常写成 virtual？ A：用基类指针 delete 派生类对象时，非虚析构只调基类析构 → 派生类资源泄漏。第10周详讲虚析构。
  • Q：this 到底是什么？ A：隐式传入非静态成员函数的 T* 指针；常函数中是 const T*；静态成员函数没有 this。
  • Q：delete 与 delete[] 混用会怎样？ A：未定义行为（数组元素析构可能不调用、堆损坏）。new[] 必须配 delete[]；用 std::vector/std::unique_ptr<T[]> 可彻底避免。
  • Q：什么时候重载 operator=，什么时候 = default？ A：成员全是可以安全拷贝的类型（值类型/智能指针）时 = default；类直接持有裸 new 资源时必须手写深拷贝版本，或干脆删除拷贝只允许移动。

9.9 本章小结

  • 三/五法则：析构、拷贝构造、拷贝赋值（加移动）要么都写要么都 = delete——C++ 内存安全第一原则；
  • 初始化列表与成员声明顺序；引用/const 成员必须用列表初始化；
  • 传感器回调若存裸指针，回调结束对象析构即悬垂——存 SharedPtr 或深拷贝是本周问题的真实版本；
  • RCLCPP_INFO_STREAM 拼接自定义类型的前提是重载了 operator<<；
  • 单例要禁拷贝赋值，但机器人代码优先依赖注入而非全局状态；
  • 链式接口（返回 *this）是 NodeOptions 一类配置对象的通用写法。
