## 4.2 知识点梳理

### 4.2.1 第1课 C 语言基础概念与编译工具操作

- **核心概念**：C 是编译型、贴近硬件的中级语言。源码（`.c`）经 gcc 四步——预处理（preprocess）、编译（compile）、汇编（assemble）、链接（link）——变成可执行文件，这一点直接对应 ROS2 中 CMake 调用编译器构建包的过程。
- **c 语言概述和计算机组成部分**：程序 = 指令 + 数据；硬件上分 CPU（运算与控制，内部有寄存器 register）、内存（存数据与指令，掉电丢失）、外存（硬盘，持久化）、输入输出设备。CPU 只与寄存器直接打交道，内存数据需先载入寄存器。
- **c 语言特点**：高效（生成机器码、可精细控制内存）、贴近硬件（指针可直接操作地址，适合驱动）、可移植性好、语法简洁但坑多（无边界检查）。缺点是无 GC、无异常安全，内存要自己管。
- **c 语言关键字简介**：C99 共 32 个关键字，如 `int char float double if else while for return sizeof struct union enum static const void` 等。关键字不能作变量名；本周先混个脸熟，后续课程逐一展开。
- **常见困惑**：编译报错看不懂、`main` 到底写 `int main(void)` 还是 `int main()`、分号与花括号配对、`%d` 与类型不匹配。对策：见错误先读第一行，用最小示例复现。
- **第一个程序**：标准骨架是 `#include <stdio.h>` + `int main(void) { ... return 0; }`。`printf` 来自标准库，`return 0` 表示正常退出。
- **gcc 操作 01 / 02**：`gcc hello.c -o hello` 一步到位；常用参数 `-o` 指定输出名、`-Wall` 打开常用警告、`-g` 生成调试信息、`-std=c11` 指定标准、`-O2` 优化、`-D` 定义宏、`-I` 添加头文件路径。
- **system 函数**：`system("命令")` 让 C 程序调用 shell 命令，定义在 `<stdlib.h>`，返回值是命令退出码。例如 `system("ls -l");`。ROS2 里 `ros2 bag record` 等命令行工具常被脚本化调用，原理相通。
- **gcc 预处理**：`gcc -E hello.c -o hello.i` 只做预处理——展开 `#include`、替换宏、去掉注释、处理条件编译（`#ifdef`）。看 `.i` 文件能理解「头文件只是文本拷贝」。
- **gcc 编译**：`gcc -S hello.i -o hello.s` 把预处理结果翻译成汇编。读懂 `.s` 中 `mov/add/call` 有助理解函数调用与寄存器。
- **汇编和链接**：`gcc -c hello.s -o hello.o` 生成二进制目标文件（符号未完全解析）；再 `gcc hello.o -o hello` 完成链接，把多个 `.o` 与标准库（如 glibc 的 `printf`）合成可执行文件。分静态链接（库代码拷入）与动态链接（运行时加载 `.so`）。
- **查询程序依赖库工具**：`ldd ./hello` 查看动态库依赖（如 `libc.so.6`）；`nm` 可看符号表。调试 ROS2 节点「找不到 so」时第一反应就是 `ldd`。
- **c 语言寄存器 / c 语言汇编**：常见寄存器有通用寄存器、程序计数器 PC、栈指针 SP。gcc `-S` 输出里能看到变量被放进寄存器或栈。这为后面理解「指针 = 地址」和嵌入式驱动里的寄存器映射埋伏笔。
- **vs 常用快捷键**：VS Code 等价对照——`F5` 启动调试、`F10` 单步跳过（step over）、`F11` 单步进入（step into）、`Ctrl+Shift+B` 构建、`Ctrl+/` 注释、`Ctrl+K Ctrl+F` 格式化。本仓库学习路径以 gcc 命令行为准，IDE 只是加速器。

### 4.2.2 第2课 常量、变量与整型数据类型详解

- **核心概念**：常量（constant）在程序运行期间值不变；变量（variable）是内存中命名的可读写存储单元，「先声明（类型 + 名字）后使用」。
- **常量概念 / 常量的语法**：三类写法——① 字面量：`100`、`3.14`、`'A'`、`"hello"`；② 宏常量：`#define PI 3.14`（预处理阶段纯文本替换，无类型、无作用域保护）；③ `const` 常量：`const double pi = 3.14;`（有类型、有作用域，编译器可检查）。
- **const 定义常量**：推荐 `const` 修饰，例如 `const int MAX_SPEED = 30;`。`const` 修饰后不可再赋值；习惯上常量名全大写。注意 `const` 在 C 中是「只读变量」，可用指针绕过，与 C++ 语义略有差别。
- **调试功能**：`gcc -g` 编译后 `gdb ./a.out`，常用 `break main`（下断点）、`run`（运行）、`n`（下一行）、`s`（进入函数）、`p 变量`（打印）、`c`（继续）、`bt`（调用栈）。VS Code 中对应 F9 断点 + F5 调试。
- **变量概念 / 变量命名规则**：命名由字母、数字、下划线组成，不能以数字开头，不能用关键字；区分大小写；见名知意（`wheel_radius` 优于 `wr`）；风格上常用小写下划线（Linux 风格）。
- **声明和定义 / 声明示例**：定义（definition）分配内存，如 `int a = 5;`；声明（declaration）只告知类型，如 `extern int a;`（定义在别处）。一个变量只能定义一次，声明可多次，多文件编程会用到。
- **常量和变量实例**：把「圆的周长计算」里的 `π` 用 `const` 固定、半径用变量，是最典型的组合。
- **数据类型简介**：基本类型分整型（`int` 等）、字符型（`char`）、实型/浮点型（`float/double`）、构造类型（数组、结构体等，后续展开）、指针类型、空类型 `void`。
- **计算机常用单位**：1 byte = 8 bit；1 KB = 1024 B，1 MB = 1024 KB，1 GB = 1024 MB。一个 `char` 恰好 1 字节，可表示 256 种状态。
- **整型概念**：`signed/unsigned` × `short/int/long/long long`。有符号数最高位是符号位（原反补码见第4课），无符号数全表示数值，范围翻倍但不能为负。
- **禁用警告波浪线**：IDE 的红色/绿色波浪线来自 IntelliSense 误报（如安全函数警告）。可用 `-Wall` 但不加 `-Werror`，或在 VS Code 设置中调整 `C_Cpp.errorSquiggles`；不要用「关掉警告」代替「修好代码」。
- **整型占用空间**：64 位 Linux（LP64）下 `char`=1、`short`=2、`int`=4、`long`=8、`long long`=8 字节。用 `sizeof(int)` 在代码里验证，不靠背。
- **输出整型的标准写法**：`int → %d`、`long → %ld`、`long long → %lld`、`unsigned → %u`、`size_t → %zu`。格式与类型不匹配是未定义行为，编译时加 `-Wformat`（含在 `-Wall` 里）可拦截。

### 4.2.3 第3课 字符数据类型相关知识精讲

- **核心概念**：`char` 本质是 1 字节的小整型，ASCII 码把字符映射为数值（`'A'`=65、`'a'`=97、`'0'`=48）。
- **有符号和无符号概念**：`signed char` 范围 -128~127，`unsigned char` 0~255。图像像素、字节流常用 `unsigned char`；判断大小写、存 ASCII 用普通 `char` 即可。
- **无符号占用空间与格式匹配**：`unsigned` 系列仍按 `short/int/long` 占 2/4/8 字节，输出用 `%u / %lu / %llu`。把 `unsigned` 与 `%d` 混用会打印出负数幻觉。
- **了解 size_t**：`size_t` 是 `sizeof` 与许多库函数（`strlen`、`fread`）返回的无符号整型，64 位下等价 `unsigned long`，格式用 `%zu`。它表示「大小/下标」，永远不会为负——用 `int i` 与 `size_t` 比较时要警惕 `-Wall` 的符号比较警告。
- **字符型详解**：`char c = 'A';` 存的是 65；`printf("%c", c)` 打 `A`，`printf("%d", c)` 打 65。字符与整型可互相赋值（隐式转换），`'A' + 1` 得 `'B'`。
- **大小写转换**：小写比对应大写大 32（`'a'-'A'`=32），`c = c - 32` 或 `c = c + 32` 互转；标准库 `tolower/toupper`（`<ctype.h>`）更安全。
- **转义字符**：`\n` 换行、`\t` 制表、`\\` 反斜杠、`\'` 单引号、`\"` 双引号、`\0` 空字符（字符串结束标志）、`\r` 回车、`\x41` 十六进制 ASCII。`"\0"` 是字符串的隐形结尾。
- **浮点数基础语法**：`float`（4 字节，约 6-7 位有效数字）、`double`（8 字节，约 15-16 位）、`long double`。默认小数字面量是 `double`，加 `f` 后缀得 `float`，如 `1.5f`。
- **实型细节**：浮点数存在精度误差（`0.1+0.2 != 0.3`），比较时用 `fabs(a-b) < 1e-6`；输出 `%f` 默认 6 位小数，`%.2f` 控制精度。机器人中的角度、速度、坐标都是浮点数，精度误差在长时间积分中会累积。
- **了解科学计数法**：`1.5e3` = 1500，`2.5e-4` = 0.00025，`e` 前后都可带小数。传感器量程（如 `9.8e-3`）常这样写。

### 4.2.4 第4课 字符串深度剖析与应用

- **核心概念**：C 没有字符串类型，字符串 = 以 `\0` 结尾的字符数组。十进制之外，二/八/十六进制是描述同一数值的不同视角。
- **二进制和转换 / 八进制和转换 / 十六进制和转换**：十进制转二进制用「除 2 取余、逆序排列」；二进制转十进制用「按权展开求和」。每 3 位二进制 = 1 位八进制，每 4 位 = 1 位十六进制（`1111 1111` = 0xFF = 255）。printf 支持 `%o`（八进制）、`%x`（十六进制）、`%#x`（带 `0x` 前缀）。
- **格式化语法**：`printf("格式串", 表达式)` 中 `%d %c %f %s %p` 对应整型/字符/浮点/字符串/指针地址；`%%` 输出百分号本身。
- **原码反码补码**：正数的原码=反码=补码；负数反码 = 原码符号位不变其余取反，补码 = 反码 + 1。计算机用补码做加减法，使 `+0/-0` 表示统一，且多表示一个最小值（如 8 位的 -128）。
- **补码练习 / 数值溢出**：`unsigned char` 255 + 1 回绕到 0；`signed char` 127 + 1 变 -128。溢出不报错但结果错误——机器人里里程计计数器、PWM 占空比常用无符号类型防回绕误判。
- **限定符**：`short long unsigned signed` 修饰整型，`long` 还可修饰 `double`；`const` 表只读，`volatile` 告诉编译器「值可能被硬件/中断改变，别优化掉读取」——驱动开发必备。
- **字符串基本使用**：`char s[16] = "hello";` 实际存 6 个字节（含 `\0`）；`%s` 输出遇 `\0` 停止；`sizeof(s)` 是数组容量，字符串长度要数到 `\0` 为止。
- **printf 格式字符细节 / 附加格式**：`%5d` 右对齐宽 5、`%-5d` 左对齐、`%05d` 补零、`%.3f` 三位小数、`%8.2f` 总宽 8 保留 2 位；`%ld %lu %zu %lld` 匹配长整型。
- **putchar / getchar**：`putchar(c)` 输出单字符，`getchar()` 读一个字符（返回 `int`，遇文件结束返回 EOF）。二者常用于逐字符处理与「清空输入缓冲区」。
- **scanf 基础 / 接收整数 / 字符 / 字符串**：`scanf("%d", &a)` 必须传地址（`&`）；`scanf("%c", &c)` 会读走上次残留的换行或空格，需用 ` getchar()` 或 `" %c"`（前导空格跳过空白）清理；`scanf("%s", buf)` 遇空格即停、且不检查长度，安全做法是 `%127s` 限宽。
- **常见陷阱汇总**：`scanf` 传值不传地址会段错误；字符串漏 `\0`；有符号/无符号混用；格式符与类型不匹配；浮点数直接 `==` 比较。

## 4.3 重点与难点

1. **gcc 四步流程**：预处理→编译→汇编→链接，每步的输入输出（`.c → .i → .s → .o → 可执行`）要能手写命令复现。这是理解 CMake/colcon 构建 ROS2 包的前提。
2. **补码与溢出**：为什么 -1 的补码是全 1、为什么 `255+1=0`。理解它才能解释嵌入式里「计数器回绕」与「有符号/无符号比较」的诡异 bug。
3. **格式化匹配**：`%d/%u/%ld/%zu/%f/%c/%s` 与类型一一对应；`scanf` 传地址、`%c` 残留换行、`%s` 无边界检查，是本周最高频的段错误来源。
4. **字符串即「以 \0 结尾的字符数组」**：`sizeof` ≠ `strlen`，这一概念贯穿第5-7周，务必本周就建立直觉。

> **注意：** `scanf("%d", &a)` 中的 `&` 不能忘；`scanf` 的返回值是成功读取的项数，做健壮输入时应检查返回值，而不是假设用户一定输入了数字。

```c
int main(void)

}
```



**场景 3：sizeof 与整型格式匹配**（对应第2课）

```c
/* types.c —— 各整型占用空间与正确格式符 */
#include <stdio.h>

int main(void)
{
    int a = 42;
    long b = 100000L;
    unsigned int c = 4000000000u;   /* 无符号可存更大正数 */
    size_t n = sizeof(double);      /* sizeof 返回 size_t */

    printf("sizeof(char)=%zu sizeof(int)=%zu sizeof(long)=%zu\n",
           sizeof(char), sizeof(int), sizeof(long));
    printf("a=%d b=%ld c=%u sizeof(double)=%zu\n", a, b, c, n);
    return 0;
}
```

```bash
gcc -Wall types.c -o types && ./types
```

**场景 4：字符大小写转换与转义字符**（对应第3课）

```c
/* case.c —— ASCII 运算实现大小写转换 */
#include <stdio.h>

int main(void)
{
    char c = 'r';
    printf("原字符: %c  ASCII=%d\n", c, c);
    printf("转大写: %c  ASCII=%d\n", c - 32, c - 32);
    printf("转小写: %c\n", (char)(c - 32 + 32));
    printf("转义演示: A\tB\\C \"quoted\"\n");   /* \t 制表 \\ 反斜杠 */
    return 0;
}
```

```bash
gcc -Wall case.c -o case && ./case
```

**场景 5：补码与数值溢出**（对应第4课）

```c
/* overflow.c —— 无符号回绕与补码现象 */
#include <stdio.h>

int main(void)
{
    unsigned char u = 255;
    signed char s = 127;
    u = (unsigned char)(u + 1);     /* 255 + 1 回绕为 0 */
    s = (signed char)(s + 1);       /* 127 + 1 回绕为 -128 */
    printf("unsigned 255+1 = %u\n", u);
    printf("signed   127+1 = %d\n", s);
    return 0;
}
```

```bash
gcc -Wall overflow.c -o overflow && ./overflow
```

**场景 6：scanf 整数/字符/字符串与 getchar 清缓冲**（对应第4课）

```c
/* input.c —— 安全的格式化输入写法 */
#include <stdio.h>

int main(void)
{
    int age = 0;
    char ch = 0;
    char name[32] = {0};

    printf("请输入年龄: ");
    scanf("%d", &age);          /* 整数：必须传地址 &age */
    getchar();                  /* 吃掉行尾残留的 '\n' */

    printf("请输入一个字符: ");
    scanf("%c", &ch);           /* 若无上面的 getchar，会读到换行 */

    printf("请输入名字(无空格): ");
    scanf("%31s", name);        /* %31s 限宽，防溢出 */

    printf("age=%d ch=%c name=%s\n", age, ch, name);
    return 0;
}
```

```bash
gcc -Wall input.c -o input && ./input
```

## 4.5 运行效果（实测）

本章实测案例：验证各整型占用空间与格式符匹配，并观察无符号/有符号数的溢出回绕——这是理解嵌入式里程计计数器翻转的第一课。

```text
sizeof(char)=1 sizeof(int)=4 sizeof(long)=8
a=42 b=100000 c=4000000000 sizeof(double)=8
unsigned 255+1 = 0
signed   127+1 = -128
```

编译命令：`gcc -Wall w4_types.c -o w4 && ./w4`（gcc 13.3.0，Ubuntu 24.04）。

## 4.6 端到端实战（实测）：gcc 四步流水线

从源码到可执行文件完整走一遍四步流程，再运行并检查动态库依赖——这条链就是 `colcon build` 的底层。

源码 `hello.c`：

```c
#include <stdio.h>
#define COURSE "ROS2-25w"

int main(void)
{
    printf("Hello from %s (compiled by gcc 4-step pipeline)\n", COURSE);
    printf("sizeof(int)=%zu sizeof(double)=%zu\n", sizeof(int), sizeof(double));
    return 0;
}
```

构建与运行（gcc 13.3.0 实测）：

```bash
$ gcc -E hello.c -o hello.i     # 1 预处理
$ gcc -S hello.i -o hello.s     # 2 编译
$ gcc -c hello.s -o hello.o     # 3 汇编
$ gcc hello.o -o hello          # 4 链接
$ ./hello
Hello from ROS2-25w (compiled by gcc 4-step pipeline)
sizeof(int)=4 sizeof(double)=8
$ ldd hello
	linux-vdso.so.1 (0x00007ffdca798000)
	libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6 (0x00007044f3c00000)
```

`libc.so.6` 就是 `printf` 的提供者；ROS2 节点报「找不到 librcl.so」时第一反应同样是 `ldd`。

## 4.7 与 ROS2 / 机器人开发的关联

1. **gcc 四步流程 = ROS2 构建链的底层**：`colcon build` 本质是 CMake 调用 gcc/g++ 对每个包做预处理→编译→汇编→链接。看懂 `-I / -L / -l` 与 `ldd`，才能定位 ROS2 包「找不到头文件 / 找不到 librcl.so」类编译链接错误。
2. **固定宽度类型与消息定义**：ROS2 消息（`.msg`）里的 `int8/int32/uint64/float32` 对应 C 的 `<stdint.h>` 定宽类型。机器人跨机通信（x86 与 ARM）时字节宽度、字节序不一致会直接数据错乱，本周的「类型占用空间」是第一道防线。
3. **补码、溢出与嵌入式驱动**：编码器计数、PWM、传感器寄存器读数常是无符号或补码有符号数；理解 8/16/32 位回绕，才能正确处理里程计计数器翻转与 IMU 原始值符号扩展。
4. **printf/scanf ↔ 日志与参数**：`RCLCPP_INFO` 的格式串语法与 `printf` 完全一致（`%d/%f/%s/%zu`）；调试机器人时按格式打印里程计、角度、距离是基本功。
5. **gdb 调试能力可直接迁移**：后面调试 rclcpp 节点的段错误、用 core dump + `bt` 定位崩溃栈，用的都是本周的 `break/run/print/bt`。

## 4.9 常见问题（FAQ）

- **Q：`gcc hello.c` 为什么生成的是 `a.out`？** A：默认输出名是 `a.out`，用 `-o 名字` 指定即可。写 ROS2 时每个可执行目标都应明确命名。
- **Q：`#define PI 3.14` 和 `const double PI = 3.14` 该用哪个？** A：优先 `const`：有类型检查、有作用域、可调试查看。`#define` 适合条件编译开关与字符串化等预处理场景。
- **Q：为什么 `scanf` 后面要写 `&a`？** A：`scanf` 要把读到的值写进变量的内存地址，`&a` 取地址。漏写 `&` 会把值当成地址去写，通常直接段错误。
- **Q：`int` 到底几个字节？** A：与平台相关，64 位 Linux 下 `int` 是 4 字节。不要写死假设，用 `sizeof` 验证；需要精确宽度时用 `<stdint.h>` 的 `int32_t` 等。

## 4.10 本章小结

- gcc 四步 = ROS2 构建链的底层，`-I/-L/-l` 与 `ldd` 是定位「找不到头文件/so」的第一反应；
- `.msg` 里的 `int32/float32` 对应 `<stdint.h>` 定宽类型，跨机通信先对齐字节宽度；
- 补码与回绕是嵌入式计数器 bug 的根源，`unsigned char` 255+1=0、`signed char` 127+1=-128 要能脱口而出；
- `RCLCPP_INFO` 的格式串语法与 `printf` 完全一致；
- gdb 的 `break/run/print/bt` 直接迁移到 rclcpp 节点的段错误调试。
