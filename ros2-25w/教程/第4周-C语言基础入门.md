# 第4章 C 语言基础入门（编译/类型/输入输出）

> 本章对应课程第 4 周：建立「源码 → gcc 四步 → 可执行 → gdb 调试」的完整闭环，打牢常量变量、整型/字符/浮点、进制与补码、printf/scanf 的地基。`colcon build` 底层就是 CMake 调用 gcc 做这四步。

## 4.1 案例以及案例分析

**需求**：验证各整型占用空间与格式符匹配，并观察无符号/有符号数的溢出回绕——这是理解嵌入式里程计计数器翻转的第一课。

## 4.2 知识点与实现

### 4.2.1 gcc 四步流程

```bash
gcc -E hello.c -o hello.i   # 预处理：展开头文件与宏
gcc -S hello.i -o hello.s   # 编译：生成汇编
gcc -c hello.s -o hello.o   # 汇编：生成目标文件
gcc hello.o -o hello        # 链接：合成可执行文件
ldd hello                   # 查询动态库依赖
```

常用参数：`-Wall`（警告）、`-g`（调试信息）、`-std=c11`、`-O2`。gdb 基本功：`break/run/n/s/p/bt`。

### 4.2.2 常量、变量与类型

- 常量优先 `const double PI = 3.14;`（有类型有作用域），`#define` 只做文本替换；
- 64 位 Linux（LP64）：`char`=1、`short`=2、`int`=4、`long`=8 字节，用 `sizeof` 验证；
- 格式符匹配：`%d/%ld/%lld/%u/%zu/%f/%c/%s` 与类型一一对应，错配是未定义行为；
- `char` 是 1 字节小整型（`'A'`=65），小写 = 大写 + 32；
- 补码：负数补码 = 反码 + 1；`unsigned char` 255+1 回绕为 0、`signed char` 127+1 变 -128；
- `scanf("%d", &a)` 必须传地址；`%c` 前的残留换行用 `getchar()` 清理；`%31s` 限宽防溢出。

## 4.4 端到端实战（实测）：gcc 四步流水线

从源码到可执行文件完整走一遍四步流程，再运行并检查动态库依赖——这条链就是 `colcon build` 的底层。

源码 `hello.c`：

```c
#include <stdio.h>
#define COURSE "ROS2-25w"

int main(void)
{
    printf("Hello from %s (compiled by gcc 4-step pipeline)\n", COURSE);
    printf("sizeof(int)=%zu sizeof(double)=%zu\n", sizeof(int), sizeof(double));
    return 0;
}
```

构建与运行（gcc 13.3.0 实测）：

```bash
$ gcc -E hello.c -o hello.i     # 1 预处理
$ gcc -S hello.i -o hello.s     # 2 编译
$ gcc -c hello.s -o hello.o     # 3 汇编
$ gcc hello.o -o hello          # 4 链接
$ ./hello
Hello from ROS2-25w (compiled by gcc 4-step pipeline)
sizeof(int)=4 sizeof(double)=8
$ ldd hello
	linux-vdso.so.1 (0x00007ffdca798000)
	libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6 (0x00007044f3c00000)
```

`libc.so.6` 就是 `printf` 的提供者；ROS2 节点报「找不到 librcl.so」时第一反应同样是 `ldd`。

## 4.5 本章小结

- gcc 四步 = ROS2 构建链的底层，`-I/-L/-l` 与 `ldd` 是定位「找不到头文件/so」的第一反应；
- `.msg` 里的 `int32/float32` 对应 `<stdint.h>` 定宽类型，跨机通信先对齐字节宽度；
- `RCLCPP_INFO` 的格式串语法与 `printf` 完全一致；
- gdb 的 `break/run/print/bt` 直接迁移到 rclcpp 节点的段错误调试。
