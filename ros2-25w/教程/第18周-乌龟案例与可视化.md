## 18.2 知识点梳理

### 18.2.1 第1课 乌龟案例坐标变换实战

**A. 乌龟跟随案例（C++）**

- **案例分析**：turtlesim 中启动后生成第二只乌龟（turtle2），实时广播两龟的坐标变换（`world -> turtle1`、`world -> turtle2`），监听端查询 `turtle2 -> turtle1` 的相对位姿，计算速度指令让 turtle2 追踪 turtle1。涉及：服务调用（`/spawn` 生成乌龟）、话题（`/turtle1/pose` 订阅位姿、`/turtle2/cmd_vel` 发指令）、TF2（广播 + 监听）、launch（组合）。分析时先画"节点-话题-TF 树"图再动手。
- **示例浏览**：课程示例包含 `turtle_spawn`（生成）、`turtle_tf_broadcaster`（广播）、`turtle_tf_listener`（跟随控制）三个节点；先跑通官方 demo `ros2 launch learning_tf2 turtle_following.launch.py` 感受效果。
- **生成乌龟（上/中/下）**：调用 turtlesim 的 `/spawn` 服务（`turtlesim/srv/Spawn`，请求 x/y/theta/name）生成 turtle2；`/kill` 可删除。要点——服务端存在性判断（`wait_for_service`）、名字参数化（用参数指定第二只乌龟名）、生成后才能订阅其 pose 话题。
- **坐标变换广播**：订阅 `/turtle1/pose`（`turtlesim/msg/Pose`，含 x/y/theta），转换成 `geometry_msgs/TransformStamped`（`world` 为父系、`turtle1` 为子系；theta 是绕 z 轴 yaw，四元数 `q.setRPY(0,0,theta)`），用 `TransformBroadcaster` 持续广播（10 Hz 级别）；turtle2 同理。
- **坐标变换监听（上/下）**：监听节点建 Buffer + TransformListener，定时器里查 `lookupTransform("turtle2", "turtle1", TimePointZero)` 得到"turtle1 在 turtle2 系下的位姿"，用角度差算转向、距离算线速度（简单 P 控制：`linear = k1 * distance`、`angular = k2 * atan2(y, x)`），发布 `/turtle2/cmd_vel`。要点：查询失败要 try/catch，初启动时 TF 未就绪属正常。
- **小结以及优化**：优化点——控制频率与 TF 查询频率匹配；限幅（防止线速度过大冲过头）；把 P 增益做成参数（`k1`/`k2` 可 `ros2 param set` 调）；把乌龟名做成参数以支持多实例。

**B. 乌龟跟随案例（Python）**

- **生成乌龟（上/下）**：`self.create_client(Spawn, '/spawn')` + `call_async`；`rclpy.spin_until_future_complete`；注意 Python 客户端在回调里嵌套 spin 的死锁风险，推荐在主流程或独立线程调用。
- **坐标变换广播**：`TransformBroadcaster(self)`，定时器回调里把 pose 转 `TransformStamped`，`quaternion_from_euler(0, 0, pose.theta)` 填四元数；`header.stamp = self.get_clock().now().to_msg()`。
- **坐标变换监听**：`Buffer()` + `TransformListener`；`lookup_transform('turtle2', 'turtle1', Time())`；从 `transform.transform.translation.x/y` 算距离、`atan2(y, x)` 算航向差；`Twist` 发速度指令。常见问题：两龟名字参数化、TF 未就绪的异常处理。

**C. 乌龟护航（多实例 + launch 组织）**

- **案例分析**：多只乌龟围绕/护送领头乌龟——本质是**多实例的广播/监听**：每只乌龟一个命名空间、一份参数（相对领队的编队偏移），用 launch 统一编排。这是多机器人编队的最小原型。
- **护航 launch（Python，上/中/下）**：用 `GroupAction` + `PushRosNamespace` + `For 循环/列表推导` 生成 N 个 follower 节点，每个节点传参数 `leader`、`offset_x`、`offset_y`、`turtle_name`；用 `DeclareLaunchArgument` 暴露"乌龟数量、领队名"；用 `RegisterEventHandler(OnProcessExit)` 保证生成节点退出后启动控制节点；`TimerAction` 延时错峰启动避免 `/spawn` 并发冲突。
- **护航 launch（XML 实现）**：`<group>` + `<push-namespace>` + 多个 `<node>`，参数用 `<param name="leader" value="turtle1"/>`；XML 版更短但无法循环生成，多实例要手写重复段。
- **本章小结**：案例串起了"服务（生成）→ 话题（pose/cmd_vel）→ TF（广播/监听）→ launch（编排）→ 参数（增益/偏移）"全部机制，是本阶段的收官之作。

### 18.2.2 第2课 可视化简介、rviz2 集成 URDF

- **可视化简介——场景、概念与作用**：机器人开发中需要"看见"传感器点云、TF 树、机器人模型、规划路径。rviz2 是 ROS2 官方 3D 可视化工具：以一个 **Fixed Frame** 为基准，把话题数据（点云、图像、标记、TF、机器人模型）渲染到同一 3D 场景。作用：调试感知、验证 TF、展示机器人状态、做 HMI 演示。
- **rviz2 基本使用——安装、启动与界面布局**：`sudo apt install ros-humble-rviz2`（desktop 版自带）；`ros2 run rviz2 rviz2`；界面布局——中央 3D 视图、左侧 Displays（显示项列表）、右侧 Views（视角）、下方 Time（回放控制）；鼠标左键旋转、中键平移、滚轮缩放；Add 可添加显示项。
- **rviz2 基本使用——插件与配置文件**：Displays 常用插件——Grid（地面）、RobotModel（机器人模型，读 `/robot_description` 话题）、TF（坐标系）、PointCloud2/LaserScan（传感器）、Image、Marker/MarkerArray、Path、Map；配置可保存为 `.rviz` 文件（YAML 格式），launch 中 `Node(package='rviz2', executable='rviz2', arguments=['-d', cfg])` 自动加载，团队共享配置文件是工程惯例。
- **rviz2 集成 URDF——基本流程与案例分析**：目标"在 rviz2 显示自己的机器人模型"。流程：写 URDF/xacro → 用 `robot_state_publisher`（发布 `/robot_description` 与 TF）+ `joint_state_publisher(_gui)`（发布关节角）→ launch 一起启动 → rviz2 加 RobotModel 显示。案例：两轮差速小车（车体 + 两轮 + 万向轮）。
- **rviz2 集成 URDF——实现（框架搭建 / urdf 文件 / xacro 工具）**：建功能包 `mycar_description`，含 `urdf/`（模型）、`launch/`（display.launch）、`rviz2/`（配置）；urdf 文件先写纯 URDF 再引 xacro；xacro 工具 `xacro model.xacro > model.urdf` 用于验证与兼容老工具；`robot_state_publisher` 参数 `robot_description` 读 xacro 处理后的内容。
- **rviz2 集成 URDF——launch 核心实现**：核心三行——`robot_state_publisher`（参数 `robot_description: Command(['xacro ', xacro_file])`）、`joint_state_publisher_gui`、`rviz2`（`-d` 加载配置）。参数化模型路径、Fixed Frame（一般 `base_footprint` 或 `base_link`）。
- **rviz2 集成 URDF——launch 优化（说明 + 实现）**：优化点——用 `get_package_share_directory` 拼路径而非硬编码；`Command(['xacro ', LaunchConfiguration('model')])` 支持命令行换模型；用 `DeclareLaunchArgument('use_gui', ...)` + `IfCondition` 选择 `joint_state_publisher` 或 `joint_state_publisher_gui`；把 rviz 配置放 `rviz2/urdf.rviz` 并 install；launch 中统一 `use_sim_time`。
- **小结**：URDF 描述"长什么样"，robot_state_publisher 把模型与 TF 广播出去，rviz2 负责显示——三者分工清晰。

### 18.2.3 第3课 URDF 使用语法详解与实现

- **URDF 语法——robot**：URDF（Unified Robot Description Format）是 XML 格式机器人描述；根元素 `<robot name="mycar">`，内部只有 `<link>` 与 `<joint>` 两类主体元素（外加 `<material>` 等辅助）。规则：link 与 joint 名在机器人内唯一；树状结构、一个根 link。
- **URDF 语法——link（简介 + 使用 + 补充）**：`<link name="...">` 下三类属性——`<visual>`（外观：`<geometry>` 盒/圆柱/球/网格 + `<origin>` 位姿 + `<material>` 颜色）、`<collision>`（碰撞体，结构同 visual，常简化几何）、`<inertial>`（惯性：`<mass>` + `<inertia>` 6 元素 + `<origin>`）。补充要点：`<geometry><box size="0.5 0.3 0.2"/>`、`<cylinder radius length>`、`<sphere radius>`、`<mesh filename="package://pkg/meshes/x.stl" scale="..."/>`；颜色用 `<material name="blue"><color rgba="0 0 0.8 1"/></material>`；惯性矩阵可不精确但不能缺失（Gazebo 必需）。
- **URDF 语法——joint（简介 + 练习）**：`<joint name="..." type="fixed|revolute|continuous|prismatic|floating|planar">`，内含 `<parent link="..."/>`、`<child link="..."/>`、`<origin xyz rpy/>`（子系相对父系的位姿）、`<axis xyz/>`（转动/移动轴）、`<limit lower upper effort velocity/>`（revolute/prismatic 必需）、`<dynamics damping friction/>`。练习：给小车装"轮子"关节（continuous）。
- **URDF 语法——joint_state_publisher 作用**：`joint_state_publisher` 发布所有非 fixed 关节的当前角度到 `/joint_states`，`robot_state_publisher` 据此算出各 link 的 TF 并广播。没有它，rviz2 中轮子不会动、TF 树缺分支。带 GUI 版 `joint_state_publisher_gui` 可拖滑块调关节角，方便调试。
- **URDF 语法——base_footprint**：惯例在 `base_link` 下再加一个 `base_footprint`（贴地投影）作为根：`base_footprint --fixed--> base_link`。作用：让机器人"接触地面"的点成为 TF 树根，导航/SLAM 约定（map→odom→base_footprint→base_link→传感器）更规范。
- **URDF 练习（车体 / 车轮上 / 车轮下）**：完整小车——`base_footprint` → `base_link`（盒体 0.5×0.3×0.2）→ 左右轮（圆柱 r=0.05，continuous 关节，轴 y 方向）→ 万向轮（球体，fixed）→ 天线/支架。车轮练习重点：圆柱默认轴向是 z，要旋转 `rpy="-1.57 0 0"` 让轴沿 y；左右轮 `origin` 对称（y=±0.15）。
- **URDF 工具**：`check_urdf model.urdf`（语法与树结构校验）、`urdf_to_graphiz model.urdf`（生成结构图）、`joint_state_publisher_gui`（交互调关节）、`ros2 run robot_state_publisher robot_state_publisher`（单独起）、`xacro` 命令（预处理）；rviz2 的 TF/RobotModel 插件也常当"可视化校验器"用。

### 18.2.4 第4课 URDF 优化 xacro 实现

- **xacro 场景、概念与作用**：纯 URDF 写复杂机器人（多轮、多传感器）时大量重复、无法参数化。xacro（XML macro）是 URDF 的**宏预处理器**：支持变量、宏（macro）、数学表达式、文件包含，编译后仍是标准 URDF。作用：减少重复、支持"同一款车不同配置"、按部件模块化组织模型。
- **xacro 快速体验**：文件头 `<robot xmlns:xacro="http://www.ros.org/wiki/xacro" name="mycar">`；`xacro model.xacro -o model.urdf` 生成 URDF；`check_urdf` 校验。launch 中可直接用 `Command(['xacro ', path])` 动态展开，无需手动生成。
- **xacro 语法——变量**：`<xacro:property name="wheel_radius" value="0.05"/>`，引用 `${wheel_radius}`；支持数学运算 `${wheel_radius * 2}`；命令行传参用 `<xacro:arg name="prefix" default=""/>` + `$(arg prefix)`，实现"多机器人同模型不同前缀"。
- **xacro 语法——宏**：`<xacro:macro name="wheel" params="name reflect"> ... </xacro:macro>`，调用 `<xacro:wheel name="left_wheel" reflect="1"/>`；宏可嵌套、可带默认参数（`params="reflect:=1"`）；惯用技巧——用宏生成"一个轮子"（含 link + joint），左右轮各调一次。
- **xacro 语法——文件包含**：`<xacro:include filename="$(find mycar_description)/urdf/wheel.xacro"/>`，把轮子、雷达、摄像头拆成独立 xacro 文件，主文件按需组合——这是 MoveIt2/Nav2 生态的标准组织方式。
- **xacro 练习（框架搭建 / 车体上 / 车体下 / 添加摄像头 / 添加雷达）**：完整流程——先拆 `base.xacro`（车体）、`wheel.xacro`（宏）、`camera.xacro`、`laser.xacro`，主文件 `mycar.xacro` include 并实例化；摄像头/雷达用 `xacro:macro` + `xacro:arg` 控制是否安装（`if` 条件：`<xacro:if value="$(arg with_camera)">`）；雷达 link 通过 fixed joint 挂在 `base_link` 上方 0.3m。
- **本章小结**：URDF 定义"几何与关节"，xacro 让它可维护、可配置；配合 robot_state_publisher 与 rviz2 形成机器人描述的标准三件套。

## 18.3 重点与难点

1. **TF 树设计**：乌龟案例的 `world → turtle1/turtle2` 与真车的 `map → odom → base_footprint → base_link → laser` 同构；理解"广播谁、监听谁、查询哪两个系"是案例核心。
2. **多实例命名空间**：乌龟护航要求每只乌龟独立命名空间 + 参数化，否则话题互相踩踏；`PushRosNamespace` + 相对话题是标准解。
3. **URDF 的 visual/collision/inertial 分工**：rviz2 只看 visual；Gazebo 仿真看 collision + inertial；缺 inertial 仿真会飞。
4. **关节轴与圆柱默认方向**：圆柱默认沿 z 轴，轮子需旋转关节 origin；`continuous` 关节无 limit 但需 `axis`。
5. **xacro 宏参数化思维**：把"重复结构"抽象成宏、把"可变量"上提为 property/arg，是机器人模型工程化的第一步。

### 18.4.2 实战 2：乌龟跟随——广播 + 监听 + 控制（Python）

```python
# turtle_follow/turtle_follow/follower.py
import math
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import TransformStamped, Twist
from tf2_ros import Buffer, TransformListener, TransformBroadcaster
from tf_transformations import quaternion_from_euler
from turtlesim.msg import Pose


class TurtleFollower(Node):
    def __init__(self):
        super().__init__('turtle_follower')
        self.declare_parameter('leader', 'turtle1')
        self.declare_parameter('follower', 'turtle2')
        self.declare_parameter('k_linear', 1.0)
        self.declare_parameter('k_angular', 4.0)
        self.buf = Buffer()
        self.listener = TransformListener(self.buf, self)
        self.br = TransformBroadcaster(self)
        self.pub = self.create_publisher(Twist, 'turtle2/cmd_vel', 10)
        self.create_subscription(Pose, 'turtle1/pose', self.on_pose, 10)
        self.create_timer(0.1, self.on_timer)          # 10 Hz 广播 + 控制

    def on_pose(self, msg: Pose):
        t = TransformStamped()
        t.header.stamp = self.get_clock().now().to_msg()
        t.header.frame_id = 'world'
        t.child_frame_id = self.get_parameter('leader').value
        t.transform.translation.x = msg.x
        t.transform.translation.y = msg.y
        q = quaternion_from_euler(0, 0, msg.theta)     # yaw → 四元数
        t.transform.rotation.z, t.transform.rotation.w = q[2], q[3]
        self.br.sendTransform(t)                       # 持续广播

    def on_timer(self):
        try:                                           # TF 未就绪时抛异常，必须捕获
            tf = self.buf.lookup_transform('turtle2', 'turtle1', rclpy.time.Time())
        except Exception as e:
            self.get_logger().warn(f'tf not ready: {e}')
            return
        x = tf.transform.translation.x
        y = tf.transform.translation.y
        dist = math.hypot(x, y)                        # 距离 → 线速度
        angle = math.atan2(y, x)                       # 航向差 → 角速度
        cmd = Twist()
        cmd.linear.x = self.get_parameter('k_linear').value * dist
        cmd.angular.z = self.get_parameter('k_angular').value * angle
        self.pub.publish(cmd)                          # 简单 P 控制跟踪
```

```python
                                  'offset_x': -1.0 * i, 'offset_y': 0.5 * i}]),
            ])]))
    return ld
```

### 18.5.4 坐标点变换监听实测（含 Python 兼容提示）

**需求**：订阅 `turtle1` 坐标系下的坐标点，利用 tf 缓存把它变换到 `world` 坐标系输出——「坐标系变换」之外的第二种监听形态。

C++ 实现（`cpp04_tf_listener/src/demo02_point_listener.cpp`）核心见 18.4.1；Python 实现（`py03_tf_broadcaster/demo02_point_listener_py.py`）：

```python
self.buffer = Buffer()
self.listener = TransformListener(self.buffer, self)   # Jazzy 需传入节点对象
out = self.buffer.transform(point, "world", timeout=rclpy.duration.Duration(seconds=1.0))
```

> 兼容提示（Python 两处易错点）：① `TransformListener(buffer)` 单参数写法在 Jazzy 下订阅不生效，必须传节点对象；② 必须显式 `import tf2_geometry_msgs`，否则 `buffer.transform()` 报 `Type ... is not loaded or supported`（转换器靠该模块注册）。

端到端实测（静态广播 world→turtle1 平移 (1,2,0)，注入 turtle1 系下的点）：

```bash
ros2 run tf2_ros static_transform_publisher --x 1 --y 2 --z 0 --frame-id world --child-frame-id turtle1
ros2 run cpp04_tf_listener demo02_point_listener
ros2 topic pub --once /turtle1/point geometry_msgs/msg/PointStamped "{header: {frame_id: turtle1}, point: {x: 0.5, y: 0.5, z: 0}}"
```

```text
[INFO] [...]: [point_listener_node_cpp]: 坐标点(0.50,0.50) 变换到 world 系下: (1.50,2.50)
[INFO] [...]: [point_listener_node_cpp]: 坐标点(1.00,1.00) 变换到 world 系下: (2.00,3.00)
```

### 18.5.5 乌龟跟随与护航实测

**需求**：生成两只乌龟，乌龟 t2 始终跟随 turtle1（保持距离 2m）。

实现分三部分：

1. **广播器**（exer02）：订阅 `/<turtle>/pose`，发布 `world → <turtle>`（乌龟名由参数 `turtle` 指定）；
2. **监听器**（exer03）：参数 `father_frame`/`child_frame`，计算两龟位移与朝向差，按比例发布 `/<father>/cmd_vel`：
   `linear.x = 0.5 * sqrt(dx²+dy²)`、`angular.z = 1.0 * atan2(dy,dx) - father_theta`；
3. **launch**（follow_launch.py）：一次生成乌龟 t2、两个广播器（turtle 参数 t1/turtle1、t2）、一个监听器。

实测 `ros2 launch cpp05_exercise follow_launch.py` 可见 t2 生成且全程跟随第一只乌龟（键盘控制 turtle1 时 t2 自动跟随，视频效果一致）。

**乌龟护航**（escort_launch.xml）：监听器在两龟之间再加一层目标点偏移（保持固定方位跟随），XML 版 launch 组织节点。

## 18.6 与 ROS2 / 机器人开发的关联

1. **TF 是导航/SLAM 的骨架**：`map → odom → base_link → laser` 就是乌龟案例 `world → turtle1/turtle2` 的工业版；第24章建图导航、机械臂抓取都以此为基础。
2. **URDF/xacro 是机器人产品的"数字名片"**：MoveIt2 Setup Assistant、Gazebo 仿真、Nav2 的 footprint 全部吃 URDF/xacro；建模规范（base_footprint、命名、宏拆分）直接影响后续自动化工具链。
3. **rviz2 是调试与交付界面**：感知算法调试看 PointCloud2/Image，导航看 Path/Map，交付演示也用它；`.rviz` 配置文件应随包入库。
4. **乌龟案例 = Mycar 的缩影**：第19-20章的智能车 bringup 就是"生成/启动 + 多节点 + TF + 参数 + launch"的放大版，本章案例可直接迁移。

> 参考答案要点：1) joint_state_publisher 发布 `/joint_states`（非 fixed 关节角）→ robot_state_publisher 结合 URDF 算各 link TF 并发布 `/robot_description` → rviz2 的 RobotModel/TF 插件渲染；base_footprint 是地面投影点，导航栈约定 map→odom→base_footprint，使"机器人触地点"有明确语义。2) 订阅 `/turtle1/pose` 广播 TF，监听 `turtle2→turtle1`，P 控制发 `/turtle2/cmd_vel`；注意 TF 未就绪异常处理与速度限幅。3) 宏参数 `name/reflect`；`<xacro:if value="$(arg with_camera)">` 条件包含；launch 用 `ParameterValue(Command(['xacro ', path]), value_type=str)`。

## 18.8 常见问题（FAQ）

- **Q：rviz2 中 RobotModel 不显示/报 No transform？** A：检查 Fixed Frame 是否是 TF 树中存在的 frame（如 `base_footprint`）；robot_state_publisher 是否在跑、`/robot_description` 有无数据（`ros2 topic echo /robot_description --once`）；模型 joint/link 是否有孤立分支。
- **Q：`xacro:include` 报找不到文件？** A：用 `$(find <pkg>)/urdf/x.xacro` 而非相对/绝对路径；确认该包已编译安装、`share` 目录含 urdf（install 规则没写全）。
- **Q：轮子显示成"躺倒"的圆柱？** A：圆柱默认轴向为 z，需在 `<visual>` 的 `<origin rpy="-1.5708 0 0"/>` 旋转；关节 `<axis>` 决定转动轴，两者要一致。
- **Q：joint_state_publisher_gui 打不开/没窗口？** A：确认装了 `ros-humble-joint-state-publisher-gui`；WSL/远程桌面注意 DISPLAY 环境变量；无 GUI 环境改用 `joint_state_publisher` 并自行发布 `/joint_states`。
- **Q：乌龟护航启动报 `/spawn` 服务调用失败？** A：多只乌龟同时 spawn 会竞争；用 `TimerAction` 错峰启动；确认 `turtlesim_node` 已起来、`wait_for_service` 后再调用。

## 18.9 本章小结

- 静态/动态广播分别使用 `StaticTransformBroadcaster` 与 `TransformBroadcaster`；静态走 `/tf_static`（transient_local，发一次），动态走 `/tf`（持续发布、约 60Hz 实测更新）；
- 监听端 `Buffer + TransformListener + lookupTransform`，时间参数传 `tf2::TimePointZero`；坐标点变换实测 `(0.5,0.5)→(1.5,2.5)`、`(1,1)→(2,3)` 端到端验证通过（含 Python 两处兼容提示）；
- 跟随/护航实操 = 广播器 × 2 + 监听器（速度公式线性化：`linear.x = 0.5*sqrt(dx²+dy²)`、`angular.z = 1.0*atan2(dy,dx) - father_theta`）+ launch 集成，实测与课程视频效果一致；
- URDF 描述结构（robot/link/joint、visual/collision/inertial、base_footprint），Xacro 消除重复（property/macro/include/if）；`xacro` 命令可离线展开验证；
- rviz2 集成三件套 = robot_state_publisher + joint_state_publisher(_gui) + rviz2，一条 launch 命令即可显示机器人模型（三进程实测通过）。
