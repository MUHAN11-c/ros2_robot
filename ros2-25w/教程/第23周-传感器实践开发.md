# 第23章 传感器仿真开发（相机/IMU/GNSS）

> 完成图像、惯导、卫星定位三类数据的仿真发布与订阅解析。
>
> 本章对应代码：`code/ws05_sensor/src/demo/cpp03_camera_sim`、`py03_camera_sim`、`cpp04_imu_demo`、`py04_imu_demo`、`cpp05_gnss_demo`、`py05_gnss_demo`。

## 23.1 虚拟相机

**需求**：合成 320×240 灰度条纹图像（mono8）发布到 `/image_raw`（sensor_msgs/Image），验证图像链路（后续可接 rqt_image_view）。

实测 `ros2 topic echo /image_raw --once --no-arr`：

```text
header:
  frame_id: camera
height: 240
width: 320
encoding: mono8
```

## 23.2 IMU 数据

**需求**：订阅 `/imu`（sensor_msgs/Imu），解析并打印姿态四元数、角速度、线加速度——IMU 是融合定位与姿态估计的基础数据源。

实测（以虚拟数据源驱动订阅方）：

```bash
ros2 topic pub --rate 10 /imu sensor_msgs/msg/Imu "{orientation: {w: 1.0}, angular_velocity: {z: 0.1}, linear_acceleration: {x: 0.2}}"
ros2 run cpp04_imu_demo imu_demo
```

```text
[INFO] [...]: ---------IMU 数据---------
[INFO] [...]: 姿态四元数:(1.00,0.00,0.00,0.00)
[INFO] [...]: 角速度:(0.00,0.00,0.10) rad/s
[INFO] [...]: 线加速度:(0.20,0.00,0.00) m/s^2
```

打印值与发布值逐项一致，解析无误。

## 23.3 GNSS 数据

**需求**：订阅 `/fix`（sensor_msgs/NavSatFix），将经纬度转换为平面坐标并发布轨迹到 `/gnss_path`：

- 以**首个有效定位**为原点；
- 经纬度差换算按 `1° ≈ 111319.49 m`（赤道处）近似，纬度方向乘 1、经度方向乘 cos(纬度)。

实测：

```bash
ros2 topic pub --rate 2 /fix sensor_msgs/msg/NavSatFix "{status: {status: 0}, latitude: 31.1, longitude: 121.3, altitude: 10.0}"
ros2 run cpp05_gnss_demo gnss_demo
```

```text
[INFO] [...]: 定位原点:(31.100000,121.300000)
```

之后每个 `/fix` 都被转换成相对原点的平面坐标追加进 `/gnss_path`，rviz2 中即可看到卫星轨迹。

## 23.4 本章小结

- 相机/IMU/GNSS 的消息规范（Image/Imu/NavSatFix）是接入真实驱动前最好的「接口演练」；
- GNSS → 平面坐标的转换是导航模块（如 robot_localization）内部的必备步骤；
- 三个案例均提供 C++ 与 Python 双实现，实测输出与发布值一致。
