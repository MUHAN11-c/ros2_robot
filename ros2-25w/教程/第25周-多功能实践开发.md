## 25.2 知识点梳理

### 25.2.1 第1课 SLAM地图服务与定位AMCL定位技术（1h44m · 21 节）

- **核心概念**：地图服务（Map Service）负责地图的保存、加载与提供；AMCL（Adaptive Monte Carlo Localization，自适应蒙特卡洛定位）是基于粒子滤波的 2D 激光定位算法，在已知地图中估计机器人位姿。
- **要点 1 · 地图保存**：`nav2_map_server` 的 `map_saver_cli` 把 `/map` 话题上的 `nav_msgs/OccupancyGrid` 保存为磁盘文件：

  ```bash
  ros2 run nav2_map_server map_saver_cli -f ~/maps/office --ros-args -p save_map_timeout:=2000
  # 产出 office.pgm（图像）+ office.yaml（元数据）
  ```

  保存基本流程：等 SLAM 稳定 → 触发保存 → 校验文件完整（地图闭合、无未探索黑洞）。

- **要点 2 · ROS2 中的地图接口**：

  | 消息/服务 | 作用 |
  |---|---|
  | `nav_msgs/OccupancyGrid` | 占据栅格地图：`header` + `MapMetaData info` + `int8[] data` |
  | `nav_msgs/MapMetaData` | `resolution`（m/格）、`width/height`（格数）、`origin`（地图原点位姿） |
  | `data[i]` | 取值 0（空闲 free）/ 100（占据 occupied）/ -1（未知 unknown） |
  | `nav2_msgs/srv/SaveMap` | 保存地图服务（带参数覆盖） |
  | `nav2_msgs/srv/LoadMap` | 按文件名加载地图服务 |

- **要点 3 · 地图存储格式**：`*.pgm` 是 8 位灰度图（白=空闲、黑=占据、灰=未知），`*.yaml` 记录 `image`、`resolution`、`origin: [x, y, yaw]`、`occupied_thresh`（默认 0.65）、`free_thresh`（默认 0.25）、`negate`。yaml 的 `origin` 决定地图左下角在 `map` 坐标系中的位姿，挪动它会整体平移地图。
- **要点 4 · 地图读取**：方式 1 终端读取——`ros2 launch nav2_map_server map_server_launch.py map:=/home/user/maps/office.yaml` 后 `ros2 topic echo /map --once`；方式 2 程序读取（三讲：基本实现 → 优化 → 补充）——订阅 `/map` 或调用 `LoadMap` 服务解析 `OccupancyGrid`，示例见 25.4。小结强调：地图文件是导航系统的持久化资产，应纳入版本管理。
- **要点 5 · AMCL 概述与定位节点**：AMCL 用粒子滤波（MCL）维护机器人位姿的概率分布，观测模型匹配激光与地图、运动模型采样自里程计，粒子数自适应（KLD 采样）。节点 `amcl`（包 `nav2_amcl`）订阅 `/scan`、`/map`、`/tf`（里程计），发布 `map → odom` 变换与 `/amcl_pose`（`PoseWithCovarianceStamped`）、`particle_cloud`。
- **要点 6 · AMCL 使用六步**：① 框架搭建（自建 bringup 包放 launch/yaml）→ ② 加载地图（`map_server` + `map:=...yaml`）→ ③ 核心实现（amcl 参数 + 雷达/里程计输入接线）→ ④ 运行（rviz2 中观察粒子云收敛）→ ⑤ **手动初始化**（rviz2 的「2D Pose Estimate」发布 `/initialpose`，粒子云骤然收缩到真值附近）→ ⑥ 优化（粒子数、`update_min_d`/`update_min_a`、激光模型 `likelihood_field` 参数）。
- **要点 7 · AMCL 关键参数**：

  | 参数 | 含义 | 调参直觉 |
  |---|---|---|
  | `alpha1..alpha5` | 运动模型噪声 | 里程计越差调越大 |
  | `max_particles` / `min_particles` | 粒子数上下限 | 大地图/多歧义环境增大 |
  | `update_min_d` / `update_min_a` | 位移/转角更新阈值 | 调小提高定位频率、费 CPU |
  | `laser_model_type` | `likelihood_field` / `beam` | 默认 likelihood_field，快且稳 |
  | `recovery_alpha_slow/fast` | 全局重定位（绑架恢复） | 机器人被搬动后自动收敛 |

### 25.2.2 第2课 导航服务器与多车编队实现（4h20m · 42 节）

- **核心概念**：导航服务器（Navigation Servers）指 Nav2 中各职责单一的生命周期节点；本课以「逐服务器实操」的方式把第24 章的架构图落地。
- **要点 1 · 准备与生命周期管理器**：准备三讲完成 bringup 包骨架、参数文件与依赖；`lifecycle_manager`（`nav2_lifecycle_manager`）统一把所有服务器 configure → activate，任何一个 activate 失败都会导致导航「起不来」。调试手段：`ros2 lifecycle list /planner_server`、`ros2 lifecycle get /planner_server`。
- **要点 2 · 行为树（Behavior Tree）**：`bt_navigator` 按 XML 行为树编排导航流程，节点分四类：Control（Sequence/ReactiveFallback）、Condition（如 `IsPathValid`）、Action（`ComputePathToPose`、`FollowPath`、`Spin`、`BackUp`）、Decorator（`RateController`）。默认 XML 在 `nav2_bt_navigator/behavior_trees/` 下，可替换自定义树实现「到点巡逻」「超时放弃」等策略。
- **要点 3 · 路径规划**：`planner_server` 插件化全局规划器（`NavfnPlanner`、`SmacPlanner2D`、`ThetaStar`），输入 `ComputePathToPose` 动作 + costmap，输出 `/plan`；rviz2 的「Nav2 Goal」即触发整条链。验收：路径绕开膨胀层、走廊中走中线。
- **要点 4 · 运动控制器**：`controller_server` 插件（`DWBController`、`MPPIController`、`RegulatedPurePursuit`）执行 `FollowPath`，输出 `/cmd_vel`；关键参数：`controller_frequency`、`max_vel_x`/`min_vel_x`、`xy_goal_tolerance`/`yaw_goal_tolerance`、costmap 膨胀半径。
- **要点 5 · 恢复服务器**：`behavior_server` 提供 `Spin`（原地旋转清除局部代价地图盲区）、`BackUp`（倒车脱困）、`Wait`、`ClearCostmap`；由行为树在规划/跟踪失败时调用，是机器人「卡住自救」的机制。
- **要点 6 · 路点跟踪**：`waypoint_follower` 执行 `FollowWaypoints` 动作，按序访问多个目标点，可配置路点任务插件（如每个路点拍照）。
- **要点 7 · 路径平滑与速度平滑**：`smoother_server`（如 `SimpleSmoother`）优化全局路径曲率；`velocity_smoother`（`nav2_velocity_smoother`）限制加加速度（jerk），把控制器输出的「跳变速度」变成底盘可执行的平滑速度——实机上不加它，电机与轮胎都会「受苦」。
- **要点 8 · 自主探索 SLAM**：把 Nav2 与 SLAM 组合（配合探索插件/`explore_lite` 类方案），机器人自主前往地图边界「未知区域」完成建图闭环；本质是「SLAM 建图 + 导航到 frontier（前沿）」循环。
- **要点 9 · 多车编队（20 节）**：

  | 环节 | 内容 |
  |---|---|
  | 简介与案例分析 | 编队 = 多车保持期望相对位姿（头车 + 从车）；相对位姿用静态坐标变换表达 |
  | 多车仿真环境 | stage_ros2/Ignition 多机器人 world，每车独立命名空间 |
  | 多车定位 | 每车独立 AMCL/SLAM（`robot1/amcl`…），注意 tf 隔离：`frame_prefix` 或 tf_namespace，否则 `map → odom` 互相打架 |
  | 多车导航 | 头车按全局目标导航；从车目标点 = 头车位姿 ∘ 编队偏移；launch/配置按车参数化 |
  | 编队逻辑 | 用 `static_transform_publisher`（或 C++ `tf2_ros::StaticTransformBroadcaster`）把队形偏移（如 robot2 在头车后方 1 m）固化为 tf，从车控制器跟踪该变换点 |

- **要点 10 · 多车的 ROS2 机制**：命名空间隔离话题（`/robot1/cmd_vel`）、参数文件按车分套、tf 用 `frame_prefix`（`robot1/odom`）或独立 tf topic + relay；这是 ROS2 分布式多机系统（含多机 DDS 发现）的实战入口。

### 25.2.3 第3课 智能语音概念和语音控制机器人实现（1h27m · 18 节）

- **核心概念**：智能语音（Intelligent Voice）= 语音识别（ASR，语音→文本）+ 语义理解（NLU）+ 语音合成（TTS，文本→语音）；与 ROS2 集成后即可「动口不动手」控制机器人。
- **要点 1 · 智能语音与 ROS2**：典型架构——麦克风音频 → ASR 节点（识别文本，发布 `std_msgs/String` 话题）→ 指令解析节点（关键词/语义映射为动作）→ 发布 `/cmd_vel` 或导航目标 → TTS 节点播报执行结果。ROS2 的话题/服务天然适合把云端 SDK 封装成节点。
- **要点 2 · 讯飞 SDK 基本使用**：官网下载 SDK（含 C/C++ 库与示例）→ 安装（解压、配置库路径/`APPID`）→ 构建测试示例 → 跑通离线/在线语音识别与合成 Demo。注意 SDK 的鉴权参数（APPID、APIKey）与线程/回调模型。
- **要点 3 · 讯飞 SDK 与 ROS2 集成**：自建功能包（`voice_pkg`）封装 SDK：语音识别功能（录音 → ASR → 发布识别文本）、语音合成功能（订阅文本 → TTS → 播放/输出音频）。集成要点：SDK 是 C 接口，用 C++ 包装为 rclcpp 节点最自然；录音设备（ALSA/PortAudio）与音频线程别阻塞 executor。
- **要点 4 · 智能语音应用实例**：需求分析（如语音说「前进/后退/左转/右转/停止」控制机器人，说「去客厅」触发导航）→ 实现五步：流程简介（ASR → 指令解析 → 执行 → TTS 反馈）→ 代码逻辑分析 → 代码框架（`asr_node` / `command_node` / `tts_node`）→ 代码实现（关键词匹配表 + `/cmd_vel` 发布）→ 执行测试。

## 25.3 重点与难点

1. **地图坐标系的 origin 语义**：`yaml` 的 `origin: [x, y, yaw]` 是「地图图像左下角」在 `map` 坐标系的位姿。改分辨率或 origin 而不重新配准，AMCL 粒子会整体偏移。
2. **AMCL 的收敛与绑架**：初始位姿靠 `/initialpose` 或默认参数；机器人被搬动（绑架问题）后靠 `recovery_alpha_*` 重定位。粒子云长期发散 = 里程计噪声参数与实际不符或地图与环境不一致。
3. **Nav2 生命周期**：所有服务器是 lifecycle node，`configure`（加载参数/插件）→ `activate`（开始工作）。报「node not active」先查 `lifecycle_manager` 日志与参数文件里的插件名拼写。
4. **行为树调试**：导航失败时先看 `bt_navigator` 日志中的行为树 tick 路径，确认是规划失败、跟踪失败还是恢复行为循环；`view_frames` + `ros2 topic echo /plan` 是两大取证工具。
5. **多车 tf 隔离**：两车不加 `frame_prefix` 时，两个 `odom → base_link` 冲突，rviz2 中表现「两车互相抽搐」。每车独立 tf 树或统一带前缀，二选一并保持全局一致。
6. **语音链路实时性**：ASR 延迟（网络/推理）决定交互体验；控制指令解析用关键词精确匹配 + 置信度阈值，避免误触发（「停」误识别为「听」）造成安全问题。

```python
# 方式2：程序读取地图（文件 map_reader.py，订阅 /map 并统计空闲/占据比例）
import rclpy
from rclpy.node import Node
from nav_msgs.msg import OccupancyGrid


class MapReader(Node):
    def __init__(self):
        super().__init__('map_reader')
        self.create_subscription(OccupancyGrid, '/map', self.on_map, 1)  # 地图是 transient_local

    def on_map(self, msg: OccupancyGrid):
        total = msg.info.width * msg.info.height
        free = sum(1 for v in msg.data if v == 0)
        occ = sum(1 for v in msg.data if v == 100)
        self.get_logger().info(
            f'{msg.info.width}x{msg.info.height} res={msg.info.resolution} '
            f'free={free/total:.1%} occ={occ/total:.1%} origin=({msg.info.origin.position.x}, '
            f'{msg.info.origin.position.y})')
        self.destroy_subscription(self.subscriptions[0])   # 只看一次


def main():
    rclpy.init()
    rclpy.spin(MapReader())
    rclpy.shutdown()
```

> **注意：** `/map` 用 transient_local（latched）QoS 发布，普通订阅者若用默认 QoS 可能收不到地图；rclpy 中把 QoS durability 设为 `ReliabilityPolicy.RELIABLE` + `DurabilityPolicy.TRANSIENT_LOCAL`。

### 25.4.3 场景 3：行为树导航目标发送（rclpy 动作客户端）

```python
# 通过 NavigateToPose 动作让 Nav2 导航到目标点（文件 send_goal.py）
import rclpy
from rclpy.node import Node
from rclpy.action import ActionClient
from geometry_msgs.msg import PoseStamped
from nav2_msgs.action import NavigateToPose


class NavGoal(Node):
    def __init__(self):
        super().__init__('nav_goal')
        self.client = ActionClient(self, NavigateToPose, 'navigate_to_pose')

    def send(self, x, y, yaw_w=1.0):
        self.client.wait_for_server()
        goal = NavigateToPose.Goal()
        goal.pose = PoseStamped()
        goal.pose.header.frame_id = 'map'
        goal.pose.header.stamp = self.get_clock().now().to_msg()
        goal.pose.pose.position.x = x
        goal.pose.pose.position.y = y
        goal.pose.pose.orientation.w = yaw_w
        return self.client.send_goal_async(goal)


def main():
    rclpy.init()
    node = NavGoal()
    node.send(3.0, 1.5)
    rclpy.spin(node)
    rclpy.shutdown()
```

### 25.4.4 场景 4：编队静态坐标变换（C++，`tf2_ros::StaticTransformBroadcaster`）

```cpp
// 把「从车相对头车的队形偏移」固化为 tf：leader_link -> follower1_link
#include "rclcpp/rclcpp.hpp"
#include "tf2_ros/static_transform_broadcaster.h"
#include "geometry_msgs/msg/transform_stamped.hpp"

int main(int argc, char ** argv) {
  rclcpp::init(argc, argv);
  auto node = rclcpp::Node::make_shared("formation_tf");
  tf2_ros::StaticTransformBroadcaster broadcaster(node);

  geometry_msgs::msg::TransformStamped t;
  t.header.stamp = node->now();
  t.header.frame_id = "leader_link";      // 头车车体
  t.child_frame_id = "follower1_link";    // 从车 1 目标位
  t.transform.translation.x = -1.5;       // 头车后方 1.5 m
  t.transform.translation.y = 0.8;        // 右侧 0.8 m（三角队形）
  t.transform.rotation.w = 1.0;           // 与头车同向
  broadcaster.sendTransform(t);

  rclcpp::spin(node);
  rclcpp::shutdown();
  return 0;
}
```

### 25.4.5 场景 5：语音指令解析 → 速度控制（rclpy，文件 `voice_cmd_node.py`）

```python
import rclpy
from rclpy.node import Node
from std_msgs.msg import String
from geometry_msgs.msg import Twist

# ASR 节点发布识别文本到 /asr/text，本节点映射为速度指令
CMD_TABLE = {
    '前进': (0.3, 0.0), '后退': (-0.3, 0.0),
    '左转': (0.0, 0.5), '右转': (0.0, -0.5), '停止': (0.0, 0.0),
}


class VoiceCmd(Node):
    def __init__(self):
        super().__init__('voice_cmd')
        self.pub = self.create_publisher(Twist, '/cmd_vel', 10)
        self.create_subscription(String, '/asr/text', self.on_text, 10)
        self.create_publisher(String, '/tts/text', 10)   # 送给 TTS 播报

    def on_text(self, msg: String):
        text = msg.data.strip()
        if text in CMD_TABLE:
            vx, wz = CMD_TABLE[text]
            cmd = Twist()
            cmd.linear.x, cmd.angular.z = vx, wz
            self.pub.publish(cmd)
            self.get_logger().info(f'执行指令: {text}')
        else:
            self.get_logger().warn(f'未识别指令: {text}')


def main():
    rclpy.init()
    rclpy.spin(VoiceCmd())
    rclpy.shutdown()
```

## 25.6 与 ROS2 / 机器人开发的关联

1. **nav2 全栈收口**：本章把第24 章架构图中的每个服务器都实操了一遍——生命周期管理、行为树调度、planner/controller/behavior/waypoint/smoother 协同，就是工业级导航产品的标准骨架。
2. **tf2 坐标树的最终形态**：`map →(AMCL) odom →(EKF/轮式里程计) base_link →(URDF) 各传感器`，多车场景再叠加 `frame_prefix`。这张树是所有机器人项目的「排障第一图」。
3. **地图与定位的持久化接口**：`OccupancyGrid`、`SaveMap`/`LoadMap`、`/initialpose` 是导航产品的数据契约；换算法（AMCL ↔ 定位版 SLAM ↔ 视觉定位）只要保住这套接口就能替换。
4. **多机器人系统的 ROS2 模式**：命名空间 + tf 前缀 + 参数分套 + 多机 DDS 发现，这套模式可直接迁移到仓储多车、机群巡检等真实项目。
5. **语音/上层交互的节点化封装**：任何第三方 SDK（语音、视觉大模型、云平台）都可以按「订阅输入话题 → 处理 → 发布输出话题/动作」封装成节点，与 Nav2 的 `NavigateToPose` 动作组合即成完整产品交互链。
6. **仿真 → 实机迁移收尾清单**：地图分辨率与真实环境一致、AMCL 运动噪声按实测里程计调、速度平滑参数按底盘动力学调、语音指令加安全限速——这四项决定实机表现。

## 25.7 自测与练习

1. **概念题**：`OccupancyGrid.data` 中 -1、0、100 分别代表什么？地图 `yaml` 的 `origin` 改了会发生什么？
2. **动手任务**：完成「建图 → 保存 → AMCL 定位 → 导航到目标点」全流程：第24 章的仿真环境中建图保存为 `office`，重启后加载地图用 AMCL 定位，发 `NavigateToPose` 目标点（3.0, 1.5）。验收标准：粒子云收敛后导航成功率 ≥ 8/10，`view_frames` 中 `map → odom` 由 amcl 发布。
3. **动手任务**：双车编队：两车在同一地图中，通过静态坐标变换令 robot2 跟随 robot1 右后方 1 m 位置。验收标准：robot1 移动时 robot2 稳定保持相对位姿（误差 < 0.3 m），两车 tf 树互不冲突。
4. **动手任务**：语音控制闭环：用录音/文本模拟 ASR 输出「前进」「停止」，机器人 `/cmd_vel` 响应正确，并由 TTS 播报「已执行」。

> 参考答案要点：1. -1 未知、0 空闲、100 占据；`origin` 是地图图像左下角在 map 系的位姿，改动会导致地图整体平移/旋转，AMCL 定位随之整体偏移。2. 定位发散优先查 `/initialpose` 是否给准、里程计与 AMCL 噪声参数是否匹配、激光 `frame_id` 是否正确。3. 编队的关键是 tf 前缀隔离与从车跟踪目标点由「头车位姿 ∘ 队形偏移」实时计算；静态偏移适合匀速平缓运动，高速时需动态队形控制。4. 指令解析用精确关键词匹配 + 未识别指令只播报不动作，避免误触发。

## 25.8 常见问题（FAQ）

- **Q：`map_saver_cli` 保存的图全是灰色/空白？** A：`/map` 尚无数据或 QoS 不匹配；先 `ros2 topic echo /map --once` 确认有地图，给订阅端配 `TRANSIENT_LOCAL` durability，或增大 `save_map_timeout`。
- **Q：AMCL 粒子云收敛但导航仍失败？** A：定位正常 ≠ 导航可用。依次查：全局 costmap 是否加载静态层（`static_layer`）、目标点是否落在膨胀区/未知区、`controller_server` 是否 activate、`/cmd_vel` 是否被其他节点（如 teleop）抢占。
- **Q：两车在 rviz2 中「抽搐/瞬移」？** A：tf 冲突。给每车配置 `frame_prefix`（如 `robot1/`）或在独立机器上分别运行再通过 relay 合并；检查是否有两个节点发布同一变换。
- **Q：语音识别节点跑起来卡顿？** A：SDK 录音/网络回调阻塞了 executor 线程。把 SDK 放独立线程 + 线程安全队列，或用 `MultiThreadedExecutor` + `callback_group`；文本发布频率与指令解析解耦。
- **Q：`NavigateToPose` 发了没反应？** A：`ros2 action list` 确认 `navigate_to_pose` 存在、`bt_navigator` 已 activate、goal 的 `frame_id` 是 `map` 且时间戳有效（用当前时间，不要用 0）。
