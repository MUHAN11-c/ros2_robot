## 1. 从生活到概念：机器人的部件怎么"说话"

回忆 10 章的完整工作流：传感器 → 状态估计 → 决策规划 → 控制器 → 执行器。真实机器人上，这几段往往跑在**不同的计算单元**上：相机接视觉板卡，规划在工控机，电机驱动在实时控制器。它们必须频繁互相喊话：

- 相机每秒 30 次："我又看到一堆点云了！"
- 规划每 0.1 秒："下一步目标速度是这个。"
- 电机驱动每 1 毫秒："我收到了，电流已到位。"

你自然会有三个工程问题：**消息怎么 reliably 送达？新部件怎么即插即用？调试时怎么偷看谁在说什么？** 自己从零写网络通信 + 时序调度 + 日志调试，足够写掉半年。ROS（Robot Operating System，机器人操作系统）就是全行业把这些轮子造好、拼起来的公共设施。

**先纠正一个名字带来的误会**：ROS2 不是 Windows/Linux 那种操作系统——它**不管理内存、不调度进程**。它是跑在 Linux 之上的一层"**通信总线 + 工具链**"：

- 通信总线：定义好了"节点之间怎么找彼此、怎么传消息"；
- 工具链：命令行、可视化、构建系统、日志、仿真接口一应俱全。

> 一句话：**Linux 管机器，ROS2 管机器人部件之间的"对话"。**

## 2. 概念是什么

### 2.1 ROS1 与 ROS2：一字之差，代际之别

ROS1 发布于 2007 年（斯坦福），ROS2 于 2020 年前后成熟（Dashing/Foxy 起），通信底座完全重写。今天的工程与教程默认 ROS2，老项目才需要 ROS1：

| 维度 | ROS1 | ROS2 |
|---|---|---|
| 通信中间件 | 自研 TCPROS/UDPROS | **DDS**（Data Distribution Service，数据分发服务，工业级标准） |
| 架构 | 需要中心节点 `roscore`（单点故障：master 挂了全瘫） | **无中心**：节点自动互相发现，没有单点 |
| 实时性 | 基本不保证 | 支持实时通信（配合 DDS 的 QoS 服务质量策略） |
| 支持平台 | 基本只有 Linux | Linux / Windows / macOS / 嵌入式 |
| 语言版本 | 老教程 Python 2 泛滥 | 只用 Python 3 |
| 命令行风格 | `rostopic`、`rosrun` | `ros2 topic`、`ros2 run`（`ros2` 打头） |

本站后续所有方向文档一律 ROS2。网上老教程的**概念**（节点、话题、发布订阅）可以迁移，**命令**不要照抄。

### 2.2 发行版怎么选

ROS2 按版本叫"发行版（Distribution）"，与 Ubuntu 版本一一绑定：

| 发行版 | 对应 Ubuntu | 官方支持到 | 建议 |
|---|---|---|---|
| **Humble Hawksbill** | 22.04 LTS | 2027 年 | **本目录主线**：教程最丰富、最稳 |
| Jazzy Jalisco | 24.04 LTS | 2029 年 | 新装 24.04 可选，教程同样适用 |
| Foxy / Iron / Dashing 等 | — | 已停止维护 | 不要选 |

**本章后续所有命令以 Humble + Ubuntu 22.04 为主线**（用 Jazzy 只需把 `humble` 全局替换成 `jazzy`）。

### 2.3 核心概念：节点、话题、消息、服务

四个词，两两成对，先看图再看定义：



![图示](../assets/labs/diagrams/diag_40_ROS2初体验_小海龟仿真_8613b5a405.svg)



| 概念 | 英文 | 一句话定义 | 类比 |
|---|---|---|---|
| **节点（Node）** | Node | 一个执行单一功能的最小程序单元（"感知节点""遥控节点"） | 一个部门 |
| **话题（Topic）** | Topic | 具名消息频道，发布-订阅式的"广播电台" | 广播频道 |
| **消息（Message）** | Msg | 话题上传输的**数据格式**，如 `Twist` = 线速度 + 角速度 | 广播的内容格式 |
| **服务（Service）** | Service | 一问一答式的调用（请求 → 响应），适合"偶尔一次"的操作 | 打客服电话 |

**发布-订阅（Publish–Subscribe）模型**的精髓在"解耦"：

- 发送方只管往话题上扔消息，**不需要知道**谁在听、几个在听；
- 接收方只管订阅话题，**不需要知道**谁在发；
- 于是换掉遥控器、加一个录包节点，都不用改对方一行代码——这就是机器系统"即插即用"的秘密。

一问一答的事（"重新载入参数""报告当前配置"）才用服务；持续流动的数据流（传感器、速度指令）一律走话题。

**话题还是服务？三秒判断法**：

| 判断 | 用话题 | 用服务 |
|---|---|---|
| 数据流形态 | 持续、高频、单向（每秒几十条） | 偶尔、低频、需要回执 |
| 例子 | 速度指令、相机帧、位姿汇报 | "生成一只新海龟""保存当前地图" |
| 通信失败的表现 | 丢一帧无伤大雅，下帧跟上 | 请求必须得到响应，否则任务失败 |

> 📖 教材对照：ROS2 官方教程 "Understanding Nodes / Topics / Services"（Humble 与 Jazzy 同名章节）

## 3. 动手装一装：Ubuntu 22.04 安装 ROS2 Humble

**Windows 用户请先看这里（WSL2 提示）**：本章主线环境是 Ubuntu 22.04。Windows 11 用户强烈建议走 **WSL2**（微软官方的"Windows 里跑 Linux"方案，自带 WSLg 图形支持，小海龟窗口能直接弹出）：管理员 PowerShell 执行 `wsl --install -d Ubuntu-22.04`，重启后进入 Ubuntu 继续下文即可。Windows 10 用户 WSLg 不可用，需额外装 X Server（VcXsrv）或用虚拟机。macOS 建议虚拟机。

**鱼香 ROS 一键安装提示（国内网络推荐）**：如果下面的手动步骤因网络原因（GitHub 访问不稳）卡住，可用社区知名的鱼香 ROS 工具一键换源安装：终端执行 `wget http://fishros.com/install -O fishros && . fishros`，按菜单选"一键安装 ROS (Humble)"。以下手动序列供理解原理与镜像环境使用。

**第一步：检查与配置软件源**

```bash
locale                                   # 检查：输出应包含 UTF-8 字样
sudo apt update                          # 刷新软件源索引（先看一眼有什么可装）
sudo apt install -y software-properties-common   # 装 add-apt-repository 工具
sudo add-apt-repository universe         # 启用 universe 源（ROS 依赖的部分包住在这）
```

**第二步：添加 ROS 官方软件源**

```bash
sudo apt update && sudo apt install -y curl       # 装下载工具 curl
sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key \
  -o /usr/share/keyrings/ros-archive-keyring.gpg   # 导入 ROS 仓库的签名钥匙（防篡改）
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] http://packages.ros.org/ros2/ubuntu $(. /etc/os-release && echo $UBUNTU_CODENAME) main" | sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null
                                                  # 把 ROS2 仓库地址写进 apt 源列表
sudo apt update                                   # 重新刷新索引，确认能读到 ROS2 源
```

**第三步：安装**

```bash
sudo apt install -y ros-humble-desktop            # 安装桌面完整版（含 turtlesim、rqt 等）
```

装完约 2–3 GB，十几分钟到半小时。之后把环境配置写进终端启动脚本，**每个新终端自动生效**：

```bash
echo "source /opt/ros/humble/setup.bash" >> ~/.bashrc   # 把 source 命令追加进 bashrc
source ~/.bashrc                                        # 让当前终端立即生效
```

**第四步：装配套工具（rosdep 与 colcon）**

```bash
sudo apt install -y python3-rosdep                # rosdep：自动安装包依赖的系统库
sudo rosdep init                                  # 初始化 rosdep（首次执行一次即可）
rosdep update                                     # 更新 rosdep 数据库
sudo apt install -y python3-colcon-common-extensions   # colcon：§5 要用的构建工具
```

**验收**：

```bash
ros2 --help                                       # 能打印出用法说明 = 安装成功
```

**动手前环境自检表**（三条全绿再进 §4，能省掉大半排障时间）：

| 检查项 | 命令/做法 | 达标标准 |
|---|---|---|
| ROS2 命令可用 | `ros2 --help` | 打印出用法与子命令列表 |
| 环境自动加载 | 新开终端直接敲 `ros2 --help` | 无需手动 source 也有输出（bashrc 生效） |
| 图形窗口可用 | `ros2 run turtlesim turtlesim_node` | 蓝色画布窗口弹出（WSL2 需 Windows 11 的 WSLg） |

## 4. 动手跑一跑：小海龟实战全流程

小海龟（turtlesim）是 ROS 界的 "Hello World"：一只画布上的小乌龟，接收速度指令爬行、留痕。麻雀虽小，**节点、话题、消息一样不缺**。

### 4.1 启动仿真器

```bash
ros2 run turtlesim turtlesim_node
```

终端会打印两行启动日志（时间戳与出生坐标每台机器、每次启动都不同）：

```text
[INFO] [1712345678.123456789] [turtlesim]: Starting turtlesim with node name /turtlesim
[INFO] [1712345678.131234567] [turtlesim]: Spawning turtle [turtle1] at x=[5.544445], y=[5.544445], theta=[0.000000]
```

**它做了什么**：`ros2 run` = "按名字启动某个包里的某个可执行程序"。这里启动了 `turtlesim` 包中的 `turtlesim_node`——一个**节点**（日志第一行就自报了节点名 `/turtlesim`）。弹出的蓝色窗口里趴着一只小海龟，它此刻正在话题上"听"速度指令。

### 4.2 键盘遥控（新开一个终端）

```bash
ros2 run turtlesim turtle_teleop_key
```

**它做了什么**：启动第二个节点——键盘遥控器。**点一下这个终端窗口让它获得焦点**，按方向键，小海龟就动起来了。此刻你已拥有一个"双人系统"：teleop 节点在**发布**，turtlesim 节点在**订阅**。留个心眼：可执行**程序**名叫 `turtle_teleop_key`，它启动后注册的**节点名**默认是 `/teleop_turtle`——程序名 ≠ 节点名，下一节用命令亲眼验证。

### 4.3 看看系统里有什么（再开一个终端）

```bash
ros2 node list
```

**它做了什么**：列出当前所有活着的节点。预期输出：

```text
/turtlesim
/teleop_turtle
```

第二个就是上节说的遥控器节点——**节点名**是 `/teleop_turtle`，而不是程序名 `turtle_teleop_key`（节点名由代码自定，排障时别找错）。

```bash
ros2 topic list
```

**它做了什么**：列出所有话题。预期输出（节选）：

```text
/turtle1/cmd_vel      ← 速度指令话题（"指令频道"）
/turtle1/pose         ← 海龟位姿话题（"汇报频道"）
```

给 `list` 加个 `-t` 参数，还能一眼看到每条话题传的是**什么类型**的消息（官方教程同款命令）：

```bash
ros2 topic list -t
```

```text
/parameter_events [rcl_interfaces/msg/ParameterEvent]
/rosout [rcl_interfaces/msg/Log]
/turtle1/cmd_vel [geometry_msgs/msg/Twist]
/turtle1/color_sensor [turtlesim/msg/Color]
/turtle1/pose [turtlesim/msg/Pose]
```

再进一步，想知道某条话题上**几个人在发、几个人在听**：

```bash
ros2 topic info /turtle1/cmd_vel
```

```text
Type: geometry_msgs/msg/Twist
Publisher count: 1
Subscription count: 1
```

此刻发布者只有遥控器一个、订阅者只有海龟一个（若你的 `echo` 监听器还开着，订阅数会多 1）。练习 5 里"两个发布者抢一条频道"的乱象，用这条命令就能提前侦察出来。

### 4.4 偷看消息长什么样

```bash
ros2 topic echo /turtle1/cmd_vel
```

**它做了什么**：订阅 `/turtle1/cmd_vel` 并把收到的消息实时打印出来——一个"监听器"。回到 4.2 的终端按几下方向键，这里就会滚动出现。按"前进"键时（官方教程的实测输出）：

```yaml
linear:
  x: 2.0
  y: 0.0
  z: 0.0
angular:
  x: 0.0
  y: 0.0
  z: 0.0
```

按"左转"键则换成另一条消息：`linear` 三项全为 0，只有 `angular.z: 2.0`（逆时针 2 rad/s）——遥控器每个方向键只负责改自己那一个数。

**它说了什么**：这是 `geometry_msgs/msg/Twist` 消息——`linear`（线速度矢量）+ `angular`（角速度矢量）。**海龟的"母语"原来就这么两条数。**（顺手再跑 `ros2 topic echo /turtle1/pose` 能看到海龟自报的 $x, y, \theta$——正是 20 章的位姿。）

**不按键也能查格式：`ros2 interface show`**

`echo` 是"等别人发了才看到"；而"这类消息**按规定**有哪些字段"，不用等，一条命令直接查（官方教程同款）：

```bash
ros2 interface show geometry_msgs/msg/Twist
```

```text
# This expresses velocity in free space broken into its linear and angular parts.

Vector3  linear
    float64 x
    float64 y
    float64 z
Vector3  angular
    float64 x
    float64 y
    float64 z
```

这就是消息的"格式单"：两个 `Vector3`（三维矢量），各含三个 `float64`（双精度浮点数）。下一节 `ros2 topic pub "{linear: {x: 2.0}, angular: {z: 1.0}}"` 里的每个字段名都来自这张单子——**发布前先查单，是 ROS2 开发的基本功**（服务也有同款查询，见 §4.7 的 `ros2 service type`）。

### 4.5 不碰键盘，直接发指令：让海龟画圆

```bash
ros2 topic pub --rate 1 /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 2.0}, angular: {z: 1.0}}"
```

**它做了什么**：`ros2 topic pub` = 命令行版发布者：以 `--rate 1`（每秒 1 次）的频率，向 `/turtle1/cmd_vel` 发布一条 `Twist` 消息：前进 2.0 m/s + 逆时针转 1.0 rad/s。**小海龟会立刻开始画圆。**

几何彩蛋：当线速度 $v$ 与角速度 $\omega$ 都恒定时，海龟走的圆半径是

$$
r = \frac{v}{\omega} = \frac{2.0\ \text{m/s}}{1.0\ \text{rad/s}} = 2.0\ \text{m}
$$

想画小圆就降 $v$ 或升 $\omega$（练习 1 让你亲手验证）。按 `Ctrl+C` 结束发布。

顺带一个频率测量工具（官方教程同款）：`ros2 topic hz` 能实测一条话题**实际的发布频率**。比如测海龟的位姿汇报：

```bash
ros2 topic hz /turtle1/pose
```

```text
average rate: 59.354
```

官方教程实测约 59 次/秒（数值随机器浮动）。§5 你会给自己写的节点定 20 Hz 的发布频率——到底够不够、海龟会不会"一顿一顿"，用 `hz` 一测便知，比猜测可靠得多。

### 4.6 看懂全局：rqt_graph

```bash
rqt_graph    # 若提示未安装：sudo apt install ~nros-humble-rqt*（官方推荐写法，~n 让 apt 按名字装齐 rqt 全家桶）
```

**它做了什么**：画出此刻系统的"组织架构图"，预期长这样：

```text
   [/teleop_turtle] ─── /turtle1/cmd_vel ───▶ [/turtlesim]
            ▲               /turtle1/pose  ───▶ （你的 echo 监听器，若有）
        （你按键盘）
```

两张节点、两条话题，与 §2.3 的发布-订阅图完全对上。以后你打开任何机器人项目的 `rqt_graph`，无论多复杂，读法都一样：**方块是节点，箭头是话题，箭头上的字是数据内容。**

### 4.7 服务实战：召唤第二只海龟

话题是广播，服务是一问一答。turtlesim 自带一个经典的"服务"体验——在画布里召唤第二只海龟：

```bash
ros2 service list
```

**它做了什么**：列出当前所有服务。能看到 `/spawn`（生成海龟）、`/clear`（清画布）、`/kill`（移除海龟）等——服务名与话题名长得一样，都是 `/` 开头的路径。

```bash
ros2 service type /spawn
```

**它做了什么**：查 `/spawn` 这个服务收发数据的"格式单"。输出 `turtlesim/srv/Spawn`——问（请求）是新海龟的坐标与朝向，答（响应）是它的名字。

```bash
ros2 service call /spawn turtlesim/srv/Spawn "{x: 4.0, y: 2.0, theta: 0.0, name: 'turtle2'}"
```

**它做了什么**：向 `/spawn` 发起一次"电话呼叫"。画布上 $(4.0, 2.0)$ 处会立刻出现第二只海龟，终端返回响应：

```text
name: turtle2
```

想指挥这只新海龟，话题名也跟着变：`/turtle2/cmd_vel` 与 `/turtle2/pose`（用 `ros2 topic list` 亲眼确认）。官方教程给的推荐玩法是**重映射（Remapping）**：启动遥控器时把它发布的话题"改名指路"，一个键盘就能指挥第二只海龟：

```bash
ros2 run turtlesim turtle_teleop_key --ros-args --remap turtle1/cmd_vel:=turtle2/cmd_vel
```

命令行的 `ros2 service call` 与 4.5 的 `ros2 topic pub` 是姐妹命令——一个打"客服电话"，一个开"广播电台"；而 `--remap` 是"不改代码、只改接线"的万金油，真机上换传感器、换底盘时全靠它。

> 📖 教材对照：ROS2 官方教程 "Understanding Services / Introducing turtlesim and rqt"

## 5. 第一个自己的节点：让海龟自动画正弦

命令行发布者只会发**固定**速度。想让海龟走出变化的轨迹（蛇形的正弦摆动），得自己写节点——这是本章的高潮，也是你从"用 ROS2"到"写 ROS2"的分水岭。

### 5.1 发布者代码（逐行注释）

轨迹设计：线速度恒定 $v = 1.5$ m/s，角速度按正弦摆动 $\omega(t) = 2.0\sin(t)$ rad/s——航向角左右摇摆，海龟便走出一条"蛇形"的正弦轨迹。

```python
#!/usr/bin/env python3
# sine_talker.py —— 让小海龟走出正弦摆动的"蛇形"轨迹
import math                                        # 数学库：取正弦
import rclpy                                       # ROS2 的 Python 客户端库
from rclpy.node import Node                        # 节点基类：所有节点的"父类"
from geometry_msgs.msg import Twist                # 速度消息类型（线速度+角速度）

class SineTalker(Node):                            # 自定义节点，继承 Node

    def __init__(self):
        super().__init__('sine_talker')            # 注册节点名：sine_talker
        self.pub = self.create_publisher(          # 创建发布者：
            Twist,                                 #   消息类型：Twist
            '/turtle1/cmd_vel',                    #   话题名：与小海龟订阅的一致
            10)                                    #   队列深度：最多缓存 10 条消息
        self.t = 0.0                               # 累计时间（秒），从 0 开始
        self.timer = self.create_timer(0.05, self.tick)   # 每 0.05 秒触发一次 tick（20 Hz）

    def tick(self):                                # 定时器回调：每 50 ms 执行一次
        msg = Twist()                              # 造一条空的 Twist 消息
        msg.linear.x = 1.5                         # 线速度：恒定向前 1.5 m/s
        msg.angular.z = 2.0 * math.sin(self.t)     # 角速度：按正弦规律左右摆动
        self.pub.publish(msg)                      # 把消息发布到话题上
        self.t += 0.05                             # 时间推进一个周期
        self.get_logger().info(                    # 终端打印日志，便于观察
            't=%.2f  v=%.2f  w=%.2f' % (self.t, msg.linear.x, msg.angular.z))

def main(args=None):
    rclpy.init(args=args)                          # 初始化 ROS2（分配通信资源）
    node = SineTalker()                            # 实例化我们的节点
    try:
        rclpy.spin(node)                           # 进入循环：持续响应定时器回调
    except KeyboardInterrupt:                      # 按 Ctrl+C 时优雅退出
        pass
    node.destroy_node()                            # 销毁节点（回收资源）
    rclpy.shutdown()                               # 关闭 ROS2

if __name__ == '__main__':
    main()
```

读代码三问（答案都在注释里，合上再自查一遍）：

1. **发什么？** `Twist` 消息，`linear.x` 恒定、`angular.z` 正弦变化；
2. **发到哪？** 话题 `/turtle1/cmd_vel`——小海龟唯一在听的"指令频道"；
3. **多久发一次？** 20 Hz（每 0.05 s 一次），频率太低海龟会一顿一顿地爬。

### 5.2 创建工作空间与功能包

ROS2 代码住在**功能包（Package）**里，功能包住在**工作空间（Workspace）**里。三步搭窝：

```bash
mkdir -p ~/ros2_ws/src                            # 创建工作空间目录（ws=workspace）
cd ~/ros2_ws/src
ros2 pkg create sine_turtle --build-type ament_python --dependencies rclpy geometry_msgs
                                                  # 创建 Python 功能包并声明依赖
```

**它做了什么**：`ros2 pkg create` 生成一个叫 `sine_turtle` 的功能包骨架（`ament_python` 是 Python 包的构建类型），并把 `rclpy`、`geometry_msgs` 记为依赖。

把 §5.1 的代码存为 `~/ros2_ws/src/sine_turtle/sine_turtle/sine_talker.py`，然后打开 `~/ros2_ws/src/sine_turtle/setup.py`，找到 `entry_points`，改成：

```python
entry_points={
    'console_scripts': [
        'sine_talker = sine_turtle.sine_talker:main',   # 注册命令：包名.文件:入口函数
    ],
},
```

**它做了什么**：告诉构建系统"以后 `ros2 run sine_turtle sine_talker` 时，去执行 `sine_turtle/sine_talker.py` 里的 `main()`"。

### 5.3 构建与运行

```bash
cd ~/ros2_ws                                      # 回到工作空间根目录
colcon build                                      # 构建（编译/安装所有包）
source install/setup.bash                         # source 构建产物：让新包进入环境
ros2 run sine_turtle sine_talker                  # 运行你的节点！
```

**它做了什么**：`colcon build` 把你的包"装"进 `install/` 目录；`source install/setup.bash` 之后，`ros2 run` 才找得到它。运行后：终端每 0.05 s 打印一行日志，小海龟在画布上画出一条漂亮的正弦蛇形线。**恭喜——这是你人生第一个在 ROS2 系统里活着的节点。**

`colcon build` 成功时的输出长这样（节选）：

```text
Starting >>> sine_turtle
Finished <<< sine_turtle [3.42s]

Summary: 1 package finished [4.10s]
```

两个常用变体：改了代码后只想重编这一个包，用 `colcon build --packages-select sine_turtle`（省时间）；想让 Python 源码改动免重编直接生效，用 `colcon build --symlink-install`（开发期推荐）。若报错，先看第一段错误信息——十有八九是 `setup.py` 的 `entry_points` 没写对或缺逗号。

再开一个终端跑 `rqt_graph`，你会看到三个节点（teleop 若已关就剩两个）：

```text
   [/sine_talker] ─── /turtle1/cmd_vel ───▶ [/turtlesim]
```

你的节点已经和官方节点**平起平坐**：谁也不知道也不关心对面是谁——这正是发布-订阅的解耦。想同时跑多个节点互不干扰，记得每个终端都要先 `source`。

## 6. 和机器人有什么关系：小海龟 ↔ 真实机器人对应表（挂钩专节）

小海龟不是玩具——它是**一台真机器人的最小镜像**。逐行对照：

| 小海龟里的东西 | 真实机器人对应 | 对应说明 |
|---|---|---|
| `turtlesim_node` | 仿真器 / 真实底盘 | 都"接收速度指令并执行"——海龟只是把轮子画成了龟 |
| `/turtle1/cmd_vel`（Twist） | 底盘电机速度指令 | `linear.x` = 前进速度，`angular.z` = 转向角速度；真机底盘节点订阅同名话题 |
| `/turtle1/pose` | **里程计（Odometry）** | 海龟自报 $(x, y, \theta)$；真机由编码器积分报位姿——10 章"状态估计"的输入之一 |
| `turtle_teleop_key` | 遥控器/手柄节点 | 人类指令进入系统的入口，与海龟无半点特殊关系 |
| `rqt_graph` | 运行时拓扑监控 | 上线第一件事：看节点图对不对 |
| `ros2 topic echo` | 调试"示波器" | 真机排障天天用：先 echo，再下结论 |
| `colcon build` | 工程构建流程 | 方向目录里的每个项目都这么编译 |

**回想 10 章的工作流图**：小海龟系统已经覆盖了"决策（teleop 或你的节点）→ 控制指令（cmd_vel）→ 执行（画布上移动）→ 反馈（pose 话题）"的完整闭环——缺的只是"感知"（海龟不需要看世界）。等你进入 SLAM 方向，给真机加上激光雷达，把 `pose` 换成 SLAM 输出的位姿，今天这张图一字不改地长大。

!!! tip "从海龟到具身智能只差'换脑袋'"
    06 具身智能方向的玩法：把发布速度指令的"脑袋"从 `sine_talker` 换成一个大模型策略——它订阅相机话题、发布 `cmd_vel`。海龟没有变，底盘没有变，变的只是"决策节点"。理解了这张对应表，你就理解了整条技术路线的骨架。

## 7. 常见错误与自救

| 错误现象 | 原因 | 怎么改 |
|---|---|---|
| `ros2: command not found` | 本终端没 source 环境 | 执行 `source /opt/ros/humble/setup.bash`；确认已写进 `~/.bashrc` |

| `rosdep init` 报错连不上 | 国内网络访问 GitHub 不稳 | 用鱼香 ROS 一键安装工具换源（见 §3 开头提示） |

| `Ctrl+C` 停掉 pub/节点后海龟还在动 | 发布-订阅模型：最后一条指令"持续生效" | 发一条全零速度让它停（练习 2）；真机靠看门狗兜底 |

| 话题名对不上收不到消息 | `/turtle1/cmd_vel` 拼错或多了 `/` | 用 `ros2 topic list` 核对一字不差 |

## 8. 动手练习

**练习 1（画圆参数）**：用 `ros2 topic pub` 画半径 1 m 的圆。给出命令，并解释你的 $v, \omega$ 取值依据。

??? details "练习 1 解答"

    由 $r = v / \omega$，取 $v = 1.0$ m/s、$\omega = 1.0$ rad/s 即得 $r = 1$ m：

    ```bash
    ros2 topic pub --rate 10 /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 1.0}, angular: {z: 1.0}}"
    ```

    （`--rate 10` 发布更密，圆更圆滑；半径只由 $v/\omega$ 的比值决定。注意画布有限，半径别超过画布——超界海龟会顶墙。）

**练习 2（直线指令）**：让海龟以 1 m/s 走直线 3 秒，然后停下。写出两条命令（用 `--once` 与 `--times` 参数可查 `ros2 topic pub --help`）。

??? details "练习 2 解答"

    ```bash
    ros2 topic pub --once /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 1.0}}"
    # --once：只发一条。海龟收到后保持该速度直到下一条指令——此时立刻计时 3 秒
    ros2 topic pub --once /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.0}}"
    # 3 秒后执行这条：速度归零，停车
    ```

    要点：发布-订阅是"最后一条指令持续生效"的模型（海龟不自带刹车），这解释了为什么真实机器人的看门狗（超时自动停车）如此重要——控制指令一旦断流，机器人不能"惯性狂奔"。

**练习 3（读位姿）**：运行 `ros2 topic echo /turtle1/pose`，列出消息的所有字段名，并把它们与 20 章的"位姿"术语一一对应。

??? details "练习 3 解答"

    字段（turtlesim/msg/Pose）：`x`、`y`、`theta`、`linear_velocity`、`angular_velocity`。

    对应关系：`x, y` 是 20 章的**位置矢量**前两维（平面）；`theta` 是**姿态角**——平面情形下姿态只需一个转角（对应 20 章 $R_z(\theta)$ 中的 $\theta$，即欧拉角的偏航分量）；`linear_velocity` / `angular_velocity` 是速度信息，属于运动学范畴（30 章"末端速度 ↔ 关节速度"的平面版直觉）。

**练习 4（改轨迹）**：把 `sine_talker.py` 中角速度改为 `3.0 * math.sin(0.5 * self.t)`，重建运行。先口算预测：摆动幅度与周期各自怎么变？再跑代码验证。

??? details "练习 4 解答"

    幅度：正弦前系数 2.0 → 3.0，摆动幅度变大（蛇形更"甩"）；角频率：1 → 0.5，周期 $T = 2\pi/\omega_{\text{摆}}$ 从约 6.3 s 变为约 12.6 s，摆动变慢、波形被拉长。运行可见海龟走出更宽、更缓的大波浪——两个参数一个管"甩多狠"、一个管"甩多快"，与预测一致。

    修改后必须重新构建才能生效：

    ```bash
    cd ~/ros2_ws
    colcon build
    source install/setup.bash
    ros2 run sine_turtle sine_talker
    ```

**练习 5（节点侦探）**：同时运行 turtlesim、teleop、sine_talker 三个节点，用 `rqt_graph` 描述：谁在向 `/turtle1/cmd_vel` 发布？会发生什么现象？怎样只让海龟听 sine_talker 的？

??? details "练习 5 解答"

    `rqt_graph` 显示 `/teleop_turtle` 与 `/sine_talker` 同时向 `/turtle1/cmd_vel` 发布，`/turtlesim` 订阅（用 `ros2 topic info /turtle1/cmd_vel` 也能看到 `Publisher count: 2`）。现象：两个发布者的消息**交替到达**，海龟会"打摆子"——上一瞬按正弦摆动、下一瞬响应你的按键，轨迹混乱。

    解法（任选其一）：关掉其中一个发布者；或让 sine_talker 改发到新话题（如 `/turtle1/cmd_vel2`）并同时把海龟的订阅也迁过去；或用重映射机制（`--remap` 参数改话题名，官方写法见 §4.7 末尾）——最后一种是真机上"接管控制权"的标准手法，方向文档里会大量用到。

**练习 6（服务初试）**：海龟爬了满画布的线，想"擦黑板"（清掉轨迹但保留海龟）。用服务解决：先查 `/clear` 服务的类型，再调用它。

??? details "练习 6 解答"

    ```bash
    ros2 service type /clear                       # 查类型：输出 std_srvs/srv/Empty
    ros2 service call /clear std_srvs/srv/Empty    # 调用：擦掉画布上的轨迹
    ```

    要点：`std_srvs/srv/Empty` 意为"空请求、空响应"——擦黑板不需要带参数，也不需要返回值，调用即生效。与练习中 `/spawn`（要传坐标、返回名字）对比，你能体会到服务的"格式单"完全由任务决定。执行后画布轨迹消失、海龟留在原地——服务成功执行的"回执"就是画布本身。
