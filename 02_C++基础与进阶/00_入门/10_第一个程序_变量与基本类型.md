## 1. 从生活到概念：变量是贴了标签的盒子

想象你在玩一款开放世界游戏，背包里有各种格子：一格铁矿、一格摩拉、一格猎人的箭簇。每个格子有两个要素——**放什么种类的东西**（格子决定了只能放这类东西）和**格子上的标签**（一眼知道这是啥）。

程序里的**变量（Variable）**就是这个格子：

- **类型（Type）**= 格子的种类，规定"这里只能放整数/只能放小数"；
- **变量名（Variable Name）**= 格子上的标签，如 `angle_deg`；
- **值（Value）**= 格子里实际放的东西，如 `90.0`，且可以随时取出换新。

类比在哪里失效？游戏背包格子大小随意、能塞的东西五花八门；而 C++ 变量的类型**一旦定死就不可更改**，格子容量（占多少内存）也是类型决定的、非常精确——这份"死板"恰恰是 C++ 跑得快的原因之一。

## 2. 程序结构解剖：五行代码里的大学问

先解剖上一章的 hello.cpp。我们把它改成机器人味儿的版本，每一行都编号注释：

```cpp
#include <iostream>          // ① 预处理指令：把"输入输出库"的内容拷贝进来
                             //    iostream = input/output stream（输入输出流）

int main() {                 // ② 主函数 main：整个程序的入口，有且只有一个
                             //    前面的 int 表示它执行完要交回一个整数
    std::cout << "Hello, Robot!" << std::endl;   // ③ 输出语句：把一行字送到屏幕
    return 0;                // ④ 返回 0：向操作系统报告"一切正常"
}                            // ⑤ 右花括号：main 到此结束
```

每一部分的角色：

| 组成部分 | 术语 | 作用 |
|---|---|---|
| `#include <iostream>` | **预处理指令（Preprocessor Directive）** | 编译前，把标准库里输入输出的"工具箱"拼进来 |
| `int main() { ... }` | **主函数（main Function）** | 程序的起点。操作系统运行程序 = 运行 main |
| `std::cout << ...` | 输出语句 | `cout` 是"屏幕"，`<<` 把内容一个个送过去 |
| `return 0;` | **返回值（Return Value）** | 0 表示成功；非 0 表示出了问题（错误码） |
| `// 注释文字` | **注释（Comment）** | 写给人看的说明，编译器直接无视 |

三个初学必知的细节：

1. **每条语句以分号 `;` 结尾**。分号像句号，漏了编译器会在下一行"莫名其妙"报错。
2. **大小写敏感**。`Cout`、`Main` 都不是 `cout`、`main`。
3. `std::` 是"名字前缀"：`cout` 住在名叫 `std`（standard，标准库）的房间里。第 20 章讲函数时会再解释这个"房间"，现在照写 `std::cout` 即可。
4. `std::endl` 是"换行并清空缓冲"；`"\n"` 是单纯换行。初学阶段两者效果一样，本目录统一用 `"\n"`（更快，也更省字）。

### 2.1 注释：写给人看的话

C++ 有两种注释：

```cpp
#include <iostream>

// 这是单行注释：从 // 到本行结束，编译器全部无视
// 适合解释"这一行为什么这么写"

/*
   这是多行注释（块注释）：
   中间写多少行都行，
   适合解释一整段逻辑或 temporarily 屏蔽一段代码
*/

int main() {
    double angle = 90.0;   // 行尾注释：关节角度，单位度
    std::cout << angle << "\n";
    return 0;
}
```

预期输出：

```text
90
```

!!! tip
    注释的黄金法则：**写"为什么"，不写"是什么"**。`angle = 90.0; // 把 angle 设成 90` 是废话注释；`angle = 90.0; // 机械臂抬到水平位，调试时的标定值` 才是好注释。三个月后的你，就是靠注释读代码的"另一个人"。

## 3. 变量：定义与初始化

### 3.1 定义变量的语法

**变量定义（Variable Definition）**的通用格式：

```text
类型  变量名  =  初始值 ;
```

完整可运行示例：

```cpp
#include <iostream>

int main() {
    int    adc_raw   = 681;    // 定义并初始化：传感器原始读数（整数）
    double angle_deg = 90.0;   // 关节角度（小数）
    bool   motor_on  = true;   // 电机开关状态（真/假）
    char   axis      = 'A';    // 轴编号：单个字符用单引号包住

    std::cout << "adc_raw   = " << adc_raw   << "\n";
    std::cout << "angle_deg = " << angle_deg << "\n";
    std::cout << "motor_on  = " << motor_on  << "\n";   // bool 默认按 1/0 打印
    std::cout << "axis      = " << axis      << "\n";

    adc_raw = 700;             // 赋值（Assignment）：往同一个盒子里放新值
    std::cout << "adc_raw   = " << adc_raw   << "\n";   // 盒子里的值变了
    return 0;
}
```

预期输出：

```text
adc_raw   = 681
angle_deg = 90
motor_on  = 1
axis      = A
adc_raw   = 700
```

注意 `angle_deg = 90.0` 输出成了 `90`——`cout` 默认不显示无意义的小数尾零，值本身仍是 90.0。

**初始化（Initialization）**= 定义变量的同时给它第一个值。C++ 还有两种初始化写法，效果等价：

```text
int count = 0;      // 复制初始化（传统写法，本章用它）
int count(0);       // 直接初始化
int count{0};       // 列表初始化（C++11 起，最严格：禁止"悄悄丢精度"的转换）
```

推荐习惯：`int count{0}` 这种列表初始化在类型不符时会直接编译报错而不是悄悄转换，能拦住一类 bug；本目录正文用传统 `=` 写法方便阅读，你两种都认识即可。

### 3.2 不初始化的下场

```cpp
#include <iostream>

int main() {
    int total;                 // 只定义，没初始化：盒子里是"内存里碰巧残留的数"
    std::cout << "total = " << total << "\n";
    return 0;
}
```

预期输出（**不确定！**可能每次运行都不同，也可能是 0）：

```text
total = -1942125055
```

C++ 不帮你把新变量清零——它读到的可能是上一个程序留在内存里的"垃圾值"。用未初始化的变量做计算，错误会像多米诺一样传下去。

!!! warning "紫樱的忠告"
    变量如「一心净土」，初值即誓言：**定义的每一个变量，都在同一行给它初始值**。`int total = 0;` 比省这三个字符划算一万倍。

### 3.3 变量命名规则

**标识符（Identifier）**（变量、函数等名字的统称）的规则与习惯：

| 规则/习惯 | 合法示例 | 非法/糟糕示例 | 说明 |
|---|---|---|---|
| 只能由字母、数字、下划线组成 | `adc_raw` | `adc-raw`（连字符不行） | 硬性规则 |
| 不能以数字开头 | `raw2` | `2raw` | 硬性规则 |
| 不能用**关键字（Keyword）** | `int_count` | `int`、`double`（被语言占用） | 硬性规则 |
| 大小写敏感 | `Angle` 与 `angle` 是两个变量 | —— | 常见 bug 来源 |
| 见名知义，用下划线分词 | `angle_deg` | `a`、`aa1`、`x` | 习惯：小写+下划线 |
| 单位写进名字 | `angle_deg`、`time_ms` | `angle`（度还是弧度？） | 机器人开发保命习惯 |

## 4. 基本类型：给数据选对盒子

C++ 内置了几个**基本类型（Built-in Type）**。下表是 64 位平台（Windows/Linux x86-64）上的典型情况：

| 类型 | 名字 | 典型字节数 | 能表示的范围 | 有效数字 | 机器人场景举例 |
|---|---|---|---|---|---|
| `int` | 整型 | 4 | 约 -21.4亿 ~ +21.4亿 | —— | 循环计数、数组下标、ADC 原始值 |
| `long long` | 长整型 | 8 | 约 ±9.2×10^18 | —— | 编码器累计脉冲数（大整数） |
| `float` | 单精度浮点 | 4 | 约 ±3.4×10^38 | 约 7 位 | 图形/显卡接口、超大规模数据省内存 |
| `double` | 双精度浮点 | 8 | 约 ±1.8×10^308 | 约 15-16 位 | **角度、时间、电压——机器人计算首选** |
| `char` | 字符型 | 1 | -128 ~ 127 | —— | 单个字符：`'A'`、串口收到的字节 |
| `bool` | 布尔型 | 1 | 只有 `true` / `false` | —— | 开关量：急停是否按下、任务是否完成 |

两个关键词先说清楚：

- **浮点数（Floating-point）**就是"带小数点的数"在计算机里的存法（类比科学计数法：符号 × 尾数 × 10 的幂，只是底数是 2）。`float` 与 `double` 的区别是"尾数"位数不同，所以**有效数字（Significant Digits）**一个约 7 位、一个约 15-16 位。
- **字节（Byte）**是内存计量单位，1 字节 = 8 个二进制位。

想知道某个类型在你的机器上到底占几个字节？用 `sizeof` 直接量：

```cpp
#include <iostream>

int main() {
    std::cout << "int        : " << sizeof(int)        << " bytes\n";
    std::cout << "long long : " << sizeof(long long)  << " bytes\n";
    std::cout << "float      : " << sizeof(float)      << " bytes\n";
    std::cout << "double     : " << sizeof(double)     << " bytes\n";
    std::cout << "char       : " << sizeof(char)       << " bytes\n";
    std::cout << "bool       : " << sizeof(bool)       << " bytes\n";
    return 0;
}
```

预期输出（64 位 Windows / Ubuntu 均相同）：`int` 4、`long long` 8、`float` 4、`double` 8、`char` 1、`bool` 1（单位 bytes）。

`sizeof` 不是函数，是运算符：它在**编译期**就告诉你"这个类型占几个字节"。

### 4.1 类型选择建议

一张决策表，拿不准时回来查：

| 你要存的东西 | 用什么 | 为什么 |
|---|---|---|
| 角度、时间、电压、坐标 | `double` | 精度是机器人计算的生命线（见第 9 节） |
| 循环计数、数组下标 | `int` | 够用、最快、最常用 |
| 可能超过 21 亿的整数 | `long long` | 编码器累计脉冲、时间戳微秒数 |
| 和图形库/旧硬件接口交换数据 | `float` | 对方接口规定了 float，只好配合 |
| 单个字符、原始字节 | `char` | 一字节一字节地读串口时用 |
| 开关状态、条件结果 | `bool` | 只有两个值，语义清晰 |

!!! tip
    拿不准小数用 float 还是 double？**闭眼选 double**。它不比 float 慢多少，精度却是它的两倍多。只有"对方接口强制要 float"时才用 float。

## 5. 类型转换：隐式陷阱与 static_cast

不同类型的盒子之间，有时需要把东西挪来挪去。C++ 分两种挪法：**隐式转换（Implicit Conversion）**——编译器自作主张；**显式转换（Explicit Conversion）**——你亲自动手，写明意图。

```cpp
#include <iostream>

int main() {
    int    a = 3;
    double b = 2.7;

    double c = a + b;            // 隐式转换：a 被悄悄变成 3.0 再相加（int -> double 安全）
    std::cout << "c = " << c << "\n";     // 5.7

    int    d = b;                // 隐式转换：double -> int，直接砍掉小数部分！
    std::cout << "d = " << d << "\n";     // 2，不是四舍五入的 3！

    int    e = static_cast<int>(b);       // 显式转换：把"我要砍小数"写明白
    std::cout << "e = " << e << "\n";     // 2

    double f = static_cast<double>(a) / 2;   // 先把 a 变成 3.0，再除
    std::cout << "f = " << f << "\n";     // 1.5
    return 0;
}
```

预期输出：

```text
c = 5.7
d = 2
e = 2
f = 1.5
```

三条铁律：

1. **小类型 → 大类型（int → double）安全**，值不会损失；
2. **大类型 → 小类型（double → int）是"截断"不是"四舍五入"**：`3.9` 变 `3`，`-3.9` 变 `-3`（向零取整）；
3. 写 `static_cast<目标类型>(值)` 不会改变结果，但把转换意图亮在明处——审代码的人和未来的你，一眼看懂这是"故意的"。

!!! warning
    编译器对 `int d = b;` 这种丢精度的隐式转换通常只是"提醒"（警告），**不会拦住你**。加 `-Wall` 编译能多看到这些提醒——这就是为什么本目录一直推荐它。

> 📖 教材对照：C++ Primer 第5版 §2.1.2（类型转换）、§4.11（显式转换 static_cast）

## 6. const 常量：不许再改的盒子

**常量（Constant）**= 加了 `const`（constant，恒定的）修饰的变量：初始化之后，任何再赋值的企图都会被编译器当场拦下。

```cpp
#include <iostream>

int main() {
    const double kPi = 3.14159265358979;   // const：必须初始化，且之后不许改
    double r = 2.5;                        // 半径（cm）

    std::cout << "C = " << 2 * kPi * r << "\n";    // 周长
    std::cout << "S = " << kPi * r * r << "\n";    // 面积
    // kPi = 3.14;          // 若取消本行注释，编译直接报错：
                            // assignment of read-only variable 'kPi'
    return 0;
}
```

预期输出：

```text
C = 15.708
S = 19.635
```

为什么用 `const` 好处有三：

1. **防止手滑**：程序里圆周率、电压参考值、齿轮比这些"物理常数"被误改，是真实事故来源；
2. **表达意图**：读代码的人看到 `const` 就知道"这值永远不变"；
3. **集中管理**：改标定值只需改定义处一行，全文生效。

命名习惯：本目录对常量用 `k` 开头 + 大驼峰，如 `kPi`、`kVref`（k 是德语 Konstante 的传统，来自 C++ 之父们的代码习惯），你也可以用 `PI`、`V_REF` 等团队风格，**全组统一**比哪种风格更重要。

> 📖 教材对照：C++ Primer 第5版 §2.4（const 限定符）

## 7. 算术运算符与整除陷阱

常用**算术运算符（Arithmetic Operator）**：

| 运算符 | 含义 | 示例 | 结果 |
|---|---|---|---|
| `+` `-` | 加、减 | `7 - 2` | `5` |
| `*` | 乘 | `3 * 4` | `12` |
| `/` | 除 | 见下方陷阱 | —— |
| `%` | 取余数（**只对整数**有意义） | `7 % 3` | `1` |
| `()` | 括号：优先级谁也大不过它 | `(2 + 3) * 4` | `20` |

优先级与数学一致：先乘除后加减，同级从左到右。**不确定就加括号**，括号不要钱。

### 7.1 全章最大的坑：整数除法

```cpp
#include <iostream>

int main() {
    std::cout << 5 / 2     << "\n";   // 2   ！整数 / 整数 = 整数，小数被砍掉
    std::cout << 5 % 2     << "\n";   // 1   % 取余数：5 = 2*2 + 1
    std::cout << 5.0 / 2.0 << "\n";   // 2.5 只要有小数参与，才是真除法
    std::cout << -7 / 2    << "\n";   // -3  向零取整（不是向下取整的 -4）
    std::cout << -7 % 2    << "\n";   // -1  余数符号跟被除数一致
    return 0;
}
```

预期输出：

```text
2
1
2.5
-3
-1
```

**`5 / 2 == 2`**：C++ 规定，两个 `int` 相除，结果还是 `int`，小数部分直接丢弃。这不是 bug，是规则——但对入门者是全章最阴的一招。想得到 2.5，任选其一：

```text
5.0 / 2        // 除数或被除数任一写成小数
5 / 2.0
static_cast<double>(5) / 2     // 变量场景：先转 double 再除
```

`%`（**取模/取余，Modulo**）在机器人里意外地好用：判断"读数是不是偶数"（`raw % 2 == 0`）、把秒数拆成"几分几秒"（`s % 60`）、随机数取范围（第 20 章见）。

## 8. 输入输出：cin 与 cout

程序要"活"，就得跟外界交换数据。`cout` 负责**输出**到屏幕，`cin` 负责**输入**——从键盘把数据读进变量。

### 例 1：输入一个数，输出它的两倍

```cpp
#include <iostream>

int main() {
    int raw = 0;                       // 先初始化，等下被输入覆盖
    std::cout << "input raw ADC value: ";
    std::cin >> raw;                   // >>：把键盘输入"抽"进变量 raw
    std::cout << "raw * 2 = " << raw * 2 << "\n";
    return 0;
}
```

运行示例：键盘输入 `681`，输出 `raw * 2 = 1362`。

方向记忆法：`cout <<` 把数据**推出**程序流向屏幕；`cin >>` 把数据**拉进**程序存入变量。箭头指向哪儿，数据就往哪儿流。

### 例 2：连续输入两个数

```cpp
#include <iostream>

int main() {
    double a = 0.0, b = 0.0;           // 一行定义两个同类型变量
    std::cout << "input two numbers: ";
    std::cin >> a >> b;                // 连续读取：空格或回车分隔均可
    std::cout << a << " + " << b << " = " << a + b << "\n";
    return 0;
}
```

运行示例：输入 `3 4.5`（回车），输出 `3 + 4.5 = 7.5`。

`cin >> a >> b` 会自动跳过空格和换行，所以 `3 4.5` 和 `3↵4.5` 都能正确读入。同样地，`<<` 可以一路串下去：字符串、变量、算式随便混排，编译器按顺序把每个东西送到屏幕。

> 📖 教材对照：C++ Primer 第5版 §1.2（初识输入输出）

## 9. 和机器人有什么关系：精度与换算

这是本章的"挂钩专节"——两个真实机器人开发中天天遇到的问题。

### 9.1 关节角度为什么用 double 不用 float？

先看实验，再讲道理：

```cpp
#include <iostream>
#include <iomanip>                   // setprecision 在这个头文件里

int main() {
    float  fa = 0.1f;                // float 字面量要加 f 后缀
    double da = 0.1;                 // double 字面量直接写

    std::cout << std::setprecision(10);      // 显示 10 位有效数字
    std::cout << "float  0.1f -> " << fa << "\n";
    std::cout << "double 0.1   -> " << da << "\n";
    return 0;
}
```

预期输出：

```text
float  0.1f -> 0.1000000015
double 0.1   -> 0.1
```

看到了吗？你想存的 0.1，`float` 实际存成 `0.1000000015...`。原因：十进制的 0.1 在二进制里是无限循环小数，而 `float` 只能存约 7 位有效数字，误差被截在这里；`double` 有约 15-16 位，十进制打印时看不出来。

这对机器人意味着什么？机械臂关节角以"度"为单位累积运算：0.1 度的表示误差，经过 20 个关节的坐标变换、数小时的连续控制循环，误差会**不断累加放大**——末端执行器可能偏离目标好几个毫米。工业现场毫米就是合格与报废的区别。

所以行业惯例是：

- **控制、规划、运动学的所有实数一律 `double`**；
- ROS2 的消息定义（位姿 `geometry_msgs::msg::Pose`、速度 `Twist` 等）内部字段全是 64 位 double；
- `float` 只出现在"对方接口规定要用"的场合（如显卡渲染、某些嵌入式库）。

### 9.2 传感器原始读数 int → 物理量 double 的换算

传感器芯片吐出来的永远是整数。以最经典的 ADC（**模数转换器，Analog-to-Digital Converter**）为例：10 位 ADC 把 0~3.3 V 的电压量化成 0~1023 的整数——这个整数叫**原始读数（Raw Value）**，它要乘一个**比例系数（Scale Factor）**才能还原成物理量。

```cpp
#include <iostream>

int main() {
    const double kVref    = 3.3;      // ADC 参考电压（V）
    const double kFullRaw = 1023.0;   // 10 位 ADC 最大读数（2^10 - 1）
    const double kV0      = 27.0;     // 红外测距模块经验系数（V·cm），示意用

    int raw = 0;
    std::cout << "input raw ADC value (0-1023): ";
    std::cin >> raw;                            // ① 原始读数：整数

    double voltage = raw * kVref / kFullRaw;    // ② int 参与浮点运算，自动升为 double
    double distance_cm = kV0 / voltage;         // ③ 简化测距公式（示意）

    std::cout << "voltage  = " << voltage << " V\n";
    std::cout << "distance = " << distance_cm << " cm\n";
    return 0;
}
```

运行示例（输入 `681`）：

```text
input raw ADC value (0-1023): 681
voltage  = 2.19648 V
distance = 12.2925 cm
```

逐条对应本章知识点：

- 原始读数是整数，**必须用 `int`**——芯片给的就是整数；
- 换算用 `double` + `const` 比例系数：`raw * kVref` 里 int 自动升为 double（安全的隐式转换）；
- 除法里 `kFullRaw` 写成 `1023.0`，避开"整除陷阱"；
- 变量名带单位（`voltage`、`distance_cm`），一眼看懂物理意义。

!!! warning
    这个例程里 `voltage` 很小时 `distance_cm` 会算出荒谬的大数。真实驱动代码一定有"限幅与合理性检查"——那需要 `if` 判断，正是第 20 章的内容。先记住这个悬念。

> 📖 教材对照：C++ Primer 第5版 §2.1.1（浮点类型的精度差异）

## 10. 调试入门：cout 打印法

**调试（Debugging）**= 找出程序里 bug 的过程。初学阶段最朴素也最有效的武器：**在可疑的地方插入 `cout`，把中间变量的值打出来看**。

先制造一个 bug——求两次读数的平均值，结果却不对：

```cpp
#include <iostream>

int main() {
    int reading1 = 1;
    int reading2 = 2;
    double avg = (reading1 + reading2) / 2;    // 目测：(1+2)/2 = 1.5？
    std::cout << "avg = " << avg << "\n";
    return 0;
}
```

实际输出：

```text
avg = 1
```

为什么是 1？用三步打印法定位：

```cpp
#include <iostream>

int main() {
    int reading1 = 1;
    int reading2 = 2;

    int total = reading1 + reading2;
    std::cout << "[debug] total = " << total << "\n";    // 第 1 刀：加法对不对？

    double avg = total / 2;
    std::cout << "[debug] avg raw = " << avg << "\n";    // 第 2 刀：除法对不对？

    double avg2 = total / 2.0;                 // 修复：除以 2.0 触发浮点除法
    std::cout << "avg = " << avg2 << "\n";
    return 0;
}
```

预期输出：

```text
[debug] total = 3
[debug] avg raw = 1
avg = 1.5
```

第 1 刀显示 `total = 3`，加法没问题；第 2 刀显示 `avg = 1`——问题锁定在**整数除法**（第 7 节的陷阱）。除以 `2.0` 修复。确认无误后，把 `[debug]` 行删掉或注释掉即可。

打印法三步诀：

1. 在"我以为值应该是 X"的地方，打印它；
2. 对比"我以为"和"实际打印"，找到第一个分叉点；
3. 分叉点所在的那一两行，就是 bug 藏身处。

!!! tip
    等你学完本目录，还有 `gdb` 调试器（可逐行执行、查看变量，上一章已装好）等更高级的工具。但 cout 打印法永远不过时——职业工程师也在用。

## 11. 常见错误与自救

| 错误现象 | 原因 | 怎么改 |
|---|---|---|
| `error: expected ';' before '}'` | 上一行漏分号 | 在报错位置的上一行找漏掉的分号 |
| `error: 'total' was not declared in this scope` | 变量名拼错，或用了没定义的变量 | 核对拼写；确认变量已定义且在作用域内 |
| `error: invalid conversion from 'double' to 'int'` | 大类型塞进小类型且写法被编译器拒绝 | 改用 `static_cast<int>(...)` 表明故意截断 |
| 除法结果总是 0 或整数 | 整数除法陷阱（`5/2==2`） | 除数或被除数写成小数，或 `static_cast<double>` |
| 变量值"莫名其妙"每次运行不同 | 使用了未初始化变量 | 定义时就初始化 |
| `cout` 输出中文变乱码 | 源文件/终端编码不一致 | 源文件存 UTF-8；Windows 终端先 `chcp 65001` |
| `error: stray '\357' in program` | 源码里混入了中文标点（，；""） | 报错行附近把中文标点改成英文标点 |
| 输入字母程序就"疯了" | `cin >> int` 遇到非数字输入会失败 | 本阶段避免输入非法数据；健壮输入后面章节讲 |

## 12. 动手练习

先自己写、编译、跑，再展开解答对照。

**练习 1**：输入总秒数（整数），输出"几小时几分几秒"。例如输入 `7385`，输出 `2 h 3 min 5 s`。

??? details "练习 1 解答"

    ```cpp
    #include <iostream>

    int main() {
        int total_sec = 0;
        std::cout << "input total seconds: ";
        std::cin >> total_sec;

        int hours = total_sec / 3600;        // 整数除法在这里是"特性"不是陷阱
        int mins  = total_sec % 3600 / 60;   // 先去掉整小时，再除 60 取分钟
        int secs  = total_sec % 60;          // 余下的就是秒

        std::cout << hours << " h " << mins << " min " << secs << " s\n";
        return 0;
    }
    ```

    运行示例：输入 `7385`，输出 `2 h 3 min 5 s`。

    要点：这次我们**主动利用**整数除法和 `%` 做拆分——同一个知识点，正着用是陷阱，反着用是工具。验证：7385 = 2×3600 + 3×60 + 5。

**练习 2**：输入华氏温度 F，输出摄氏温度 C。公式：C = 5/9 × (F − 32)。输入 `100`，输出应约 `37.7778`。

??? details "练习 2 解答"

    ```cpp
    #include <iostream>

    int main() {
        double f = 0.0;
        std::cout << "input Fahrenheit: ";
        std::cin >> f;

        double c = 5.0 / 9.0 * (f - 32.0);   // 5.0/9.0：写成 5/9 就整除成 0 了！
        std::cout << "Celsius = " << c << "\n";
        return 0;
    }
    ```

    运行示例：输入 `100`，输出 `Celsius = 37.7778`。

    要点：`5/9` 用整数写会得到 `0`，整个结果归零——这是本章陷阱的实战重现。物理公式里出现分数，一律写成小数形式。

**练习 3**：改造第 9.2 节的 ADC 程序：换成 12 位 ADC（最大读数 4095）、参考电压 5.0 V。输入 `2048`，输出电压应约 `2.50183` V。

??? details "练习 3 解答"

    ```cpp
    #include <iostream>

    int main() {
        const double kVref    = 5.0;      // 参考电压换成 5V 系统
        const double kFullRaw = 4095.0;   // 12 位 ADC：2^12 - 1

        int raw = 0;
        std::cout << "input raw ADC value (0-4095): ";
        std::cin >> raw;

        double voltage = raw * kVref / kFullRaw;
        std::cout << "voltage = " << voltage << " V\n";
        return 0;
    }
    ```

    运行示例：输入 `2048`，输出 `voltage = 2.50183 V`。

    要点：换硬件只改两个 `const` 常量，逻辑一行不动——这就是常量集中管理的价值。

**练习 4（找 bug）**：下面程序想算 3 次读数的平均值，结果却输出 `2`。找出所有问题并修复：

```cpp
#include <iostream>

int main() {
    int total;
    double avg = total / 3;
    total = 1 + 2 + 3;
    std::cout << "avg = " << avg << "\n";
    return 0;
}
```

??? details "练习 5 解答"

    两个 bug：

    1. **未初始化**：`total` 定义时没赋值，第一行使用它时读到的是内存垃圾；
    2. **整数除法**：`total / 3` 是 int 除 int，`6 / 3 = 2` 本例侥幸对，但若总和是 7 就会得 2（应为 2.33333）。

    修复版：

    ```cpp
    #include <iostream>

    int main() {
        int total = 1 + 2 + 3;                     // 初始化：先算好总和
        double avg = static_cast<double>(total) / 3;   // 显式转 double 再除
        std::cout << "avg = " << avg << "\n";
        return 0;
    }
    ```

    预期输出：

    ```text
    avg = 2
    ```

    本例总和恰好是 3 的倍数所以答案仍是 2；把数据改成 `1 + 2 + 4` 再试，原版输出 `2`（错），修复版输出 `2.33333`（对）——请务必动手验证这一次。

## 本章速查卡

| 语法 | 示例 | 说明 |
|---|---|---|
| 变量定义并初始化 | `double angle_deg = 90.0;` | 每个变量定义必给初值 |
| 列表初始化 | `int count{0};` | C++11，禁止悄悄丢精度 |
| 常量 | `const double kPi = 3.14159;` | 初始化后不可修改 |
| 整数除法 | `5 / 2` → `2` | int / int 还是 int，砍小数 |
| 真除法 | `5.0 / 2` → `2.5` | 有小数参与才行 |
| 取余 | `7 % 3` → `1` | 仅整数；符号随被除数 |

| 输出 | `std::cout << "x=" << x << "\n";` | `<<` 链式串联 |
| 输入 | `std::cin >> raw;` | 空格/回车分隔均可 |
| 控制精度 | `std::setprecision(10)` | 需 `#include <iomanip>` |
| 查字节数 | `sizeof(double)` → `8` | 编译期运算符 |
