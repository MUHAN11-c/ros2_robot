## 1. 从生活到概念：程序不是直线跑道

任何程序都由三种基本结构拼成：**顺序**（一句接一句，前两章全是它）、**分支**（走到岔路口按条件选路：下雨带伞，晴天戴帽）、**循环**（同一段路反复走直到条件不满足：上下刷，直到两分钟到）。

**控制流（Control Flow）**就是程序在语句之间"走位"的方式。类比在哪里失效？生活里人类靠常识选路，程序里每条岔路都必须**亲手写清判断条件**——漏写一条，机器人就敢直挺挺撞上去。

## 2. if 与 else：给程序装上红绿灯

### 2.1 基本形态

```cpp
#include <iostream>

int main() {
    double distance = 7.5;              // 前方障碍距离（cm），先直接写死

    if (distance < 10.0) {              // 条件为真 → 执行花括号里的语句
        std::cout << "DANGER: stop!\n";
    } else {                            // 条件为假 → 走这里
        std::cout << "SAFE: keep going\n";
    }
    return 0;
}
```

预期输出：`DANGER: stop!`

`if` 括号里是一个**条件（Condition）**，值只有真/假两种。写条件用**比较运算符（Comparison Operator）**和**逻辑运算符（Logical Operator）**：

| 运算符 | 含义 | 示例 | 结果 |
|---|---|---|---|
| `==` | 等于（两个等号！） | `5 == 5` | true |
| `!=` | 不等于 | `5 != 3` | true |
| `<` `>` 与 `<=` `>=` | 小于/大于；小于等于/大于等于 | `7 < 3`、`8 >= 8` | false、true |
| `&&` | 与：两边**都**真才真 | `(5 > 3) && (2 > 1)` | true |
| `\|\|` | 或：一边真即真 | `(5 < 3) \|\| (2 > 1)` | true |
| `!` | 非：真假取反 | `!(5 > 3)` | false |

`&&` 和 `||` 有个贴心行为叫**短路求值（Short-circuit Evaluation）**：`&&` 左边是假时右边根本不算（结果注定假），`||` 左边是真时同样偷懒。多分支用 `else if` 串联：自上而下逐个检查，命中即止，最后的 `else` 兜底——适合互斥档位，如"电量充足全速 / 低电量节能 / 电量告急返航"。

### 2.2 嵌套与悬空 else

`if` 里面可以再套 `if`，叫**嵌套（Nesting）**。但嵌套藏着一个著名的坑——**悬空 else（Dangling Else）**：

```cpp
#include <iostream>

int main() {
    int mode = 1;              // 1 = 巡线
    bool fault = false;        // 无故障
    if (mode == 1)
        if (fault)             // 缩进是骗人的！
            std::cout << "with fault check\n";
    else                       // 你以为它配外面的 if？错！
        std::cout << "idle\n";
    return 0;
}
```

预期输出：`idle`

意外吧？`mode == 1` 明明成立，却打印了 `idle`。规则：**`else` 永远配对离它最近的、还没有 else 的 `if`**——它跟的是里层的 `if (fault)`。缩进只是给人看的，编译器根本不看缩进。修复只有一个办法：**永远给 if/else 写花括号**——外层写成 `if (mode == 1) { if (fault) {...} } else {...}` 后，`else` 就只能属于外层，本例 mode 为巡线时什么都不打印。

### 2.3 全章第二大的坑：`=` 手滑写成 `==`

!!! warning
    一个等号是**赋值（Assignment）**（把 true 放进盒子），两个等号才是**比较**（盒子里的值等于 true 吗）。`if (running = true)` 会把 true 存进 running，条件恒为真，变量还被偷偷改掉——`g++ -Wall` 会点名这种写法，这是坚持 `-Wall` 的又一个理由。

> 📖 教材对照：C++ Primer 第5版 §5.3.1（if 语句与悬垂 else）

## 3. switch：多路分岔的信号灯

变量只有少数几种"档位"（模式编号、菜单选项）时，`switch` 比一长串 `else if` 清爽：

```cpp
#include <iostream>

int main() {
    const int kIdle  = 0;        // 模式编号用 const int 常量，消灭"魔法数字"
    const int kLine  = 1;        // （魔法数字：代码里凭空出现的裸数字）
    const int kAvoid = 2;

    int mode = kLine;            // 当前模式：巡线

    switch (mode) {              // 按 mode 的值跳到对应 case
        case kIdle:
            std::cout << "IDLE: motors off\n";
            break;               // break：跳出 switch
        case kLine:
            std::cout << "LINE: follow the black line\n";
            break;
        case kAvoid:
            std::cout << "AVOID: turn left 90 deg\n";
            break;
        default:                 // 上面所有 case 都没接住时走这里
            std::cout << "UNKNOWN mode\n";
            break;
    }
    return 0;
}
```

预期输出：`LINE: follow the black line`

三条规则：`case` 后必须是**编译期常量**（`const int`、字面值都行，普通变量不行）；每个 case 末尾写 `break`；永远写 `default` 兜底。`break` 不能省——忘了它，程序会从命中的 case 一路"漏"到底，后面所有 case 全部执行，这叫**穿透（Fall-through）**：把 `mode` 改成 0 并删掉所有 break，输出会变成 `IDLE`、`LINE`、`AVOID` 三行连发。

> 📖 教材对照：C++ Primer 第5版 §5.3.2（switch 语句）

## 4. 循环：while、do-while 与 for

### 4.1 while 与循环三要素

```cpp
#include <iostream>

int main() {
    int count = 3;                 // ① 初始化：循环开始前备好变量

    while (count > 0) {            // ② 条件：为真才继续；为假就跳出
        std::cout << "T-" << count << "\n";
        count = count - 1;         // ③ 更新：朝"条件变假"的方向推进
    }
    std::cout << "LAUNCH\n";
    return 0;
}
```

预期输出：`T-3`、`T-2`、`T-1`、`LAUNCH` 各一行。

**循环三要素**：初始化、条件、更新，缺一不可（像开荒配队：初始化是配队、条件是体力条、更新是回体力）。忘了更新，体力永远不减、队伍永远刷下去——这就是死循环。

顺带认识省字符号：`count -= 1` 等价于 `count = count - 1`（**复合赋值运算符**还有 `+=`、`*=`、`/=`、`%=`）；`++count`（自增）等价于 `count += 1`，`--count` 等价于 `count -= 1`。单独成句时 `++count` 与 `count++` 效果相同，本目录统一用 `++count`。

### 4.2 for：把三要素排成一排

```cpp
#include <iostream>

int main() {
    for (int count = 3; count > 0; --count) {   // ①初始化; ②条件; ③更新
        std::cout << "T-" << count << "\n";
    }
    std::cout << "LAUNCH\n";
    return 0;
}
```

预期输出：与 4.1 逐拍相同。与 while 版本完全等价，经验法则：**已知循环几次 → for；"直到某事发生才停" → while**。

### 4.3 do-while：先斩后奏

`do-while` 先执行一次循环体，**再**判断条件——适合"至少要做一次"的场景（反复索要合法输入）：

```cpp
#include <iostream>

int main() {
    int battery = -1;
    do {                                    // 先干一次
        std::cout << "battery percent (0-100): ";
        std::cin >> battery;
    } while (battery < 0 || battery > 100); // 输入不合法 → 回到 do 再问一遍

    std::cout << "battery = " << battery << "\n";
    return 0;
}
```

运行示例：输入 `-5`，它再问一遍；输入 `80`，输出 `battery = 80`。

三种循环何时用哪个：

| 循环 | 执行顺序 | 典型场景 |
|---|---|---|
| `for` | 先判断后执行 | 已知次数：遍历 0~1023、跑 100 个控制拍 |
| `while` | 先判断后执行 | 未知次数：直到距离小于 10 cm 为止 |
| `do-while` | 先执行后判断 | 至少一次：反复索要合法输入 |

> 📖 教材对照：C++ Primer 第5版 §5.4.1（while）、§5.4.2（传统 for）、§5.4.4（do while）

### 4.4 break 与 continue：循环的刹车和跳步

```cpp
#include <iostream>

int main() {
    for (int i = 1; i <= 10; ++i) {
        if (i % 2 == 0) {
            continue;            // 偶数：跳过下面的打印，直接 ++i 进下一轮
        }
        if (i > 7) {
            break;               // 超过 7：整个循环到此为止
        }
        std::cout << i << " ";
    }
    std::cout << "\n";
    return 0;
}
```

预期输出：`1 3 5 7`

### 4.5 无限循环：机器人程序的常态

条件恒真的**死循环（Infinite Loop）**听起来像事故，其实是机器人主循环的常态——机器人本来就该一直"读-算-写"直到断电。关键在于"由谁决定退出"：或循环体里 `break`，或像第 8 节那样用 `bool running` 标志；失控的死循环（忘了更新条件）靠终端 `Ctrl + C` 强制终止——它是每位开发者的紧急逃生口，人人都需要。

> 📖 教材对照：C++ Primer 第5版 §5.5.1（break）、§5.5.2（continue）

## 5. 函数：把一段代码装进工具箱

**函数（Function）**= 起了名字、可以反复调用的一段代码。好处：**不复制粘贴**（改一处全生效）、**起名即注释**（`wheel_cm(10, 6.4)` 一眼看懂）、**分解问题**（大程序拆成小工具）。

### 5.1 定义、形参与实参

```cpp
#include <iostream>

// 函数定义：返回类型 double，函数名 wheel_cm，形参表 (double rpm, double diameter_cm)
double wheel_cm(double rpm, double diameter_cm) {
    const double kPi = 3.14159265358979;
    double circumference = kPi * diameter_cm;   // 轮子转一圈的距离（cm）
    return rpm * circumference;                 // return：把结果交还给调用者
}

int main() {
    double cm = wheel_cm(10.0, 6.4);    // 调用：转速 10 转/分，轮径 6.4 cm
    std::cout << "distance = " << cm << " cm/min\n";
    return 0;
}
```

预期输出：`distance = 201.062 cm/min`

定义四要素：**返回类型**（不返回任何值用 `void`）→ **函数名** → **形参表** → **函数体**。`return` 把结果交回调用处并立刻结束本函数。**形参（Parameter）**与**实参（Argument）**要分清：

| 概念 | 本例中 | 出现位置 | 什么时候有值 |
|---|---|---|---|
| 形参 | `rpm`、`diameter_cm` | 函数定义的括号里 | 定义时只是"占位的名单" |
| 实参 | `10.0`、`6.4` | 调用处括号里 | 调用时才填入真值 |

### 5.2 函数声明与头文件初见

编译器从上往下读文件：如果函数定义在 `main` 之后，编译器读到调用处还不认识它，会报 `error: 'wheel_cm' was not declared in this scope`。解决办法是**函数声明（Function Declaration）**——先递"名片"（只有签名没有函数体），定义可以晚点给。名片多了放哪？**头文件（Header File）**。真实工程都是"声明进头文件、定义进源文件"的三件套，完整走一遍（三个文件放同一目录）：

**文件 1：`math_utils.h`**（声明住这里）

```cpp
#ifndef MATH_UTILS_H        // 头文件保护符：防止头文件被重复包含
#define MATH_UTILS_H

double wheel_cm(double rpm, double diameter_cm);   // 只有名片，没有函数体

#endif
```

**文件 2：`math_utils.cpp`**（定义住这里）

```cpp
#include "math_utils.h"     // 包含自己的头文件，让编译器核对声明与定义一致

double wheel_cm(double rpm, double diameter_cm) {  // 本体
    const double kPi = 3.14159265358979;
    return rpm * kPi * diameter_cm;
}
```

**文件 3：`main.cpp`**（使用者）

```cpp
#include <iostream>
#include "math_utils.h"     // 双引号：当前目录找；尖括号 <>：标准库目录找

int main() {
    std::cout << wheel_cm(10.0, 6.4) << "\n";
    return 0;
}
```

多个源文件一起编译（**分离式编译（Separate Compilation）**：每个 .cpp 独立编译，最后链接拼装），运行后预期输出 `201.062`：

```bash
g++ -Wall main.cpp math_utils.cpp -o wheel_app && ./wheel_app
```

`#include` 的本质是**复制粘贴**：编译前，预处理器把头文件内容原样粘到 include 那一行。ROS2 节点开头一大串 `#include "rclcpp/rclcpp.hpp"`，粘的就是整个 ROS2 的工具箱清单。

> 📖 教材对照：C++ Primer 第5版 §6.1.2（函数声明）、§6.1.3（分离式编译）、§2.6.3（编写自己的头文件）

### 5.3 局部变量与作用域

**作用域（Scope）**= 名字"有效"的代码区域：从定义处开始，到它所在那对花括号的 `}` 为止。

```cpp
#include <iostream>

int main() {
    int outer = 1;                // 作用域：到 main 的右花括号为止
    {                             // 手工开一对花括号造一个"小房间"
        int inner = 2;            // 作用域：只到小房间的右花括号
        std::cout << "inner = " << inner << "\n";   // 在房间里，可用
    }
    std::cout << "outer = " << outer << "\n";       // main 里，可用
    // std::cout << inner;        // 房间已塌（出了作用域），取消注释会编译报错
    return 0;
}
```

预期输出：`inner = 2` 与 `outer = 2` 两行。

函数体内定义的**局部变量（Local Variable）**：每次调用都新开一批，函数结束全部销毁。所以"函数改了自己的局部变量"对外面**毫无影响**——这就引出下一节。

### 5.4 值传递：函数拿到的是复印件

```cpp
#include <iostream>

void try_swap(int a, int b) {    // 形参 a、b 是实参的"复印件"（值传递）
    int tmp = a;                 // 经典三步交换
    a = b;
    b = tmp;                     // 但换的只是复印件，原件毫发无损
}

int main() {
    int left = 1, right = 9;
    try_swap(left, right);       // 把实参的"值"复印一份传进去
    std::cout << "left = " << left << ", right = " << right << "\n";
    return 0;
}
```

预期输出：`left = 1, right = 9`

**值传递（Pass by Value）**：调用时把实参的值复制一份给形参，函数里怎么折腾都是复印件的事。想真改原件？**引用传递**是第 40 章《指针、引用与内存模型》的主角，本章先把"复印件规则"刻进脑子。

> 📖 教材对照：C++ Primer 第5版 §6.2.1（传值参数）

### 5.5 默认实参

形参可以带默认值：调用时不给就用默认，给了就覆盖。

```cpp
#include <iostream>

// P 控制（比例控制）：控制量 = 增益 × 误差；增益不指定时用 0.5
double p_control(double error, double gain = 0.5) {
    return gain * error;
}

int main() {
    std::cout << p_control(2.0)      << "\n";   // 不给 gain → 用默认 0.5
    std::cout << p_control(2.0, 0.1) << "\n";   // 手动给 0.1
    return 0;
}
```

预期输出：`1` 与 `0.2` 两行。规则一条：**默认实参必须从最右边开始连续给**——`f(int a = 1, int b)` 非法，因为 `f(3)` 说不清 3 该给谁。

> 📖 教材对照：C++ Primer 第5版 §6.5.1（默认实参）

### 5.6 函数重载初见

同一个名字，按**参数类型**准备多个版本，编译器自动挑——**函数重载（Function Overloading）**：

```cpp
#include <iostream>

void print_value(int v) {        // 版本 1：收 int
    std::cout << "int    : " << v << "\n";
}

void print_value(double v) {     // 版本 2：收 double，同名不同参
    std::cout << "double : " << v << "\n";
}

int main() {
    print_value(3);              // 实参是 int → 挑版本 1
    print_value(3.0);            // 实参是 double → 挑版本 2
    return 0;
}
```

预期输出：`int    : 3` 与 `double : 3` 两行。注意：**只有返回类型不同、参数完全一样，不构成重载**。ROS2 源码里大量重载，现在你有了读懂它们的门票。

> 📖 教材对照：C++ Primer 第5版 §6.4（函数重载）

## 6. 递归：函数调用自己

**递归（Recursion）**= 函数在自己的函数体里调用自己。写递归只需回答两个问题：**递归出口（Base Case）**——什么情况不必再递归、直接给答案（没有出口 = 无限套娃）；**递归步**——怎么把规模 n 的问题化成规模更小的同类问题。

### 6.1 阶乘：n! = n × (n-1) × … × 1

```cpp
#include <iostream>

int factorial(int n) {
    if (n <= 1) {                  // ① 出口：1! = 1（0! 也定义为 1）
        return 1;
    }
    return n * factorial(n - 1);   // ② 递归步：n! = n × (n-1)!
}

int main() {
    std::cout << "5! = " << factorial(5) << "\n";
    return 0;
}
```

预期输出：`5! = 120`

逐层演算 `factorial(5)`——先"往下钻"（问题每次缩小 1），到出口后"往回收"（答案逐层乘回来）。这两步合起来就是**调用栈（Call Stack）**的文字版：每调用一次压一层现场记录，return 时逐层弹出：

```text
往下钻：factorial(5) = 5 × factorial(4) = 4 × factorial(3) = 3 × factorial(2) = 2 × factorial(1) → 1（出口！）
往回收：factorial(1)=1 → factorial(2)=2×1=2 → factorial(3)=3×2=6 → factorial(4)=4×6=24 → factorial(5)=5×24=120
```

### 6.2 斐波那契：一题两解的警示

斐波那契数列：第 1、2 项是 1，之后每项 = 前两项之和。

```cpp
#include <iostream>

int fib(int n) {
    if (n == 1 || n == 2) {        // 出口：前两项都是 1
        return 1;
    }
    return fib(n - 1) + fib(n - 2);   // 递归步：两项相加（注意：调用了自己两次！）
}

int main() {
    for (int i = 1; i <= 8; ++i) {     // 打印前 8 项
        std::cout << fib(i) << " ";
    }
    std::cout << "\n";
    return 0;
}
```

预期输出：`1 1 2 3 5 8 13 21`

画一下 `fib(5)` 的调用树，会发现大量重复劳动：

```text
fib(5)
├─ fib(4)
│  ├─ fib(3)
│  │  ├─ fib(2) → 1
│  │  └─ fib(1) → 1
│  └─ fib(2) → 1        ← fib(2) 第 2 次算
└─ fib(3)               ← fib(3) 第 2 次算！
   ├─ fib(2) → 1        ← fib(2) 第 3 次算
   └─ fib(1) → 1
```

n 越大重复越夸张（`fib(50)` 用这种写法能慢到怀疑人生）。第 30 章学过容器后，你就能用"循环 + 表格"把重复计算全省掉。本阶段底线：**会写、会手推、知道它可能慢**。

!!! warning
    递归没有出口，调用栈会一层层压到爆掉，报 `Segmentation fault`（**栈溢出，Stack Overflow**）——编程问答网站 stackoverflow.com 的名字就是玩这个梗。

> 📖 教材对照：C++ Primer 第5版 §6.3（返回类型与 return 语句，含递归）

## 7. 综合小例：随机游走模拟传感器漂移

机器人常用随机数做两件事：给仿真加噪声、模拟**漂移（Drift）**——惯性传感器每次测量差一点点，误差不断累积，读数慢慢"游"离真值。工具在 `<cstdlib>` / `<ctime>` 里：`rand()` 返回 0 ~ RAND_MAX 的伪随机整数（`rand() % n` 压到 0 ~ n-1，除余数有轻微不均匀，初学够用；工程上用 C++11 的 `<random>` 更规范）；`srand(seed)` 设定**随机种子（Random Seed）**——同一种子生成同一序列，种子用当前时间 `time(0)` 则每次运行都不同。

```cpp
#include <iostream>
#include <cstdlib>   // rand()、srand()
#include <ctime>     // time()

int main() {
    srand(static_cast<unsigned>(time(0)));   // 用当前时间做种子

    const double kTrueValue = 25.0;   // 真实温度：25 摄氏度
    double drift = 0.0;               // 累计漂移，从 0 开始（"随机游走"的位置）

    std::cout << "step  reading(degC)  drift\n";
    for (int step = 1; step <= 6; ++step) {
        int noise = rand() % 21 - 10;        // 随机整数，范围 [-10, 10]
        drift += noise / 1000.0;             // 每步漂移 ±0.01 度以内，且不断累积
        std::cout << step << "    " << kTrueValue + drift
                  << "          " << drift << "\n";
    }
    return 0;
}
```

预期输出（**每次运行都不同**，下面是一次真实运行的结果）：

```text
step  reading(degC)  drift
1    25.003          0.003
2    24.998          -0.002
3    25.012          0.012
4    25.006          0.006
5    24.991          -0.009
6    25.001          0.001
```

抓一个物理直觉：单步噪声很小（±0.01 度），但**它没有"回家的引力"**——几步之后漂到哪儿全看运气；真实惯导几十分钟能漂出几度，工程上必须靠滤波/标定补偿。另外 `noise / 1000.0` 的除数写成小数，又一次躲开整除陷阱。

## 8. 和机器人有什么关系：主循环与状态机

本章两大新能力（循环、分支），恰好是机器人软件的心脏和神经。

### 8.1 控制主循环：机器人的心跳

几乎所有机器人控制程序都长成一个模子——循环里反复做三件事：**读传感器 → 算控制量 → 写电机**。这就是**闭环控制（Closed-loop Control）**的最小骨架（"闭环"：把输出测回来，比较目标，不断修正）：

```cpp
#include <iostream>

int main() {
    bool running = true;           // 运行标志：真实机器人上由急停/超时/上位机指令改它
    int tick = 0;                  // 控制拍计数
    const double kTarget = 96.0;   // 目标角度（度）
    double angle = 0.0;            // 当前角度（从传感器来）

    while (running) {              // 机器人的"一生"就在这几行里循环
        ++tick;
        // ① 读传感器（真实机器人：读编码器/IMU/测距模块；这里用模拟值）
        double measured = angle;
        // ② 算控制量：误差 = 目标 - 实测；控制量按误差比例给（P 控制雏形）
        double error = kTarget - measured;
        double command = 0.5 * error;
        // ③ 写电机（真实机器人：下发电流/速度指令；这里模拟关节转过 command 度）
        angle = angle + command;

        std::cout << "tick " << tick << "  angle = " << angle << "\n";
        if (tick >= 8) {           // 演示版靠它停下；真实程序可能连跑几天几夜
            running = false;       // 标志改假 → while 条件失效 → 循环结束
        }
    }
    std::cout << "loop exited after " << tick << " ticks\n";
    return 0;
}
```

预期输出：

```text
tick 1  angle = 48
tick 2  angle = 72
tick 3  angle = 84
tick 4  angle = 90
tick 5  angle = 93
tick 6  angle = 94.5
tick 7  angle = 95.25
tick 8  angle = 95.625
loop exited after 8 ticks
```

看数据：误差每拍减半（96 → 48 → 24 → …），角度一步步逼近 96 度——这就是"反馈让系统收敛"的直观版。真实 ROS2 程序里这个循环通常由定时器回调驱动（框架替你管循环），但"读-算-写"的三段式心跳一模一样。

### 8.2 状态机：switch 处理机器人模式

机器人同一时刻只该做一件事。把"模式"建成**状态机（State Machine）**：状态（mode 变量）+ 转移规则（if）+ 每个状态的动作（switch）。

```cpp
#include <iostream>

int main() {
    const int kIdle  = 0;      // 状态 0：待机
    const int kLine  = 1;      // 状态 1：巡线
    const int kAvoid = 2;      // 状态 2：避障

    int mode = kIdle;          // 开机先待机
    double obstacle_cm = 50.0; // 前方障碍距离（cm），来自"传感器"

    for (int t = 1; t <= 6; ++t) {
        // 剧本：模拟 6 拍的传感器变化——第 3 拍出现障碍，第 5 拍解除
        if (t == 3) obstacle_cm = 8.0;
        if (t == 5) obstacle_cm = 40.0;

        // 转移规则：根据传感器，决定要不要换状态
        if (mode == kIdle && t >= 2)               mode = kLine;   // 待机一拍后出发
        if (mode == kLine && obstacle_cm < 10.0)   mode = kAvoid;  // 太近 → 避障
        if (mode == kAvoid && obstacle_cm >= 10.0) mode = kLine;   // 解除 → 回巡线

        // 状态执行：switch 把每种状态的动作分发出去
        switch (mode) {
            case kIdle:
                std::cout << "t=" << t << "  IDLE   : motors off\n";
                break;
            case kLine:
                std::cout << "t=" << t << "  LINE   : follow the black line\n";
                break;
            case kAvoid:
                std::cout << "t=" << t << "  AVOID  : stop, then turn left\n";
                break;
        }
    }
    return 0;
}
```

预期输出：

```text
t=1  IDLE   : motors off
t=2  LINE   : follow the black line
t=3  AVOID  : stop, then turn left
t=4  AVOID  : stop, then turn left
t=5  LINE   : follow the black line
t=6  LINE   : follow the black line
```

对照输出复述剧情：第 1 拍待机；第 2 拍出发巡线；第 3 拍障碍 8 cm（< 10）切入避障；第 4 拍障碍还在，继续避障；第 5 拍解除（40 cm），回巡线。**"转移规则"决定进入哪个状态，"switch"决定该状态下干什么**——两层各司其职。真实的 ROS2 行为树比这复杂，但骨架就是它。

> 📖 教材对照：C++ Primer 第5版 §5.4（迭代语句）、§5.3（条件语句）

## 9. 常见错误与自救

| 错误现象 | 原因 | 怎么改 |
|---|---|---|
| 程序永远不结束 | 死循环：忘了更新循环变量 | 检查三要素之"更新"；终端 `Ctrl + C` 急停 |
| `if` 判断永远成立 | `=` 写成赋值，应为 `==` | 开 `-Wall` 看警告；比较一律双等号 |
| else 归属和想象不符 | 悬空 else：配对最近的 if | 给每个 if/else 都写花括号 |
| 一个 case 命中，后面全执行 | 忘写 break 导致穿透 | 每个 case 末尾补 `break` |
| `error: 'xxx' was not declared in this scope` | 函数定义在调用之后又没有声明 | 文件开头加声明，或放进头文件 |
| 多文件编译报 `undefined reference` | 忘了把 .cpp 一起编译 | `g++ main.cpp math_utils.cpp -o app` 全部列出 |
| 函数里改了形参，外面没变化 | 值传递：改的是复印件 | 本阶段属正常；要改原件等第 40 章引用 |
| 递归报 `Segmentation fault` | 没有出口，栈溢出 | 确认出口存在，且每次递归规模必须缩小 |

**练习 1**：用嵌套 `for` 打印九九乘法表（`i` 外层 1~9，`j` 内层 1~9，用 `\t` 分隔）。

??? details "练习 1 解答"

    ```cpp
    #include <iostream>

    int main() {
        for (int i = 1; i <= 9; ++i) {          // 外层：管"第几行"
            for (int j = 1; j <= 9; ++j) {      // 内层：管"这一行第几个"
                std::cout << i << "x" << j << "=" << i * j << "\t";
            }
            std::cout << "\n";                  // 内层走完一行才换行
        }
        return 0;
    }
    ```

    预期输出（节选前 3 行，共 9 行）：

    ```text
    1x1=1   1x2=2   1x3=3   1x4=4   1x5=5   1x6=6   1x7=7   1x8=8   1x9=9
    2x1=2   2x2=4   2x3=6   2x4=8   2x5=10  2x6=12  2x7=14  2x8=16  2x9=18
    ```

**练习 2**：写函数 `bool is_safe(double distance_cm)`：距离大于等于 10.0 cm 返回 true（安全），否则 false。在 main 里用 8.0 和 25.0 测试（bool 打印为 1/0）。

??? details "练习 2 解答"

    ```cpp
    #include <iostream>

    bool is_safe(double distance_cm) {    // 返回类型 bool：判断型函数
        return distance_cm >= 10.0;       // 比较表达式的值直接返回
    }

    int main() {
        std::cout << "d = 8.0  cm, safe? " << is_safe(8.0)  << "\n";
        std::cout << "d = 25.0 cm, safe? " << is_safe(25.0) << "\n";
        return 0;
    }
    ```

    预期输出：

    ```text
    d = 8.0  cm, safe? 0
    d = 25.0 cm, safe? 1
    ```

    要点：`distance_cm >= 10.0` 本身就是 bool 值，直接 return 它，不必写成 if/else 两行。

**练习 3**：写递归函数 `sum_to(n)` 计算 1+2+…+n。先在纸上演算 `sum_to(4)` 的展开与回归，再写代码验证（另测 n=100 应得 5050）。

??? details "练习 3 解答"

    纸上演算：

    ```text
    展开：sum_to(4)=4+sum_to(3) → 3+sum_to(2) → 2+sum_to(1) → 1（出口）
    回归：sum_to(2)=2+1=3 → sum_to(3)=3+3=6 → sum_to(4)=4+6=10
    ```

    ```cpp
    #include <iostream>

    int sum_to(int n) {
        if (n == 1) {              // 出口：加到 1 就不必再递归
            return 1;
        }
        return n + sum_to(n - 1);  // 递归步：n + (1+2+…+n-1)
    }

    int main() {
        std::cout << "sum_to(4) = " << sum_to(4) << "\n";
        std::cout << "sum_to(100) = " << sum_to(100) << "\n";
        return 0;
    }
    ```

    预期输出：

    ```text
    sum_to(4) = 10
    sum_to(100) = 5050
    ```

    思考：改成 `for` 循环版（累加器从 1 加到 n）对比——循环版没有调用栈开销，n 大时更快；递归版更贴近数学定义。两种都要会写。

## 综合习题：避障决策小状态机（全章知识串联）

小车依次测得三帧距离 `45, 25, 8`（厘米）。写一个程序：对每帧用**函数**判级（<10 急停 / <30 减速 / 其余 安全），再用 **switch** 打标记，循环里统计警告次数，最后用**递归**算组合数 $\binom{4}{2}$（为后续"三选二传感器冗余"做铺垫）。

**(a) 分级函数**（§2 if-else 链、§5 函数）：写出 `level(d)`，返回 `"急停"/"减速"/"安全"`。

**(b) 分岔打标**（§3 switch）：用 `switch (d / 10)` 给每帧附加 `[紧急]/[警告]/[正常]` 标记，并统计警告帧数（§4 循环）。

**(c) 递归阶乘**（§6）：写 `fact(n)`，并用它算 $\binom{4}{2} = \tfrac{4!}{2!\,2!}$。

**(d) 状态机视角**（§8 主循环）：这个 for 循环加上分级函数，与机器人主循环"感知 → 决策 → 执行"的哪两步对应？

**(e) 扩展预演**（§7 随机游走同款思路）：若距离来自 `rand()` 加漂移，程序结构需要变吗？

??? details "综合习题完整解答（程序已实测编译运行）"

    ```cpp
    #include <iostream>
    int fact(int n) { return n <= 1 ? 1 : n * fact(n - 1); }   // (c)
    const char* level(int d) {                                   // (a)
        if (d < 10) return "急停";
        if (d < 30) return "减速";
        return "安全";
    }
    int main() {
        int distances[] = {45, 25, 8};
        int warned = 0;
        for (int i = 0; i < 3; ++i) {                            // (b)
            int d = distances[i];
            std::cout << d << "cm -> " << level(d);
            switch (d / 10) {
                case 0: std::cout << " [紧急]"; break;
                case 2: std::cout << " [警告]"; ++warned; break;
                default: std::cout << " [正常]";
            }
            std::cout << "\n";
        }
        std::cout << "警告次数=" << warned
                  << " C(4,2)=" << fact(4)/(fact(2)*fact(2)) << "\n";
        return 0;
    }
    ```

    实测输出：

    ```text
    45cm -> 安全 [正常]
    25cm -> 减速 [警告]
    8cm -> 急停 [紧急]
    警告次数=1 C(4,2)=6
    ```

    **(d)** for 循环读数组是"感知"的占位，`level()` + switch 是"决策"；真正的机器人只是把 `distances[i]` 换成传感器回调——**主循环骨架一模一样**。**(e)** 不需要变：把 `int d = distances[i]` 换成 `int d = 200 + rand()%100 + drift;`（§7 的写法），决策逻辑原封不动——这就是"感知与决策解耦"的第一次落地。
