## 1. 为什么机器人行业离不开 C++

### 1.1 三个硬理由

**理由一：ROS2 本身就是用 C++ 写的。**
ROS2（Robot Operating System 2，机器人操作系统第 2 版）是当今机器人领域事实上的标准框架。它的官方 C++ 客户端库叫 `rclcpp`，性能比 Python 版 `rclpy` 更好，工业项目里节点（运行中的机器人程序单元）大多用 C++ 写。你可以用 Python 快速做出"能动的 demo"，但一旦要上真机器人，C++ 几乎绕不开。

**理由二：实时控制需要确定性。**
机器人控制有**实时性（Real-time）**要求：控制周期可能只有 1 毫秒，必须保证"每一步都在固定时间内算完"。C++ 编译成机器码直接执行，没有解释器和**垃圾回收（Garbage Collection，自动清理内存的机制）**带来的随机卡顿，所以电调、伺服驱动、底层控制器的代码几乎全是 C/C++。

**理由三：开源机器人项目的主语言就是 C++。**
你以后一定会读、会用的这些项目，核心都是 C++：

| 项目 | 它是干什么的 | 主语言 |
|---|---|---|
| ROS2（rclcpp） | 机器人通信与框架 | C++ |
| MoveIt 2 | 机械臂运动规划 | C++ |
| ros2_control | 电机/硬件控制框架 | C++ |
| PCL | 点云处理库 | C++ |
| Gazebo / Isaac Sim 接口 | 机器人仿真 | C++ |
| Eigen | 矩阵运算库（机器人学数学引擎） | C++ |

### 1.2 C++ 和 Python 怎么分工？

机器人工程师通常两种语言都用，分工大致如下：

| 对比项 | C++ | Python |
|---|---|---|
| 运行方式 | 先**编译（Compile）**成机器码再运行 | 由**解释器（Interpreter）**逐行执行 |
| 运行速度 | 非常快 | 慢一到两个数量级 |
| 开发速度 | 慢一点，语法要求严格 | 快，几行就能跑 |
| 类型检查 | 编译期就查，错误藏不住 | 运行时才可能暴露 |
| 内存管理 | 自己管（本目录第 40 章讲） | 自动回收 |
| 机器人典型用途 | 驱动、实时控制、性能关键节点 | 上层逻辑、算法原型、测试脚本 |
| 在本站的角色 | 本目录 7 章专攻 | 其他目录另有覆盖 |

一个粗略的类比：Python 像"参谋部"，出主意快；C++ 像"手脚"，真正按毫秒级节拍干活。类比在哪儿失效？——真实的机器人是分层的，参谋和手脚之间要靠同一种"语言"通信（ROS2 的消息接口），所以两种语言经常出现在同一个项目里，而不是二选一。

## 3. 环境搭建：三选一

C++ 是**编译型语言（Compiled Language）**：源代码必须先由**编译器（Compiler）**翻译成机器能直接执行的程序，才能运行。所以我们要装的核心只有一样——编译器 `g++`（GCC 里的 C++ 编译器），外加一个顺手的编辑器 VS Code。

三条路线，选一条走完就行：

| 方案 | 适合谁 | 难度 | 特点 |
|---|---|---|---|
| A. Windows + VS Code + MinGW-w64 | 只想快点开始、主力系统是 Windows | ★☆☆ | 最轻量，装完即用 |
| B. Windows + WSL2 + Ubuntu | 想同时体验 Linux、以后要玩 ROS2 | ★★☆ | 一步到位，强烈推荐给立志做机器人的你 |
| C. Ubuntu 原生 | 电脑已经装了 Ubuntu / 双系统 | ★☆☆ | 和机器人开发环境最接近 |

### 3.1 方案 A：Windows + VS Code + MinGW-w64

MinGW-w64 是把 GCC 编译器移植到 Windows 上的发行版。我们用社区维护的打包版 **WinLibs**，下载解压就能用。

**第 1 步：下载 MinGW-w64（WinLibs 版）。**
浏览器打开 `https://winlibs.com/`，找到 "Release versions" 里最新的 GCC 版本（例如 GCC 13.x），在 "Win64" 一栏下载 **Zip archive**（选 UCRT runtime 的即可，Win10/11 都自带其运行库）。文件名类似 `Winlibs-...-UCRT-...-zip`，约 100-200 MB。

**第 2 步：解压到固定位置。**
右键 zip → 全部解压，把解压出来的 `mingw64` 文件夹整个放到 `C:\` 盘根目录下，最终路径形如：

```text
C:\mingw64\bin\g++.exe
```

!!! warning
    路径里**不要有中文和空格**。`C:\工具包\mingw64` 或 `C:\my files\mingw64` 都可能埋下莫名其妙的坑。

**第 3 步：把编译器加进 PATH。**
**环境变量（Environment Variable）**是操作系统查找程序用的"通讯录"。把 `C:\mingw64\bin` 记进去，以后在任何位置敲 `g++` 都能找到它：

1. 按 `Win` 键，搜索"编辑系统环境变量"，回车；
2. 点右下角"环境变量(N)..."；
3. 在上半区"用户变量"里选中 `Path` → 点"编辑(I)..."；
4. 点"新建(N)"，输入 `C:\mingw64\bin`，一路点"确定"退出。

**第 4 步：验证安装。**
**重要：先关掉所有已打开的终端再重新开一个**（PATH 改动对旧终端不生效）。然后：

```bash
g++ --version
```

看到类似下面这就成功了（版本号不必和我一样）：

```text
g++.exe (GCC) 13.2.0
Copyright (C) 2023 Free Software Foundation, Inc.
```

顺手确认调试器也在（后面章节会用）：

```bash
gdb --version
```

**第 5 步：安装 VS Code。**
打开 `https://code.visualstudio.com/`，下载 Windows 版并安装（一路默认即可）。装好后打开 VS Code，点左侧"扩展"图标（四个方块），搜索并安装两个扩展：

- **C/C++**（微软官方，代码高亮与智能提示）；
- **Chinese (Simplified) Language Pack**（界面中文化，可选）。

### 3.2 方案 B：Windows + WSL2 + Ubuntu

**WSL（Windows Subsystem for Linux）**是 Windows 内置的"正版 Linux 子系统"，能让你在 Windows 里跑一个真正的 Ubuntu。以后学 ROS2 基本绕不开 Linux，现在装 WSL 是最有远见的选择。

**第 1 步：安装 WSL 与 Ubuntu。**
在开始菜单搜 `PowerShell`，右键选"**以管理员身份运行**"，执行：

```bash
wsl --install
```

它默认安装 WSL2 + Ubuntu。装完**重启电脑**。

**第 2 步：初始化 Ubuntu。**
重启后 Ubuntu 窗口会自动打开（没打开就在开始菜单搜 `Ubuntu`）。它会让你设置用户名和密码：

- 用户名用小写英文（如 `robot`）；
- 密码输入时**屏幕上什么都不显示，这是正常的**，盲打完回车即可。

**第 3 步：安装编译工具链。**
在 Ubuntu 终端里执行（`sudo` 表示以管理员权限运行，会要求再输一次密码）：

```bash
sudo apt update
```

先刷新软件源列表，然后：

```bash
sudo apt install -y build-essential gdb
```

`build-essential` 是一个"全家桶"，一次性装好 `g++`、`gcc`、`make` 和 C/C++ 标准库头文件；`gdb` 是调试器。

**第 4 步：验证。**

```bash
g++ --version
```

```text
g++ (Ubuntu 11.4.0-1ubuntu1~22.04) 11.4.0
```

!!! tip
    代码和工程建议放在 Ubuntu 的家目录里（如 `~/cpp_work`），而不是 Windows 的 C 盘路径——WSL 跨系统读写文件很慢，这是前人踩过的新手坑。

（可选）在 VS Code 里安装 **WSL** 扩展，然后按 `F1` 输入 `WSL: Connect to WSL`，就能用 VS Code 直接编辑 Ubuntu 里的代码，体验和本地方案 A 完全一致。

### 3.3 方案 C：Ubuntu 原生

如果你已经在用 Ubuntu（物理机或虚拟机），最简单。打开终端（`Ctrl+Alt+T`），依次执行：

```bash
sudo apt update
```

```bash
sudo apt install -y build-essential gdb
```

```bash
g++ --version
```

```text
g++ (Ubuntu 11.4.0-1ubuntu1~22.04) 11.4.0
```

有版本号输出即成功。Ubuntu 自带文本编辑器 `gedit`，也推荐装个 VS Code（`https://code.visualstudio.com/` 有 Linux 版 deb 包）。

!!! tip
    三条路殊途同归：最终你都得到了 `g++ + gdb`。本目录所有代码在三种环境下完全通用，只有个别运行命令的写法差异，第 4.5 步会说明。

## 4. 第一个程序 hello.cpp：全流程演练

环境装好了，现在从零开始走一遍"写代码 → 编译 → 运行"的完整流程。每个命令都单独给出并解释，跟做即可。

### 第 1 步：建立工作目录

Windows（cmd 或 PowerShell）与 Ubuntu/WSL 命令相同——在用户目录下建一个专门放 C++ 代码的文件夹：

```bash
mkdir cpp_work
```

`mkdir` 是 make directory 的缩写：新建一个名为 `cpp_work` 的文件夹。

然后进入这个文件夹：

```bash
cd cpp_work
```

`cd` 是 change directory 的缩写：把终端的"当前位置"切进去。后面所有操作都在这个文件夹里进行。

### 第 2 步：新建源文件

创建一个名为 `hello.cpp` 的空文件并打开编辑。按环境选一条：

```bash
code hello.cpp
```

VS Code 方式：用 VS Code 打开（或新建）`hello.cpp`。

```bash
notepad hello.cpp
```

Windows 记事本方式（提示文件不存在、要不要新建，选"是"）。

```bash
nano hello.cpp
```

Ubuntu/WSL 方式：nano 是终端里的极简编辑器，`Ctrl+O` 保存、`Ctrl+X` 退出。

**源文件（Source File）**就是程序员写的人读得懂的文本文件，`.cpp` 后缀表明它是 C++ 源码。

### 第 3 步：输入代码

在 `hello.cpp` 里原样输入以下 5 行（先照抄，第 10 章逐行解剖）：

```cpp
#include <iostream>                // 引入输入输出库，让程序认识 cout

int main() {                       // 程序从这里开始执行
    std::cout << "Hello, Robot!" << std::endl;   // 向屏幕输出一行字
    return 0;                      // 告诉操作系统：程序正常结束
}
```

注意：`main` 是主函数，一个 C++ 程序有且只有一个；每条指令以分号 `;` 结尾；大小写敏感（`Cout` 和 `cout` 不是一回事）。

### 第 4 步：编译

在终端里（确保当前目录还是 `cpp_work`）执行：

```bash
g++ hello.cpp -o hello
```

这条命令的四个部分分别是：

- `g++`：调用 C++ 编译器；
- `hello.cpp`：要编译的源文件；
- `-o`：output 的缩写，指定输出文件名的选项；
- `hello`：输出的**可执行文件（Executable）**名（Windows 会自动生成 `hello.exe`）。

编译成功时**没有任何输出**——不吭声就是好消息。也可以一条命令串起编译和运行：

```bash
g++ hello.cpp -o hello && ./hello
```

中间的 `&&` 意思是"前面成功才执行后面"。注意老版 Windows PowerShell 5.1 不支持 `&&`，遇到报错就拆成两条命令分别执行。

### 第 5 步：运行

Linux / WSL / Ubuntu 下：

```bash
./hello
```

`./` 表示"当前目录下的"，因为 Linux 默认不会在当前目录里找程序，所以必须显式写。

Windows PowerShell 下：

```powershell
.\hello.exe
```

Windows cmd 下直接输：

```text
hello
```

三种环境的预期输出完全一样：

```text
Hello, Robot!
```

### 刚才到底发生了什么？

```text
 hello.cpp（人写的源码）
     │  g++ 做了三件事：
     │  ① 预处理：把 #include 的库内容"拷贝"进来
     │  ② 编译：翻译成机器指令
     │  ③ 链接：把标准库等拼装成完整程序
     ▼
 hello / hello.exe（机器可直接执行的可执行文件）
     │  ./hello 让操作系统加载并运行它
     ▼
 屏幕上出现 Hello, Robot!
```

**预处理（Preprocess）→ 编译（Compile）→ 链接（Link）**这条流水线，就是 C++ 与 Python "边解释边执行"的最大区别。以后每次改完代码，都要重新执行第 4 步编译，再运行。

## 5. 常见错误与自救

环境阶段的高频翻车现场，先收藏，撞上时回来查：

| 错误现象 | 原因 | 怎么改 |
|---|---|---|
| `'g++' 不是内部或外部命令` / `command not found` | PATH 没配好，或改完没重开终端 | 核对 PATH 里是 `...\bin`；**关掉所有终端重开**再试 |
| `g++: error: hello.cpp: No such file or directory` | 终端不在源文件所在目录 | 先 `cd cpp_work` 进入目录，`ls`/`dir` 确认文件在 |
| `expected ';' before ...` | 某行末尾少了分号 | 看报错行号和它的**上一行**，补分号 |
| `permission denied`（运行 ./hello 时） | Linux 下文件没有执行权限或路径写错 | 用 `./hello`（带 `./`）；仍不行执行 `chmod +x hello` |
| 程序里的中文输出变成乱码 | 源文件编码与终端编码不一致 | 源文件保存为 UTF-8（VS Code 右下角可见/可点）；Windows 终端先执行 `chcp 65001` |
| 编译时一堆奇怪错误且路径含中文 | 源文件或路径用了中文 | 路径、文件名一律用英文 |
| `hello.exe` 被杀毒软件删了 | 误报 | 恢复并把 `cpp_work` 目录加入白名单 |
| WSL 安装时报错提示"虚拟机平台" | BIOS 未开启虚拟化 | 进入 BIOS 开启 VT-x（Intel）/ SVM（AMD），或先 `wsl --update` |
| VS Code 终端里找不到 g++（明明装了） | VS Code 是在改 PATH 之前启动的 | 完全退出 VS Code 再重开 |

## 7. FAQ：三个高频问题

### 7.1 需要先学 C 语言吗？

不需要。C++ 兼容 C 的绝大部分语法，Primer 也是直接从 C++ 讲起。先学 C 再学 C++ 会先养成一些"过时写法"再费力纠正。本目录按现代 C++（C++11 及以后）直接教，个别历史概念（如 C 风格数组）在需要的章节会顺带交代。

### 7.2 用 IDE 还是命令行？

起步阶段**强烈建议命令行 + 编辑器**（本目录的方式）：手动敲 `g++ hello.cpp -o hello`，你才真正理解"编译"发生了什么，报错也不会被 IDE 的提示框遮住。等学完本目录，再换 Visual Studio / CLion / VS Code 全家桶配置，那时你才知道每个按钮背后是什么。就像学做菜先练刀工，再上集成灶。

### 7.3 学完这 7 章能干什么？

- 看得懂 ROS2 教程里 C++ 节点的主体代码，能改能编译；
- 能写出"读传感器数值 → 判断 → 控制"这类小程序骨架（第 20 章就会动手）；
- 为后续路线铺路：机器人学里的运动学、控制器实现都要 C++（或至少能读懂）；
- 距离"独立开发机器人软件"还很远，但**地基已经打完**，后面都是往上盖楼。

## 8. 动手练习

**练习 1**：修改 `hello.cpp`，让它输出两行：第一行你的代号（英文即可），第二行 `I am learning C++ for robots.`。重新编译并运行。

??? details "练习 1 解答"

    ```cpp
    #include <iostream>

    int main() {
        std::cout << "Traveler" << std::endl;              // 第一行：代号
        std::cout << "I am learning C++ for robots." << std::endl;   // 第二行
        return 0;
    }
    ```

    预期输出：

    ```text
    Traveler
    I am learning C++ for robots.
    ```

    要点：多一条输出就多一行 `std::cout << ... << std::endl;`，改完必须**重新编译**，否则运行的还是旧程序。

**练习 2**：把可执行文件编译成 `hello_robot`（而不是 `hello`），并运行它。

??? details "练习 2 解答"

    ```bash
    g++ hello.cpp -o hello_robot
    ```

    ```bash
    ./hello_robot
    ```

    预期输出：

    ```text
    Hello, Robot!
    ```

    要点：`-o` 后面跟什么名字，就生成什么可执行文件，与源文件名无关。

**练习 3**（重要）：故意把 `hello.cpp` 第 4 行末尾的分号删掉，重新编译，**读一遍报错的第一行**，然后把分号补回去。

??? details "练习 3 解答"

    删掉分号后编译会看到类似：

    ```text
    hello.cpp: In function 'int main()':
    hello.cpp:5:5: error: expected ';' before 'return'
        5 |     return 0;
          |     ^~~~~~
          |     ;
    ```

    要点：报错第一行已经告诉你——在第 5 行 `return` 前面少了个分号（错误点往往在**报错位置的上一行**）。学会读第一行报错，是排查一切问题的起点。读完把分号补回，确认程序恢复编译通过。

**练习 4**：加参数 `-Wall` 重新编译一次：`g++ -Wall hello.cpp -o hello`，对比输出有没有变化。

??? details "练习 4 解答"

    预期输出（编译阶段）：

    ```text
    （无任何输出，编译通过）
    ```

    要点：`-Wall` 打开"所有常见警告"。hello.cpp 太干净所以无事可说；但以后变量没初始化、类型可疑转换等，它都会提前点名。从现在起建议养成 `g++ -Wall` 的习惯。

## 本章速查卡

| 目的 | 命令 | 说明 |
|---|---|---|
| 验证编译器 | `g++ --version` | 三种环境通用 |
