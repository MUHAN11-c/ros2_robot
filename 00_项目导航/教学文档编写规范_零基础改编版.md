# 教学文档编写规范 · 零基础改编版（v6.6）

> 本规范在原 v5.0 规范基础上，为"从零基础出发"的单主线（起点→核心→进阶→前沿四段旅程）架构改编而成；v6.1 图示画法与实验配套；v6.2 新增符号表与 emoji 政策。
> 适用于：第〇阶【零基础筑基】全部章节，以及后续各轮从旧版深度内容重写出的章节。
> 旧版深度章节（第三阶）仍按 v5.0 档位制撰写，本规范不追溯。

---

## 一、读者画像（最重要的一节）

第〇阶章节的读者是**真正的零基础学习者**：

- 可能刚上大学，或从其他专业转入，**没学过**大学数学、没写过代码
- 高中知识可能有遗忘（三角函数、指数对数需要时简要回顾，不假设熟练）
- **不要**使用"显然""易得""不难证明"这类词——每个推导都要给出中间步骤
- **不要**预先引用后续章节的术语；首次出现的术语必须给定义
- 每章开头要回答三个问题：这章讲什么？为什么要学它（在机器人学中的位置）？学完能做什么？

## 二、章节统一骨架（第〇阶改编）

```markdown
## 本章导航                ← 替代旧版"前置自测"：零基础读者没有可自测的前置
（本章学什么/为什么学/学完能做什么，三段各 2-3 句，加一个"本章在路线图中的位置"小图）

## 1. 从生活到概念          ← 每个新概念从具体场景/生活直觉切入
## 2. 概念是什么            ← 定义 + 最简单的例子 + 一个反例
## 3. 动手算一算            ← 逐步演算，禁止跳步；每步一行，等号对齐
## 4. 和机器人有什么关系     ← 把概念挂到机器人场景（宁可具体不要抽象）
## 5. 常见错误与自救        ← 表格：错误现象 / 原因 / 怎么改
## 6. 动手练习              ← 3-5 题，附完整解答（折叠在 ??? details 里）
## 本章速查卡               ← 一张表浓缩全部公式/语法
## 下一章预告               ← 一句话说明下一章用什么、为什么
```

### 骨架要点

- **逐步演算禁止跳步**：一行一个等号，每行右边可加小括号注明"这步用了什么规则"
- **生活类比放在概念定义之前**，但类比后必须明确"类比在哪里失效"
- **机器人挂钩**每章至少一处，要具体（例如：旋转矩阵 ↔ 机械臂末端姿态；导数 ↔ 速度估计），禁止空喊"机器人很重要"
- 代码章节：所有代码**必须能直接复制运行**，标注运行环境与预期输出；代码中的每一行新语法用行内注释解释
- 数学章节：公式全部用 `$...$` / `$...$`（MathJax）；变量首次出现要说明"它是什么、单位是什么"

## 三、语言风格

1. 中文正文，术语中英对照首次标注：**矩阵（Matrix）**
2. 语气：像学长面对面讲课，可用第一人称"我们"；允许轻度幽默与品牌意象点缀（樱机/紫樱），但**不得引用任何现有动漫/游戏 IP**，且不得干扰知识表达——每章主题元素不超过 1-2 处
3. 段落不超过 5 行；连续讲解每 2-3 段插一个表格、列表或代码块换节奏
4. 禁止 v5.0 深水区词汇直接裸奔：如"测度""泛函""辛结构"等，第〇阶一律不出现

## 四、可用与禁用的 Markdown 元素

| 元素 | 用法 | 说明 |
|---|---|---|
| `!!! note` / `!!! tip` / `!!! warning` | 提示块 | note=定义补充，tip=技巧，warning=易错点 |
| `??? details "练习解答"` | 折叠解答 | 所有练习解答必须折叠 |
| `=== "C++"` | 多语言对照 | 代码章节 C++/Python 对照时用 |
| 表格 | 对比、速查 | 每章至少 2 张 |
| `$...$` | 公式 | MathJax 语法 |
| **粗体** | 术语定义处 | 首次定义术语加粗 |
| 图片 | ⭕ 站点生成图可用 | 实验插图放 `assets/labs/`（由 scripts/labs 生成），正文不贴外链图 |
| mermaid | ✅ 鼓励使用 | 遵循第八节画法规范；每个流程图/架构图优先 mermaid |

## 五、章内导航与衔接

- 章首"本章导航"必须给出：上一章链接（相对路径）、本章四问、预计学习时长表（首次学/复习两档）
- 章末"下一章预告"给下一章相对链接
- 教材对照：涉及教材的知识点在正文后加一行 `> 📖 教材对照：同济《高等数学》上册 §1.1-1.3`，让读者能回到教材查证

## 六、难度与时长标定

- 第〇阶章节**不使用档位制**（档位制是高阶层的），改用学习时长表：

| 学习方式 | 时间 | 适合谁 |
|---|---|---|
| 首次学习（跟做练习） | 2-4 小时 | 第一次接触该主题 |
| 快速复习 | 30-60 分钟 | 学过但遗忘，查漏补缺 |

- 单章目标体量 **400-800 行**：宁可拆章也不写超长章

## 七、质量红线（提交前自查）

1. 每个推导无跳步？——抽查最长的那个推导
2. 每个术语首次出现有定义？——用 Ctrl+F 搜术语反向检查
3. 代码块可直接运行？——C++ 标注完整 `#include` 与 `main`；Python 标注 `pip install` 依赖
4. 练习有折叠完整解答？
5. 机器人挂钩具体不空洞？
6. 相对链接指向的文件真实存在？
7. 无禁用词汇；mermaid 与插图符合画法规范？

## 八、图示画法规范（v6.1 新增）

> v6.2 起见第九节符号表——文档中所有装饰符号必须取自该表。

流程图与架构图一律优先 Mermaid（站点已启用渲染），参照行业权威画法：

### 1. 流程图符号语义（沿袭经典流程图规范）

| 形状 | Mermaid 写法 | 语义 |
|---|---|---|
| 圆角矩形（stadium） | `A([开始/结束])` | 起点 / 终点 |
| 矩形 | `B[处理步骤]` | 加工 / 动作 |
| 菱形 | `C{条件判断?}` | 判断分支（出口标注 是/否） |
| 平行四边形 | `D[/"输入/输出数据"/]` | 输入 / 输出 |

### 2. 架构图画法

- 分层用 `subgraph`（如：感知层 → 决策层 → 执行层），层间连线表达数据流
- 闭环控制系统必须画反馈回路：比较点用圆形节点 `(("Σ"))` 标注 `e=r−y`
- 节点文字精炼（≤ 2 行），连线可加标签说明触发条件

### 3. 渲染方式与统一初始化头

- Mermaid 块**在构建时**由 `scripts/labs/render_mermaid.py` 预渲染为 SVG（存入 `assets/labs/diagrams/` 并提交仓库），站点运行时零 JS 依赖；修改图示源码后需本地重跑该脚本并一并提交 SVG
- 每个图块保留统一初始化头（配色与全站主题一致）：

```text
%%{init: {"theme":"base","themeVariables":{"primaryColor":"#FFFFFF","primaryBorderColor":"#8166B1","primaryTextColor":"#292530","lineColor":"#B39ADE","fontSize":"14px"}}}%%
```

- 节点标签一律用双引号包裹（`A["文字"]`），避免撇号/括号/竖线破坏解析

### 4. 可视化实验配套（第〇阶/第一阶章节适用）

- 章节涉及可计算的理论概念时，在章末追加「🔬 配套实验」一行，链接 `08_可视化实验室/` 对应实验室页
- 实验代码只依赖 numpy + matplotlib，固定随机种子，保证读者复现结果与站内插图一致

## 九、樱机符号表（v6.2 新增，全站强制）

装饰符号一律取自下表；**禁止 emoji 呈现**（彩色 emoji 与双主题适配差、风格不统一）。几何符号随正文颜色渲染，亮暗主题自动适配。

| 符号 | 语义 | 替代了 |
|---|---|---|
| ★ | 难度星级（连排）/ 单个=核心必会 | ⭐ |
| ◆ | 前置自测、工程/排查/工业标记 | 📋 🔧 🏭 🦾 🚁 |
| ◇ | 本质洞察 | 💡 |
| ◎ | 类比 / 认知标记 | 🧠 |
| ● | 状态圆点 | 🟡 🟣 🔵 |
| ✗ | 禁止 / 反例警示 | 🚫 |
| ⚠ | 易错点 / 警告（纯文本呈现） | ⚠️ |
| 🔬 | 配套实验回链（品牌标记，位置固定于章末） | — |
| 📖 | 教材对照（品牌标记） | 📕 📘 📗 |
| ①②③ | 步骤序号（保留） | — |

例外：代码围栏内的注释/输出不受本表约束；数学符号（⟹ ℝ ∑ 等）与 box-drawing ASCII 图保留。

## 十、吉祥物组件系统（v6.3 新增，全站强制）

吉祥物「紫樱（Sakura）」：紫发少女 Q 版贴纸形象（用户提供贴纸包素材）。素材库位于 `assets/mascots/`：`src/` 存原始贴纸包 PNG（只读存档），正式素材由 `scripts/assets/build_mascot_assets.py` 从贴纸包连通域提取单个贴纸并装配——`hero.webp`（首页）/ `tip.webp`（提示卡）/ `404.webp`（404 页）/ `avatar-512|128|64.webp`（头像三档）/ `favicon.png`。**正文页吉祥物出场每页最多 1 次**，只允许以下组件形态：

| 组件 | 用途 | 出场位置 |
|---|---|---|
| rt-hero（插画 + 双光晕 + 技术标签 + 樱花瓣） | 首页 Hero | 仅首页 |
| rt-assistant | 右下角 58px 浮动助手（搜索/返回顶部/阅读状态） | 全站固定，自动注入 |
| rt-chapter-header | 模块入口信息条（44px 贴纸头像 + 代码徽章 + 定位语 + ◆ chips） | 8 方向入口页 + 实验室总览 |
| rt-mascot-tip | 吉祥物提示卡（小图 + 一句话） | 实验室总览 / 学习路线总图 / 目录索引 |
| rt-complete | 章末完成卡（✓ 徽章 + 右侧 76px 完成贴纸 + 下一站/配套实验链接） | 第〇阶筑基各章末尾 |
| rt-404 | 404 页（根路径 raw HTML 写法） | 仅 404 |

写作规则：
1. 禁止在正文段落中插入吉祥物图片或"紫樱说"类旁白（实验室代码旁的 `> 紫樱备注` 引用块除外，每 lab 至多 1 处）；
2. rt-mascot-tip 文案 ≤ 60 字，只写可操作建议，不复述正文；
3. 新增模块入口页时必须补 rt-chapter-header（代码徽章 + 定位语 + 3-4 个 ◆ chips）；
4. 404 页的图片与按钮必须用根相对 raw HTML（见 `scripts/sync_docs.py write_404`），不得用 markdown 链接；
5. 素材只从 `assets/mascots/` 取用，禁止整张贴纸包直接上站、禁止手绘 SVG 替代；新增姿态需求时在 `build_mascot_assets.py` 的 CONFIG 中改选提取贴纸并重跑，不得手改 webp；
6. 组件内贴纸必须用 markdown 图片语法（感叹号 + 方括号 alt + 圆括号 src，再以 attr_list 花括号加类名）；mkdocs 会自动按页深改写 URL；**禁止 raw HTML `<img>`**——其 src 不会被改写（深度即错），且 glightbox 的 `<a>` 包装会破坏组件 grid（CSS 盯 `> p:first-child` 包装层）；
8. **实验代码本地测试门禁（v6.6 强制）**：任何写进教程的可运行代码（Python/C++）必须先在本地执行通过——Python 走 `scripts/labs/verify_lab_code.py`（提取全部代码块逐块运行，全绿才可发布）；C++ 走 `python -m ziglang c++`（.venv 已装 ziglang 工具链）编译运行并记录实测输出；
9. 活体吉祥物（Live2D 风格轻量实现）：首页 hero 贴纸支持视差跟随与点击随机反应（`assets/mascots/pool/` 全卡司 + `manifest.json`）。真 Live2D 需分层 PSD 原稿经 Cubism 绑定，平面贴纸无法转化，暂以轻量交互实现；
7. 制图工具映射（§八 补充）：流程/结构/通信图 → mermaid（`render_mermaid.py` 预渲染）；几何/坐标/机构示意图 → matplotlib（`scripts/labs/gen_intro_figs.py` 模式）；理论正文需要的实测图优先复用 `assets/labs/` 现成图并回链实验室；正文代码块内 ASCII 盒绘示意图不再新增（存量深层章逐步转化）。
